# 1\. はじめに

この資料は、6502-CPLD ボードに
HEXPAD（7セグ表示6桁とキー20個の基板）をつないだシステムで、**自分で機械語プログラムを作って動かす**ための手引きです。ROM
に入っているモニタ「**HEXMON**」を使い、キーパッドから RAM にプログラムを打ち込んで実行します。

## 1.1 この資料でできること

  - モニタでメモリを見たり書き換えたりする（3章）

  - プログラムを作り、打ち込んで実行する（4章）

  - HEXPAD のレジスタで表示とキーを使う（5章）

  - HEXMON の API（キー待ち・時間待ちなど）を呼ぶ（6章）

  - LED・スイッチ・タイマー・シリアル通信を直接使う（7章）

  - サンプルを打ち込んで、動きを確かめる（別冊「サンプル集」）

## 1.2 必要なもの

|                                             |                                 |
| ------------------------------------------- | ------------------------------- |
| **もの**                                      | **用途**                          |
| HEXMON の ROM と、HEXPAD 自動制御版の CPLD を書き込んだボード | 必須。2つは必ず組で書き換える。ROM の書き込み方は付録 D |
| この資料の付録 A（命令表）                              | 手でアセンブルするとき                     |
| 別冊「サンプル集」                                   | 打ち込んで試せるサンプル13本                 |
| PC と cc65（ca65 / ld65）                      | PC でアセンブルするとき（なくてもよい）           |

## 1.3 前提とする知識

6502 の基本（レジスタ
A・X・Y、ロード・ストア・分岐など）を知っていると読みやすくなります。知らなくても、別冊「サンプル集」のサンプルを打ち込みながら付録
A の命令表と見比べれば、少しずつ分かってきます。

## 2.3 表示とキーの配置

図2　HEXPAD 基板。上に7セグ表示6桁、右下にキー20個

表示は6桁です。モニタでは、左4桁にアドレス、右2桁にそのアドレスの中身を表示します。プログラムから表示するときは、表示レジスタ
HP\_DIGIT0（右端）〜HP\_DIGIT5（左端）に1桁ずつ、または HP\_HEX0〜2 に2桁ずつ書きます（詳しくは 5.2）。

|              |          |          |          |   |   |        |
| ------------ | -------- | -------- | -------- | - | - | ------ |
| **桁**        | **左端**   |          |          |   |   | **右端** |
| モニタでの意味      | アドレス     | データ      |          |   |   |        |
| HP\_DIGIT0〜5 | 5        | 4        | 3        | 2 | 1 | 0      |
| HP\_HEX0〜2   | HP\_HEX2 | HP\_HEX1 | HP\_HEX0 |   |   |        |

キーの配置は次のとおりです（基板を正面から見た並び）。各キーを押すと、5.3 のキーレジスタに読めるコードを括弧内に示します。

|           |          |          |          |
| --------- | -------- | -------- | -------- |
| RST（リセット） | JMP（$11） | A/D（$12） | INC（$13） |
| C（$0C）    | D（$0D）   | E（$0E）   | F（$0F）   |
| 8（$08）    | 9（$09）   | A（$0A）   | B（$0B）   |
| 4（$04）    | 5（$05）   | 6（$06）   | 7（$07）   |
| 0（$00）    | 1（$01）   | 2（$02）   | 3（$03）   |

> **メモ　**RST キーを押すと、CPLD が CPU をリセットしてモニタが起動し直します。プログラムが止まらなくなったときも RST
> で抜けられます。RAM の内容は消えません。

HEXPAD 基板の J1（6ピン）を、CPU 基板の J2（GPIO）の**下の3段**に次のようにつなぎます。6本とも J2
の下端にまとまるので、配線しやすくなります。

![](media/image3.png)

図3　CPU 基板の J2 と HEXPAD 基板 J1 の接続

|               |        |                |              |
| ------------- | ------ | -------------- | ------------ |
| **HEXPAD J1** | **信号** | **CPU 基板 J2**  | **CPLD の端子** |
| 1             | 3V3    | 3V3（下の段、J2-23） | —            |
| 2             | KEYINT | G16            | 65（今は使っていない） |
| 3             | DIO    | G18            | 64           |
| 4             | CLK    | G17            | 97           |
| 5             | STB    | G19            | 63           |

J2 の一番上の段（J2-1・J2-2）も同じ 3V3・GND なので、そちらから取ってもかまいません。

# 3\. モニタ（HEXMON）の使い方

## 3.1 起動と画面の見方

電源を入れるか RST キー（または CPU 基板の RESET スイッチ）を押すと、モニタが起動して「0200
xx」と表示されます。左4桁がアドレス（$0200）、右2桁がその番地の中身です。起動直後は**アドレス入力モード**です。

> **メモ　**数字の「0」は「o」の形（下半分）で表示されます。また、今どちらのモードかは表示では分かりません。迷ったら RST
> キーを押すと、アドレス入力モードで 0200 に戻ります。

## 3.2 キー操作

|        |                                                    |                       |
| ------ | -------------------------------------------------- | --------------------- |
| **キー** | **アドレス入力モード**                                      | **データ入力モード**          |
| 0〜F    | アドレスに右から入る（左へずれていく）                                | 中身に右から入り、すぐメモリに書き込まれる |
| A/D    | データ入力モードへ                                          | アドレス入力モードへ            |
| INC    | アドレスを1つ進める                                         | 同左（モードはそのまま）          |
| JMP    | 表示中のアドレスからプログラムを実行                                 | 同左                    |
| RST    | CPU をリセットしてモニタを起動し直す（0200、アドレス入力モード）。プログラムの実行中でも効く | 同左                    |

例えばアドレス入力モードで 1 2 3 4 と押すと、アドレスは 0001 → 0012 → 0123 → 1234 と変わります。

## 3.3 メモリを見る

1.  アドレス入力モードで、見たいアドレスを4桁入力する（例：0 2 1 0）

2.  右2桁に中身が表示される

3.  INC を押すたびに次の番地へ進む

## 3.4 プログラムを打ち込んで実行する

別冊「サンプル集」の①（足し算、11バイト）を例にします。

1.  RST を押す（「0200」になる）

2.  A/D を押して、データ入力モードにする

3.  1 8 → INC、A D → INC、1 0 → INC …と、「2桁入力 → INC」を1バイトずつくり返す

4.  最後のバイト（6 0）を入力したら、A/D でアドレス入力モードに戻る

5.  データを用意する：0 2 1 0 → A/D → 1 2 → INC → 3 4 → A/D

6.  0 2 0 0 → JMP で実行する

7.  0 2 1 2 を表示すると、右2桁に結果「46」が出る

## 3.5 打ち込んだ内容を確かめる

アドレス入力モードで先頭アドレス（0 2 0 0）を入力し、INC で1バイトずつ進めながら、ダンプと見比べます。間違いを見つけたら、A/D
でデータ入力モードにして正しい2桁を入力し直せば上書きされます。

## 3.6 困ったとき

|                      |                                                                    |
| -------------------- | ------------------------------------------------------------------ |
| **症状**               | **対処**                                                             |
| プログラムが止まらない、表示が変わらない | RST キーを押す。RAM の内容は残るので、打ち込み直す必要はない                                 |
| 今どちらのモードか分からない       | RST キーを押す（アドレス入力モード、0200 に戻る）                                      |
| キーを押しても反応しない         | プログラムがキーを読んでいないか確認する（キーは CPLD が覚えているので、すばやく押しても取りこぼさない）。RST で抜けられる |
| JMP したらすぐ戻ってきた       | 先頭が 60（RTS）になっていないか、アドレスが合っているか確認する                                |

# 4\. プログラムを作る

## 4.1 決まりごと

|               |                                                               |
| ------------- | ------------------------------------------------------------- |
| **項目**        | **決まりごと**                                                     |
| 置く場所          | $0200 から。$0200-$7EFF が使える                                     |
| ゼロページ         | **$20-$FF を使う**。$00-$1F はモニタが使っている                            |
| 終わり方          | RTS（$60）でモニタに戻る。くり返すだけのプログラムは無限ループにして、**RST で抜けてもよい**（その方が短い） |
| 割り込み          | 割り込み禁止（SEI）の状態で呼ばれる。CLI は**使わない**（割り込みベクタが未設定のため暴走する）         |
| 10進モード        | SED を使ったら、モニタのルーチンを呼ぶ前に CLD で戻す                               |
| GPIO のタイマー T1 | モニタの時間待ちが使っている。**T1 と ACR は変更しない**（T2 は自由に使える）                |
| 変数の初期値        | **RAM の中身は不定**（電源投入時の値や、前に動かしたプログラムの残り）。使う変数は必ず最初に値を入れる       |
| 表示レジスタ        | 計算の途中の値を書かない（一瞬表示されてしまう）。途中の計算は A レジスタで行い、結果だけを書く             |
| 大きさ           | 手で打ち込むので、なるべく小さく作る。1バイトにつきキーを3回押す                             |

## 4.2 作り方の流れ

1.  何をするプログラムか決める（例：押したキーを表示する）

2.  アセンブラのソースを書く（ラベルとコメント付きで紙やエディタに）

3.  機械語に直す。手でアセンブルする（4.3）か、PC でアセンブルする（4.4）

4.  打ち込みダンプ（「0200: A2 05 …」の形）を作る

5.  モニタで打ち込み、確かめてから JMP で実行する

## 4.3 手でアセンブルする

付録 A の命令表から、命令とアドレッシングモードに合うオペコードを探し、オペランドを続けて書きます。

  - **即値**（\#$12）とゼロページ（$12）は、オペコードの後に1バイト。

  - **絶対アドレス**（$1234）は、オペコードの後に**下位バイト → 上位バイト**の順で2バイト。例：JSR $FF00 → 20
    00 FF

  - 命令を書くたびにアドレスを数えておくと、分岐先やデータの番地を計算しやすい。

### 分岐命令のオフセット

BNE や BRA などの分岐命令は、飛び先を「次の命令からの距離」（−128〜+127）で書きます。

> オフセット ＝ 飛び先アドレス −（分岐命令のアドレス ＋ 2）
> 
> マイナスになったら 256 を足す（$100 − 距離）

例（サンプル集の②）：$0208 の BPL から $0202 に戻る場合、$0202 −（$0208 ＋ 2）＝ −8。256 − 8 ＝
248 ＝ $F8 なので、10 F8 になります。前に進む場合はそのまま正の値です（例：+10 なら $0A）。

> **注意　**分岐先が遠すぎる（−128〜+127 を超える）ときは、JMP を使うか、逆の条件の分岐で JMP を飛び越す形にします。

## 4.4 PC でアセンブルする

cc65 の ca65（アセンブラ）と ld65（リンカ）を使うと、ラベルや分岐の計算を自動でやってくれます。プロジェクトの soft
フォルダに一式あります。

1.  soft/samples/ に新しいソース（例：myprog.s）を置く。書き方は下のテンプレートのとおり

2.  soft フォルダで make を実行する（samples/myprog.bin ができる）

3.  make dump で、打ち込み用のダンプを表示する

テンプレート：

> ; myprog.s : プログラムの説明
> 
> .include "hexmon.inc" ; API・レジスタ・キーコードなどの定義
> 
> WORK = $20 ; 自分で使うゼロページ ($20〜)
> 
> .segment "CODE" ; $0200 から配置される
> 
> START: jsr WAIT\_KEY ; キーを待つ (A=キーコード)
> 
> sta HP\_HEX0 ; 右2桁に16進で表示
> 
> bra START ; くり返す (RST で抜ける)

  - ラベル名を命令名と同じにしない（例：SEC という名前はエラーになる）。

  - make の出力の .lst ファイルを見ると、各行の機械語が分かる。

# 5\. HEXPAD のレジスタ（表示とキー）

表示とキーは、CPLD が HEXPAD（TM1627）と自動でやり取りしています。プログラムは **HEXPAD
のレジスタを読み書きするだけ**で使えます。レジスタ名などの定義は hexmon.inc
にあります。キー待ちや時間待ちに使う HEXMON のルーチンは、6章で説明します。

## 5.1 HEXPAD のレジスタ

|             |              |                                                 |                                                    |
| ----------- | ------------ | ----------------------------------------------- | -------------------------------------------------- |
| **アドレス**    | **名前**       | **読み出し**                                        | **書き込み**                                           |
| $8800       | HP\_KEY      | bit7＝新しく押されたキーあり、bit4-0＝キーコード。**読むと bit7 が消える** | —                                                  |
| $8802       | HP\_CTRL     | 書いた値                                            | bit7＝RST でリセット、bit3＝表示 ON、bit2-0＝輝度（0〜7）           |
| $8804-$8806 | HP\_HEX0〜2   | 2桁ぶんの値                                          | 1バイトで16進2桁（HP\_HEX0＝右2桁、HP\_HEX1＝中2桁、HP\_HEX2＝左2桁） |
| $8808-$880D | HP\_DIGIT0〜5 | 表示コード                                           | 表示コード（HP\_DIGIT0＝右端、HP\_DIGIT5＝左端）                 |
| $880F       | HP\_VERSION  | CPLD の版（$01）                                    | —                                                  |

どのレジスタも、普通のメモリと同じように LDA・STA・INC などで読み書きできます。それぞれの詳しい働きは 5.2〜5.4 で説明します。

## 5.2 表示レジスタと基板の対応

HEXPAD
基板の7セグ表示は6桁です。基板のシルク印刷で、左4桁に「ADDRESS」、右2桁に「DATA」と書かれています。6桁の1つ1つに表示レジスタ
HP\_DIGIT0〜5 が対応し、2桁ずつまとめて書ける HP\_HEX0〜2 が重なっています。

![](media/image4.png)

図4　表示器と表示レジスタの対応（HP\_HEX は2桁ずつ、HP\_DIGIT は1桁ずつ）

同じ対応を表にすると次のとおりです。

|               |                  |                  |                  |                  |                  |                  |
| ------------- | ---------------- | ---------------- | ---------------- | ---------------- | ---------------- | ---------------- |
|               | **左端**           |                  |                  |                  |                  | **右端**           |
| 表示器（回路図の部品番号） | AFF1             | AFF2             | AFF3             | AFF4             | AFF5             | AFF6             |
| 基板のシルク        | ADDRESS（4桁）      | DATA（2桁）         |                  |                  |                  |                  |
| 1桁ずつ書く（表示コード） | HP\_DIGIT5 $880D | HP\_DIGIT4 $880C | HP\_DIGIT3 $880B | HP\_DIGIT2 $880A | HP\_DIGIT1 $8809 | HP\_DIGIT0 $8808 |
| 2桁ずつ書く（16進）   | HP\_HEX2 $8806   | HP\_HEX1 $8805   | HP\_HEX0 $8804   |                  |                  |                  |
| HEX のどのビットか   | bit7-4           | bit3-0           | bit7-4           | bit3-0           | bit7-4           | bit3-0           |
| モニタでの使い方      | アドレス上位           | アドレス下位           | データ              |                  |                  |                  |

例えば HP\_HEX0 は右2桁にまたがっていて、上位4ビットが右から2桁目（AFF5）、下位4ビットが右端（AFF6）に表示されます。

### HP\_HEX0〜2（$8804-$8806）に書いたとき

書いた1バイトが16進2桁として表示されます。**上位4ビットが左の桁、下位4ビットが右の桁**になり、それぞれの桁の表示レジスタ（DIGIT）に
0〜15 の値が入ります。

|                               |         |                                 |                    |
| ----------------------------- | ------- | ------------------------------- | ------------------ |
| **命令**                        | **書く値** | **変わるレジスタ**                     | **基板の表示（左端 … 右端）** |
| LDA \#$3A / STA $8804         | $3A     | HP\_DIGIT1＝3、HP\_DIGIT0＝A       | □□□□3A（右2桁だけ変わる）   |
| LDA \#$12 / STA $8806         | $12     | HP\_DIGIT5＝1、HP\_DIGIT4＝2       | 12□□□□（左2桁だけ変わる）   |
| $8806←$12、$8805←$34、$8804←$56 | —       | 左から HP\_DIGIT5＝1 … HP\_DIGIT0＝6 | 123456             |
| INC $8804（表示が 09 のとき）         | —       | HP\_DIGIT1＝0、HP\_DIGIT0＝A       | □□□□0A（FF の次は 00）  |

□ はそれまでの表示のままの桁です。書いてから実際に表示が変わるまで、最大で約 9ms かかります（CPLD が約 9ms ごとに HEXPAD
へ送っているため）。目で見て遅れが分かることはありません。

### HP\_HEX0〜2 を読んだとき

2つの桁の表示コードの**下位4ビットずつ**を合わせた値が読めます。HEX で書いた桁なら、書いた値がそのまま返ります。

  - 例：HP\_HEX0 に $3A を書いた後に HP\_HEX0 を読むと $3A。

  - 例：HP\_DIGIT1 に 17（H）、HP\_DIGIT0 に 5 を書いた後に HP\_HEX0 を読むと $15（17＝$11
    の下位4ビットは 1）。16 以上の表示コードの桁は、読んでも元の文字は分かりません。

  - INC $8804 や ADC $8804 のように、表示されている値をそのまま計算に使えます（サンプル集の④⑥）。

### HP\_DIGIT0〜5（$8808-$880D）

1桁ずつ、表示コード（0〜31、5.5 の表）を書きます。書いた値の上位3ビットは無視されます。読むと、その桁の表示コードが返ります。

|                             |                    |
| --------------------------- | ------------------ |
| **命令**                      | **基板の表示（左端 … 右端）** |
| LDA \#22 / STA $8808（22＝P）  | □□□□□P（右端だけ P）     |
| LDA \#20 / STA $880D（20＝空白） | □□□□□（左端が消える）      |

電源を入れた直後（CPLD が起動した直後）は、6桁とも「-」（コード 16）です。HEXMON が起動すると、モニタの表示に変わります。

## 5.3 キーレジスタ HP\_KEY（$8800）

CPLD は約 9ms ごとに HEXPAD のキーを読み、**新しく押されたキー**を1つ覚えておきます。プログラムは HP\_KEY
を読むだけでキーが分かります。各キーを押したときに読めるキーコードは図5のとおりです。

![](media/image5.png)

図5　キーと、HP\_KEY に読めるキーコード（RST は CPU のリセット）

|         |                       |       |       |                         |
| ------- | --------------------- | ----- | ----- | ----------------------- |
| **ビット** | **7**                 | **6** | **5** | **4〜0**                 |
| 意味      | 新しく押されたキーがある（1）／ない（0） | 常に 0  | 常に 0  | キーコード（$00〜$13、2.3 の配置図） |

  - **読むと bit7 が 0 に戻ります**（キーコードはそのまま残ります）。同じキーを2回数えないための仕組みです。

  - キーを押したままにしても、記録されるのは押した瞬間の1回だけです。

  - 押したまま別のキーに指を移したときは、新しいキーとして記録されます。

  - 読む前に次のキーが押されると、**新しい方**が残ります（覚えておけるのは1つだけ）。

  - 同時に2つ押したときは、どちらか一方（配線上の順番が早い方）だけが記録されます。

  - RST は通常、キーとして記録されず、CPU のリセットになります（5.4 の bit7）。

操作と、HP\_KEY を読んだときの値の例：

|                 |                   |                     |
| --------------- | ----------------- | ------------------- |
| **操作**          | **HP\_KEY を読んだ値** | **説明**              |
| （何も押していない）      | $0x（bit7＝0）       | 下位5ビットは前に押したキーのまま   |
| 5 を押す           | $85               | bit7＝1（新しい）、コード＝$05 |
| （続けてもう一度読む）     | $05               | 読んだので bit7 が 0 になった |
| 5 を押したまま読む      | $05               | 押しっぱなしでは新しく記録されない   |
| 5 を離して A を押す    | $8A               |                     |
| 読む前に 1、2 と続けて押す | $82               | 新しい方（2）が残る          |

キーがあるかどうかは LDA $8800 / BPL なし の2命令で調べられます（bit7 がそのまま N
フラグに入るため）。キーを待つだけなら HEXMON の JSR
WAIT\_KEY（6.3）が短く書けます。

## 5.4 制御レジスタ HP\_CTRL（$8802）

|         |                                        |            |                 |         |
| ------- | -------------------------------------- | ---------- | --------------- | ------- |
| **ビット** | **7**                                  | **6〜4**    | **3**           | **2〜0** |
| 意味      | RST キーで CPU をリセットする（1）／RST もキーとして読む（0） | 未使用（読むと 0） | 表示 ON（1）／全消灯（0） | 輝度 0〜7  |

輝度の値と明るさ（LED を点灯させる時間の割合）：

|        |       |       |       |       |       |       |       |       |
| ------ | ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- |
| **輝度** | **0** | **1** | **2** | **3** | **4** | **5** | **6** | **7** |
| 点灯時間   | 1/16  | 2/16  | 4/16  | 10/16 | 11/16 | 12/16 | 13/16 | 14/16 |

|         |                                         |
| ------- | --------------------------------------- |
| **書く値** | **意味**                                  |
| $8A     | RST でリセット、表示 ON、輝度 2（HEXMON が起動時に設定する値） |
| $8F     | いちばん明るくする                               |
| $82     | 表示を消す（RST は有効のまま）。$8A に戻すと元の表示が出る       |
| $0A     | RST をキーとして読む（RST でプログラムを止められなくなるので注意）   |

表示全体を点滅させるには、LDA $8802 / EOR \#$08 / STA $8802
をくり返します（表示レジスタの中身はそのまま残ります）。RST
によるリセットでは HP\_CTRL は元に戻りませんが、HEXMON が起動時に $8A を書き直します。

# 6\. HEXMON の API

API は、ROM の HEXMON
に入っているルーチンのうち、ユーザープログラムから呼べるようにしたものです。キー待ちや時間待ちのように、自分で書くと長くなる処理を、3バイトの
JSR 命令1つで使えます。定義は hexmon.inc にあります。

## 6.1 呼び方

  - JSR で呼び、処理が終わると RTS で戻ってきます。JSR 命令は3バイト（20 ＋ 番地の下位 ＋ 番地の上位）です。例：JSR
    WAIT\_KEY → 20 06 FF。

  - 番地は ROM の $FF00 からのジャンプテーブルで**固定**です。HEXMON
    を改造しても変わらないので、打ち込み済みのプログラムはそのまま動きます（新しい
    API は後ろに追加します）。

  - 「壊すレジスタ」は、呼ぶと値が変わるレジスタです。残しておきたい値は、呼ぶ前にゼロページなどに保存しておきます。

  - 10進モード（SED）を使ったら、呼ぶ前に CLD で2進モードに戻します。

## 6.2 一覧

|          |             |                            |                   |                             |            |
| -------- | ----------- | -------------------------- | ----------------- | --------------------------- | ---------- |
| **アドレス** | **名前**      | **働き**                     | **入力**            | **出力**                      | **壊すレジスタ** |
| $FF06    | WAIT\_KEY   | キーが押されるまで待つ                | —                 | A=キーコード                     | A          |
| $FF03    | POLL\_KEY   | キーを1回調べる（待たない）             | —                 | C=1：新しく押された（A=キーコード）／C=0：なし | A          |
| $FF09    | DELAY\_MS   | 指定ミリ秒だけ待つ                  | A=ミリ秒（0は256）      | —                           | A          |
| $FF0F    | DELAY\_10MS | 10ミリ秒単位で待つ                 | A=10ms単位（0は2.56秒） | —                           | A, X       |
| $FF00    | DISPLAY     | 表示バッファ SEGDATA の6桁を表示する    | SEGDATA           | —                           | A, X       |
| $FF0C    | PUT\_HEX    | 1バイトを16進2桁にして SEGDATA へ入れる | A=値、X=桁位置         | SEGDATA+X に下位、+X+1 に上位      | A          |

## 6.3 キー入力：WAIT\_KEY・POLL\_KEY

### WAIT\_KEY（$FF06）

キーが新しく押されるまで待ち、A
にキーコード（5.3）を入れて戻ります。押しっぱなしのキーは1回しか返しません。キーを待つだけなら、HP\_KEY
を直接読むよりも短く書けます。

> LOOP: jsr WAIT\_KEY ; 20 06 FF キーを待つ (A=キーコード)
> 
> cmp \#KEY\_AD ; A/D なら
> 
> beq DONE ; 終わり
> 
> sta HP\_HEX0 ; それ以外は右2桁に表示
> 
> bra LOOP

### POLL\_KEY（$FF03）

キーが押されていなくても、すぐに戻ります。新しく押されたキーがあれば C=1 で A にキーコード、なければ C=0
です。表示や計算を続けながら、ときどきキーを調べるときに使います。

> LOOP: ... ; くり返したい処理
> 
> jsr POLL\_KEY ; 20 03 FF
> 
> bcc LOOP ; 押されていなければくり返す
> 
> ; ここに来たら A にキーコード

LDA HP\_KEY / BPL で直接調べるのと同じ長さです。直接読む場合は、A の bit7 が立ったままなので、キーコードだけにするには
AND \#$1F が要ります。

## 6.4 時間待ち：DELAY\_MS・DELAY\_10MS

### DELAY\_MS（$FF09）

A に入れたミリ秒だけ待ちます（1〜255。0 は 256ms）。CPU 基板の 6522 のタイマー T1 を 1ms
周期で数えているので、プログラムの長さや CPU
の速さに関係なく正確です。誤差は1回の呼び出しあたり
1ms 未満です。

> lda \#250 ; 250ms
> 
> jsr DELAY\_MS ; 20 09 FF

### DELAY\_10MS（$FF0F）

A×10ms だけ待ちます（0 は 2.56 秒）。1秒以上待つときに使います。A のほか X も壊れます。

> lda \#100 ; 1秒 (100 x 10ms)
> 
> jsr DELAY\_10MS ; 20 0F FF
> 
> **注意　**6522 の T1 と ACR（$800B）をプログラムで変えると、どちらも正しく待てなくなります（T2 は自由に使えます）。

## 6.5 表示バッファ：DISPLAY・PUT\_HEX

ゼロページの $02-$07 を表示バッファ SEGDATA として使い、まとめて表示する方法です。SEGDATA+0
が右端、SEGDATA+5 が左端で、入れる値は 5.5 の表示コードです。

  - **DISPLAY（$FF00）**：SEGDATA の6桁を、表示レジスタ HP\_DIGIT0〜5 にまとめて写します。

  - **PUT\_HEX（$FF0C）**：A の値を16進2桁に分け、SEGDATA+X に下位4ビット、SEGDATA+X+1
    に上位4ビットを入れます（表示はまだ変わらない）。

> lda $20 ; 表示したい値
> 
> ldx \#0 ; 右2桁
> 
> jsr PUT\_HEX ; 20 0C FF
> 
> jsr DISPLAY ; 20 00 FF

1バイトを表示するだけなら、LDA $20 / STA HP\_HEX0（5.6）の方が短く書けます。モニタは自分の表示も SEGDATA
に入れているので、右2桁だけ書いて DISPLAY を呼ぶと、左4桁にはモニタのアドレスが残ります。

# 7\. ハードウェアを直接使う

GPIO・UART は I/O レジスタに直接読み書きして使います。レジスタの一覧は付録 B にあります。

## 7.1 ユーザー LED（PA7〜PA4）

6522 のポート A の上位4ビットが CPU 基板のユーザー LED に、下位4ビットがユーザースイッチにつながっています（図6）。

![](media/image6.png)

図6　ユーザー LED・スイッチと、ポート A のビットの対応

|          |        |        |        |        |        |        |        |        |
| -------- | ------ | ------ | ------ | ------ | ------ | ------ | ------ | ------ |
| **シルク**  | **D0** | **D1** | **D2** | **D3** | **S0** | **S1** | **S2** | **S3** |
| ポート A    | PA7    | PA6    | PA5    | PA4    | PA0    | PA1    | PA2    | PA3    |
| ORA のビット | bit7   | bit6   | bit5   | bit4   | bit0   | bit1   | bit2   | bit3   |

> **注意　**LED は、シルクの番号とビットの番号が逆順です（シルクの D0 が bit7、D3 が bit4）。

LED は、ORA のビットが **1 で点灯**します。出力にするには、DDRA（$8003）の上位4ビットを1にします。

> lda \#$F0
> 
> sta $8003 ; DDRA : PA7-4 を出力に
> 
> lda \#$50
> 
> sta $8001 ; ORA : PA6 と PA4 を 1 に

出力にしたビットは、ORA を読むとその値が返ります。そのため LDA $8001 / EOR \#$F0 / STA $8001 だけで
LED を反転できます（サンプル集の⑨）。

> **メモ　**ユーザースイッチを押している間は、LED に CPU のアドレス（デバッグ表示）が出ます。また、HEXMON は起動時（RST
> を含む）に ORA と DDRA を 0 に戻すので、LED は消えます。

## 7.2 ユーザースイッチ（PA3〜PA0）

シルクの S0〜S3 が PA0〜PA3 です（図6）。押すと 0、離すと 1 が読めます。

> lda $8001 ; ORA を読む
> 
> and \#$0F ; PA3-0 = SW3-SW0 (押すと 0)

## 7.3 タイマー T2（ワンショット）

T2 は CPU クロック（約1.8425MHz、1ms ≒ 1842 カウント）で1ずつ減り、0 になると IFR（$800D）の bit5
が立ちます。T1 はモニタが使っているので使わないでください。

> lda \#\<18424 ; 約10ms
> 
> sta $8008 ; T2CL
> 
> lda \#\>18424
> 
> sta $8009 ; T2CH : 書くとスタート
> 
> WAIT: lda $800D ; IFR
> 
> and \#$20 ; bit5 = T2
> 
> beq WAIT
> 
> lda $8008 ; T2CL を読むとフラグがクリアされる

## 7.4 シリアル（UART）

CPU 基板の USB-C（図1の1）で PC につながります。19200bps・8ビット・パリティなし・ストップビット1
で固定です。最初にコマンドレジスタへ $0B
を書きます（割り込みなし）。打ち込んで試せる例は別冊「サンプル集」の⑫⑬にあります。

> lda \#$0B
> 
> sta $8402 ; コマンド : 割り込みなし
> 
> PUTC: pha ; A の文字を1文字送る
> 
> PUTW: lda $8401 ; ステータス
> 
> and \#$10 ; bit4 = 送信バッファ空き
> 
> beq PUTW
> 
> pla
> 
> sta $8400 ; 送信
> 
> rts
> 
> GETC: lda $8401 ; 1文字受け取る (届くまで待つ)
> 
> and \#$08 ; bit3 = 受信データあり
> 
> beq GETC
> 
> lda $8400 ; 受信データ
> 
> rts

## 7.5 HEXPAD を直接使う

表示とキーは、5章のレジスタで直接使えます。CPLD が TM1627 との通信をすべて行うので、TM1627 を直接操作する必要はありません。

# 付録 D　ROM の書き込み

HEXMON を更新したときは、PC から ROM（Flash）に書き込みます。ツールは
6502-CPLD/soft/tool/writebin.py（Python と pyserial が必要）です。

> python writebin.py --port COM3 --file hexmon.bin

1.  スクリプトを起動し、案内に従って CPU 基板の BURN スイッチ（図1の5）を押す（Flash の消去が始まる）

2.  消去が終わったら、もう一度 BURN スイッチを押す（16KB の書き込みが始まる）

3.  書き込みが終わったら RESET スイッチを押す

> **メモ　**書き込み中は CPU が止まっています。ポート名（COM3 など）は PC の環境に合わせてください。
