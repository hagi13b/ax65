## 1. この資料について

- AX65 のコンパイラはまだ存在しません。「コンパイル結果」は、仕様書 1.0 の規則に従って手で生成した**想定出力**です。実際のコンパイラの出力とは、細部が違う可能性があります。
- 測定には、作業用に作った 65C02 のアセンブラとエミュレータを使いました（`tools/`）。サイクル数は W65C02S のデータシートの値で、ページ境界をまたぐ場合の +1、分岐の +1／+2、10進モードの `adc`・`sbc` の +1 を含みます。
- コード例と仕様の参照は、すべて仕様書 1.0 の書き方と章番号です。

再現の手順（Python 3.8 以上。外部のパッケージは使いません）：

```
cd ax65_1.0/sample
python3 -I tools/run_bench.py
```

`asm/` に `.bin`・`.lst`・`.sym.json` を作り、`results/bench_result.json` に結果を書き、要約を表示します。

AX65 のコンパイラができた後は、次のコマンドで同じものを作る想定です。

```
cd ax65_1.0/sample/project
ax65 build -t v2 -O0 -o build/O0
ax65 build -t v2 -O1 -o build/O1
ax65 build -t v2            -o build/O2      # 既定（-O2）
ax65 build -t v2 -Os -o build/Os
ax65 check --all-targets                     # v2 と v3 の両方で検査
```

## 3. ゲームの仕様

`project/src/meteor.ax65` が実装しているゲームの仕様です。手書き版の `asm/meteor_hand.s` も、この仕様に従って作っています。


### 3.1 概要

画面の上から落ちてくる 8 個の隕石を、画面の一番下にいるプレイヤーが左右に動いてよけるゲームです。隕石が下まで落ちきるたびに 1 点が入ります。隕石に当たるか、終了のキーを押すとゲームが終わります。

### 3.2 動作環境

| 項目 | 内容 |
|---|---|
| CPU | W65C02S（65C02）。`wai` 命令がある場合は、待ち時間に使う |
| クロック | 1MHz を基準とする（ターゲット定義のクロックからタイマーの周期を計算する） |
| タイマー | VIA（6522）のタイマー1 を $6000 番地台に置く。連続モードで割り込みを起こす |
| 入出力 | v2：シリアル端末（ACIA）。v3：画面とキーボード |
| 実行の形 | RAM の $0300 に読み込み、モニタから実行する。終わったらモニタへ戻る |
| 割り込み | IRQ を使う。ベクタはモニタが用意する RAM 上の場所（$0280）に書く |

### 3.3 フィールド

- フィールドの大きさは、横 20 マス（列 0〜19）、縦 16 マス（行 0〜15）です。
- プレイヤーは常に行 15（一番下の行）にいます。
- 隕石は行 0 に現れ、行 15 まで落ち、行 16 に達した時点で消えます（画面のある構成では、行 16 に床を描きます）。

### 3.4 時間の進み方

- ゲームは 1 秒に 60 回の「フレーム」単位で進みます。
- VIA のタイマー1 を、1/60 秒ごとに割り込みが起きるように設定します。1MHz では周期の設定値は 16664（$4118）で、実際の周期は 16666 サイクルです。
- 割り込みのたびにフレームの番号（TICKS）を 1 増やします。
- メインの処理は、TICKS が前のフレームから変わるのを待ってから、1 フレーム分の処理を行います。待つ間は、`wai` 命令で CPU を止めます。
- 1 フレームの処理が 1/60 秒を超えた場合、次のフレームは待たずにすぐ始まります（遅れを取り戻すための追加の処理はしません）。

### 3.5 起動時の動作

1. 割り込みを止め、VIA のタイマーを設定する
2. 変数を初期化する（プレイヤーの列 10、スコア 0、乱数の種 $5A、TICKS 0）
3. 端末に「METEOR DODGE」と復帰（$0D）を出力する
4. 8 個の隕石を、番号 0 から 7 の順に出現させる（7節の「出現」）
5. 割り込みを許可し、フレームのループを始める

### 3.6 1 フレームの処理

1 フレームでは、次の順序で処理します。

1. **フレームを待つ**：TICKS が変わるまで待つ
2. **入力**：キーが 1 つ届いていれば読み、操作する（8節）。終了のキーならゲームオーバーへ進む（この場合、このフレームの隕石の更新は行わない）
3. **隕石の更新**：8 個の隕石を、番号 0 から 7 の順に更新する（7節）
4. **当たりの判定**：更新の途中で 1 個でも当たりがあれば、8 個すべての更新を終えた後でゲームオーバーへ進む（この場合、このフレームの表示は行わない）
5. **表示**：フィールドの状態を表示する（9節）

### 3.7 隕石

#### 持っている情報

各隕石は、列（x）、行（y）、待ち時間（wait）を持ちます。

#### 出現

隕石を出現させるときは、乱数 r を 1 つ取り、次のように設定します。

| 項目 | 値 |
|---|---|
| 列 x | 出現位置の表の、r の下位 3 ビット番目の値 |
| 行 y | 0 |
| 待ち時間 wait | r の下位 2 ビット（0〜3） |

出現位置の表は、番号 i（0〜7）に対して (i × 7 + 3) mod 20 で、値は次のとおりです。

| 番号 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| 列 | 3 | 10 | 17 | 4 | 11 | 18 | 5 | 12 |

隕石が出てくる列はこの 8 列だけで、残りの 12 列（0、1、2、6〜9、13〜16、19）には隕石が来ません。

#### 更新

各フレームで、各隕石を次のように更新します。

1. 待ち時間が 0 より大きければ、待ち時間を 1 減らして、この隕石の処理を終える
2. 待ち時間が 0 なら、待ち時間を 3 にし、行を 1 増やす（1 マス落ちる）
3. 落ちた結果、行が 16 になったら、その隕石を出現させ直し（新しい乱数を使う）、スコアに 1 を足す
4. そうでなく、行が 15 で、かつ列がプレイヤーの列と同じなら、当たりとする

この規則により、隕石は 4 フレームに 1 マスの速さで落ちます。出現してから行 16 に達するまでは、最初の待ち時間（0〜3 フレーム）に加えて 61 フレームかかります（最初の待ちの後の 1 フレームで行 1 に落ち、その後 4 フレームごとに 1 行ずつ落ちて、15 回で行 16 に達するため）。

#### 当たりの判定についての注意

当たりは、隕石が行 15 に「落ちてきた」フレームにだけ判定します。隕石がすでに行 15 にいるときに、プレイヤーがその列へ移動しても、当たりにはなりません。また、複数の隕石が同じマスに重なることがあります。

### 3.8 操作

| キー | 動作 |
|---|---|
| A または a | 1 列左へ移動する。列 0 では動かない |
| D または d | 1 列右へ移動する。列 19 では動かない |
| Q または q | ゲームを終了する（ゲームオーバーと同じ表示をする） |
| それ以外 | 無視する |

- キーは 1 フレームに最大 1 つだけ読みます。
- 移動は、同じフレームの隕石の更新より先に行われます。当たりの判定には、移動後の列を使います。

### 3.9 表示

#### 画面のない構成（v2）

毎フレーム、端末に次の文字列を出力します。

```
\rSCORE dddd
```

`\r` は復帰（$0D）、`dddd` はスコアの 10 進 4 桁（先頭の 0 も表示）です。同じ行に上書きされるので、端末にはスコアが 1 行で表示され続けます。

#### 画面のある構成（v3）

毎フレーム、画面を消してから、次のものを描きます。

| 描くもの | 位置 | 文字 |
|---|---|---|
| 床 | 行 16 の列 0〜19 | `-` |
| 隕石 | 各隕石の (x, y) | `*` |
| プレイヤー | (プレイヤーの列, 15) | `A` |

文字は、ターゲット定義の画面用の変換表で、機種の文字コードに変換されます。

### 3.10 スコア

- スコアは 10 進 4 桁（BCD）で持ちます。
- 隕石が下まで落ちきるたびに 1 点足します。
- 9999 点の次は 0000 点に戻ります。

### 3.11 乱数

- 8 ビットの線形帰還シフトレジスタ（ガロア型）を使います。
- 種を 1 ビット左にずらし、はみ出たビットが 1 なら $1D と XOR を取ったものを、新しい種とし、乱数の値にもします。
- 種の初期値は $5A です。種が 0 以外なら、0 を除く 255 種類の値を一巡します。
- 乱数は隕石を出現させるときにだけ使い、起動時の 8 回と、隕石が落ちきるたびに 1 回ずつ取ります。番号の小さい隕石から順に取るので、同じキー操作をすれば、毎回同じゲームの展開になります。

### 3.12 ゲームオーバー

当たりがあったか、終了のキーが押されたら、次の文字列を出力して、モニタへ戻ります。

```
\rGAME OVER  SCORE dddd\r
```

## 4. サンプルのプロジェクト（全ファイル）

ファイルの置き場所は [2章](#r2) の図のとおりです。ターゲット v2 では `console` に ACIA の実装が bind され、`screen` は bind されません。v3 は v2 を引き継ぎ、画面を加えます。

### 4.1 `project/ax65.proj` — プロジェクトファイル（仕様書 17.2）

関連する仕様：[仕様書](../spec/ax65_spec_1.0.md#s17-2)

```
// ax65.proj — meteor プロジェクトの設定（仕様書 1.0 17.2節）
project meteor {
    main       = "src/meteor.ax65";     // プログラムの入口（main を含むファイル）
    paths      = ["."];                 // use でモジュールを探す場所（hw::acia_console → ./hw/acia_console.ax65）
    target_dir = "targets";             // ターゲット定義を探す場所
    targets    = [v2, v3];              // ax65 check --all-targets の対象
    default    = v2;                    // -t を省略したときのターゲット
    opt        = O2;                    // -O を省略したときの最適化の段階（既定も O2）
    out_dir    = "build";               // 出力先（build/<ターゲット名>/ の下に出力する）

    lints {                             // 警告の扱い（allow / warn / deny）
        naming         = warn;
        unused_imports = warn;
    }
    fmt {                               // ax65 fmt の書き方
        hex   = dollar;                 // 16進は $FF に統一する（0x にするなら hex = c）
        array = rust;                   // 配列の型は [T; N] に統一する（従来の T[N] にするなら legacy）
    }
}
```

### 4.2 `project/targets/v2.target` — ターゲット定義 v2（仕様書 16章）

関連する仕様：[仕様書](../spec/ax65_spec_1.0.md#s16)

```
// targets/v2.target — シリアル端末だけの構成（仕様書 1.0 16章）
target v2 {
    cpu          = Cpu::W65C02S;        // CPU の品種
    clock        = 1_000_000;           // 1MHz
    stack        = 128;                 // ハードウェアスタックの予算（バイト）
    run          = ram;                 // RAM に読み込んで実行する
    load         = $0300;               // 読み込み先（Wozmon から 300R で実行する）
    exit         = monitor($FF1F);      // main が終わったらモニタへ戻る
    irq          = indirect($0280);     // モニタの ROM が jmp ($0280) で IRQ 処理へ飛ぶ
    nmi          = indirect($0282);     // 同じく NMI
    irq_interval = 16_666;              // IRQ の最短の間隔（サイクル）。割り込み処理の時間の検査に使う

    region zp    = $00..=$EF;           // ゼロページのうち使ってよい範囲
    region stack = $0100..=$01FF;
    region ram   = $0200..=$1FFF;       // RAM 8KB
    region io    = $6000..=$8FFF;       // VIA（$6000）と ACIA（$8000）
    reserve $24..=$2B;                  // Wozmon が使うゼロページ
    reserve $0200..=$0283;              // Wozmon の入力バッファと、IRQ・NMI のベクタ

    output = [woz, bin, sym, lst];      // 既定で出力する形式

    bind console = hw::acia_console;    // 1文字の入出力は ACIA
    // screen は bind しない → target.has(screen) は false
}
```

### 4.3 `project/targets/v3.target` — ターゲット定義 v3（v2 を引き継ぐ）

関連する仕様：[仕様書](../spec/ax65_spec_1.0.md#s16-1)

```
// targets/v3.target — v2 に画面を追加した構成（仕様書 1.0 16.1節の extends）
target v3 extends v2 {
    clock        = 2_000_000;           // 2MHz に上げた
    irq_interval = 33_333;
    load         = $0800;               // 画面メモリ（$0400〜$07FF）の後ろに読み込む

    region ram = [$0200..=$03FF, $0800..=$BFFF];    // 区画を書き直す（同じ種類の区画は置き換え）
    region io  = [$0400..=$07FF, $6000..=$8FFF];    // 画面メモリを I/O の区画に加える

    encoding screen {                   // 画面用の文字の変換表（Apple II と同じ並び）
        ' '..='?' => $A0..=$BF;
        '@'..='_' => $C0..=$DF;
    }

    bind screen = hw::v3_screen;        // 画面の実装
    const SCREEN_WIDTH: u8 = 40;        // コードを伴わない性質は定数で書く
}
```

### 4.4 `project/src/meteor.ax65` — ゲームの本体

関連する仕様：[仕様書](../spec/ax65_spec_1.0.md#s1)

```
// src/meteor.ax65 — ax65 サンプル：隕石よけゲーム（ax65 仕様書 1.0）
//
// 想定するターゲット：
//   v2 … シリアル端末だけの構成（スコアを端末に表示する）
//   v3 … 画面のある構成（隕石とプレイヤーを画面に描く）
// どちらのターゲットも、$6000 に VIA（6522）があり、
// main が終わったらモニタへ戻る（exit = monitor(...)）。ターゲット定義は targets/ を参照。
// console の実装は hw/acia_console.ax65、screen の実装は hw/v3_screen.ax65（v3 だけ）。
//
// 操作：A で左、D で右、Q で終了

use console::{putc, poll};              // 1文字の入出力（実装はターゲットの bind で決まる）
use screen;                             // 画面（bind されていないターゲットもある）

// ---- 定数 ---------------------------------------------------------------

const FIELD_W: u8 = 20;                 // 画面の幅（マス）
const FIELD_H: u8 = 16;                 // 画面の高さ（マス）
const PLAYER_Y: u8 = FIELD_H - 1;       // プレイヤーは一番下の行にいる

// タイマーの周期：1/60 秒ごとに割り込みを起こす（クロックはターゲット定義から読む）
comptime assert(target.clock / 60 <= 65535, "クロックが速すぎて、タイマーの周期が16ビットに収まらない");
const T1_PERIOD: u16 = (target.clock / 60 - 2) as u16;

const TITLE: str = p"METEOR DODGE";     // 長さ付きの文字列（ASCII）

// ---- 型 -----------------------------------------------------------------

range Mid = 0..8;                       // 隕石の番号（0〜7）。終わりの 8 は含まない

enum Key { Left, Right, Quit }          // 操作の種類

flags Ifr { Ca2, Ca1, Shift, Cb2, Cb1, T2, T1, Any }   // VIA の割り込みフラグ（ビット0〜7）

struct Meteor { x: u8, y: u8, wait: u8 }   // wait：次に1マス落ちるまでのフレーム数

// ---- 表（コンパイル時に計算する） --------------------------------------

comptime fn spawn_x(i: int) -> u8 {     // 隕石が出てくる列（コンパイル時専用の関数）
    ((i * 7 + 3) % 20) as u8            // int の計算なので、% も自由に使える
}

const SPAWN_X: [u8; Mid] = [for i in 0..8 => spawn_x(i)];   // 8個の出現位置の表

// ---- 変数 ---------------------------------------------------------------

static METEORS: [Meteor; Mid] = [Meteor { x: 0, y: 0, wait: 0 }; Mid];  // フィールドごとの配列になる
static PLAYER_X: u8 = FIELD_W / 2;  // プレイヤーの列
static SCORE: bcd16 = 0;            // スコア（10進4桁）
static SEED: u8 = $5A;              // 乱数の種（0 以外）

shared(irq) TICKS: u16 = 0;             // 1/60 秒ごとに増える。書き込むのは割り込み処理だけ

// ---- I/O（VIA） ---------------------------------------------------------
// 本来は VIA のドライバのモジュールにまとめるが、サンプルなのでここに置く。
// I/O 変数は pub にできないので、このモジュールの外からは触れない。

io        T1C_L: u8  @ $6004;           // タイマー1 下位（書くと周期の設定、読むと割り込みフラグが消える）
io(out)   T1C_H: u8  @ $6005;           // タイマー1 上位（書いた瞬間にタイマーが動き出す）
io(out)   ACR:   u8  @ $600B;           // 補助制御レジスタ
io(in)    IFR:   Ifr @ $600D;           // 割り込みフラグ（ビットフラグ型として読む）
io(out)   IER:   u8  @ $600E;           // 割り込みの許可

init {                                  // 起動時に main の前に1回だけ実行される（割り込みは止まったまま）
    ACR   = 0b0100_0000;                // タイマー1 を連続モードにする
    T1C_L = (T1_PERIOD & $FF) as u8;    // 下位を先に書く（I/O の読み書きの順序はソースどおりに守られる）
    T1C_H = (T1_PERIOD >> 8) as u8;     // 上位を書くと動き出す
    IER   = 0b1100_0000;                // タイマー1 の割り込みを許可する
}

// ---- 割り込み -----------------------------------------------------------

#[interrupt(irq)]
fn on_irq() {
    if IFR.contains(Ifr::T1) {          // タイマー1 による割り込みか
        let _ = T1C_L;                  // 読むだけで割り込みフラグが消える（この読み込みは省略されない）
        TICKS += 1;                     // 割り込み処理の中なので atomic は不要（10.4節）
    }
}

fn ticks() -> u16 {
    atomic { TICKS }                    // 16ビットの読み込みは2命令なので、割り込みを止めて読む
}

fn wait_frame(last: u16) -> u16 {       // 次のフレーム（TICKS が変わる）まで待つ
    loop {
        let now = ticks();
        if now != last { return now; }
        comptime if target.cpu == Cpu::W65C02S {
            wait_interrupt();           // W65C02S なら、割り込みが来るまで CPU を止めて待つ
        }
    }
}

// ---- 乱数 ---------------------------------------------------------------

asm fn rand_step(r: u8) -> u8 {         // 8ビットの疑似乱数（ガロア型 LFSR）。r は A で届き、A で返す
    asl a                   ; A を左に1ビットずらす（はみ出たビットはキャリーへ）
    bcc done                ; はみ出たビットが 0 なら、そのまま done へ飛ぶ
    eor #$1D                ; 1 なら、決まった値と XOR を取る（周期が最大の255になる定数）
done:                       ; 合流地点
    rts                     ; A を戻り値として返す
}

fn rand() -> u8 {
    SEED = rand_step(SEED);
    SEED                                // 最後の式が戻り値になる（return を省略）
}

// ---- 入力 ---------------------------------------------------------------

fn read_key() -> Option<Key> {
    let c = poll()?;                    // キーが押されていなければ、この関数も None を返して抜ける
    match c {
        'A' | 'a' => Some(Key::Left),
        'D' | 'd' => Some(Key::Right),
        'Q' | 'q' => Some(Key::Quit),
        _         => None,              // char は値が多いので、_ が必須
    }
}

fn move_player(k: Key) {
    match k {                           // Key の値をすべて書かないとエラーになる
        Key::Left  => { PLAYER_X = PLAYER_X.saturating_sub(1); }   // 0 より左には行かない
        Key::Right => { if PLAYER_X < FIELD_W - 1 { PLAYER_X += 1; } }
        Key::Quit  => {}
    }
}

// ---- 隕石 ---------------------------------------------------------------

fn clear_meteors() {
    #[reg(x)]                           // ループの番号を X に置く（中で関数を呼ばないので置ける）
    for m in Mid {                      // m は Mid 型なので、METEORS[m] に範囲の検査は要らない
        METEORS[m].y = 0;
        METEORS[m].wait = m as u8;      // 出てくる時間をずらす
    }
}

fn respawn(m: Mid) {                    // 隕石を一番上の行に出し直す
    let r = rand();
    METEORS[m].x = SPAWN_X[Mid::wrap(r)];   // 下位3ビットだけを取って、必ず 0〜7 にする（and 1命令）
    METEORS[m].y = 0;
    METEORS[m].wait = r & 3;
}

fn update_meteors() -> bool {           // 隕石を動かし、プレイヤーに当たったら true を返す
    let hit = false;
    for m in Mid {
        if METEORS[m].wait > 0 {
            METEORS[m].wait -= 1;
            continue;
        }
        METEORS[m].wait = 3;
        METEORS[m].y += 1;
        if METEORS[m].y == FIELD_H {    // 下まで落ちきったら、上から出直す
            respawn(m);
            SCORE += 1;                 // BCD の足し算（sed と cld はコンパイラが入れる）
        } else if METEORS[m].y == PLAYER_Y && METEORS[m].x == PLAYER_X {
            hit = true;
        }
    }
    hit
}

// ---- 表示 ---------------------------------------------------------------

fn print(s: str) {                      // 長さ付きの文字列を出力する
    for c in s { putc(c); }
}

fn print_score() {
    for d in SCORE.digits() {           // 上の桁から1桁ずつ（0〜9）取り出す
        putc(('0' as u8 + d) as char);
    }
}

fn draw() {
    comptime if target.has(screen) {    // 画面が bind されているターゲットだけ
        screen::clear();
        for x in (0..FIELD_W).rev() {   // 逆順のループ（dex と bpl で回るので少し速い）
            screen::put(x, FIELD_H, '-'@screen);    // 床を描く（画面用の文字コードに変換済み）
        }
        for m in Mid {
            screen::put(METEORS[m].x, METEORS[m].y, '*'@screen);
        }
        screen::put(PLAYER_X, PLAYER_Y, 'A'@screen);
    } else {                            // 画面がないターゲット：スコアだけを端末に上書き表示する
        putc('\r');
        print(p"SCORE ");
        print_score();
    }
}

// ---- メイン -------------------------------------------------------------

fn main() {
    print(TITLE);
    putc('\r');

    clear_meteors();
    for m in Mid { respawn(m); }

    irq_enable();                       // ここで初めて割り込みを許可する

    let last = ticks();
    'game: loop {
        last = wait_frame(last);
        if let Some(k) = read_key() {
            if k == Key::Quit { break 'game; }
            move_player(k);
        }
        if update_meteors() { break 'game; }
        draw();
    }

    print(p"\rGAME OVER  SCORE ");
    print_score();
    putc('\r');
}                                       // main が終わるとモニタへ戻る（ターゲット定義の exit）
```

関連する仕様：[仕様書](../spec/ax65_spec_1.0.md#s8-4)

```
// hw/acia_console.ax65 — console インターフェースの ACIA（6551）による実装（仕様書 1.0 8.4節）

flags AciaStatus { Pe, Fe, Ovr, Rdrf, Tdre, Dcd, Dsr, Irq }    // ビット0〜7

impl console {
    io      DATA:   u8         @ $8000; // 送信データ（書く）と受信データ（読む）
    io(in)  STATUS: AciaStatus @ $8001; // 状態（読み込み専用）

    fn putc(c: char) {                  // 送信の準備ができるまで待ってから 1 文字送る（インターフェースの関数は自動で公開される）
        while !STATUS.contains(AciaStatus::Tdre) { }
        DATA = c as u8;
    }

    fn poll() -> Option<char> {         // 受信していれば文字を返し、していなければ None
        if STATUS.contains(AciaStatus::Rdrf) { Some(DATA as char) } else { None }
    }

    fn getc() -> char {                 // 1 文字届くまで待つ
        loop {
            if let Some(c) = poll() { return c; }
        }
    }
}
```

// hw/v3_screen.ax65 — screen インターフェースの、v3 の画面メモリによる実装（仕様書 1.0 8.4節）

range Col = 0..40;                      // 列（0〜39）
range Row = 0..24;                      // 行（0〜23）

impl screen {
    const WIDTH: u8 = 40;               // インターフェースの定数（関数と同じく自動で公開され、pub は書かない）
    const HEIGHT: u8 = 24;

    io VRAM: [[u8; Col]; Row] @ $0400;  // 画面メモリ（行ごとの先頭アドレスの表はコンパイラが作る）

    fn clear() {                        // 画面全体を空白にする
        for r in Row {
            for c in Col { VRAM[r][c] = ' '@screen as u8; }
        }
    }

    fn put(x: u8, y: u8, c: char@screen) {          // 画面の外なら何もしない
        if let Some(r) = Row::check(y) {
            if let Some(col) = Col::check(x) { VRAM[r][col] = c as u8; }
        }
    }
}

| `for c in s { putc(c); }` | 長さ付きの文字列を回す。`str` の引数はポインタで、A と X で渡る | [3.9](../spec/ax65_spec_1.0.md#s3-9)、[15.2](../spec/ax65_spec_1.0.md#s15-2) |
| `for d in SCORE.digits()` | BCD の桁の取り出し | [5.5](../spec/ax65_spec_1.0.md#s5-5) |
| `('0' as u8 + d) as char` | 型の変換（`u8` ↔ `char`） | [3.14](../spec/ax65_spec_1.0.md#s3-14) |
| `comptime if target.has(screen) { … } else { … }` | bind の有無による条件コンパイル。v2 では else 側だけが残る | [13.6](../spec/ax65_spec_1.0.md#s13-6)、[16.6](../spec/ax65_spec_1.0.md#s16-6) |
| `(0..FIELD_W).rev()` | 逆順のループ | [6.4](../spec/ax65_spec_1.0.md#s6-4) |
| `'-'@screen` | 画面の変換表で変換した文字（v3 の `encoding screen`） | [3.3](../spec/ax65_spec_1.0.md#s3-3)、[16.5](../spec/ax65_spec_1.0.md#s16-5) |
| `irq_enable();` | 割り込みの許可（`main` で明示する） | [10.3](../spec/ax65_spec_1.0.md#s10-3) |
| `main` の終わり | ターゲット定義の `exit = monitor($FF1F)` に従ってモニタへ戻る | [15.1](../spec/ax65_spec_1.0.md#s15-1)、[16.4](../spec/ax65_spec_1.0.md#s16-4) |

コンパイラがこのプログラムについて確かめること：

| 検査 | このプログラムでの内容 |
|---|---|
| 再帰がない | すべての呼び出し関係に輪がない |
| スタックの予算 | 最も深い経路は start → main → update_meteors → respawn → rand → rand_step の 10 バイトに、割り込みの分を足したもの（予算 128 バイト） |
| 範囲外の添字がない | `METEORS` と `SPAWN_X` の添字は、すべて `Mid` 型 |
| 値を入れる前の読み込みがない | すべてのローカル変数は、宣言と同時に値が入っている |
| 割り込みとの共有 | `TICKS` は割り込み処理だけが書き、メインは `atomic` の中で読む |
| I/O の向き | `io(in)` の `IFR` には書かず、`io(out)` のレジスタは読んでいない |
| match の網羅性 | `move_player` の `match` は `Key` のすべての値を書いている |
| Option の確認 | `read_key()`・`poll()` の結果は、`if let` と `?` で確かめてから使っている |
| ターゲットにない機能 | `wait_interrupt()` は `comptime if target.cpu == Cpu::W65C02S` の中だけ |
| bind の確認 | `screen` は `comptime if target.has(screen)` の中だけで使っている |

## 6. コンパイル結果（想定出力）

どの段階にも、段階にかかわらず行う規則（[仕様書 19.5](../spec/ax65_spec_1.0.md#s19-5)）が入っています。読み捨ての I/O に `bit`、初期値 0 は `stz`、末尾呼び出しは `jmp`、ポインタの引数は A と X です。

| ファイル | 段階 | 主な最適化 |
|---|---|---|
| `asm/meteor_O0.s` | -O0 | なし。変数は通常の RAM、ゼロページはポインタだけ。関数は展開しない |
| `asm/meteor_O1.s` | -O1 | ゼロページへの自動配置。1 か所からしか呼ばれない関数と、小さな `respawn` を展開。`clear_meteors` のループを逆順にした |
| `asm/meteor_O2.s` | -O2（既定） | ゼロページへの自動配置。展開は 1 か所からしか呼ばれない関数だけ（`respawn` は関数のまま、番号を X で渡す）。`clear_meteors` の不要な書き込みを削除。`print_score` の共通部分をくくり出し |
| `asm/meteor_Os.s` | -Os | -O2 に加えて `respawn` と `digits()` を展開。更新のループがページ境界をまたがないように、サブルーチンを起動処理の前に移した |

段階による違いが最も大きいのは、隕石の更新のループです。

```asm
; -O0：respawn が X と Y を壊すので、隕石の番号 m をメモリ（um_m）に置く
@loop:  ldx um_m                ; m を X に読む（毎回）
        lda M_WAIT,x            ; METEORS[m].wait を読む（通常の RAM なので 4 サイクル、3 バイト）
        ...
@next:  inc um_m                ; m を 1 増やす（メモリ上で）
        lda um_m                ; m を読む
        cmp #8                  ; 8 に達したか
        bne @loop               ; 1 回あたりの管理のコストは 19 サイクル

; -O2：respawn に m を X で渡し、respawn は X を変えないので、m を X に置いたまま回せる
upd_loop:
        lda M_WAIT,x            ; METEORS[m].wait（ゼロページなので 2 バイト）
        ...
upd_next:
        inx                     ; 次の m へ
        cpx #8                  ; 8 に達したか
        bne upd_loop            ; 1 回あたりの管理のコストは 7 サイクル
```

<a id="r7"></a>
## 7. 手書きのアセンブリ

`asm/meteor_hand.s` は、[3章](#r3) のゲームの仕様から、最初からアセンブリで書いたものです。端末への出力が、コンパイル版とまったく同じになるように書いています。

手書きならではの工夫は次のとおりです。

- **変数の置き場所**：よく使う変数と隕石の配列を、すべてゼロページに置く
- **呼び出しの展開**：乱数、出し直し、入力の判定などを、呼び出さずにその場に書く
- **割り込み処理**：レジスタを使わない（`bit` で調べて、`bit` で読み捨てる）
- **プログラムの書き方**：TICKS を 8 ビットにする、大文字と小文字を `ora #$20` でまとめて判定する、文字列を 0 終端で 1 つの表にまとめ、表の中の位置（X）で渡す

最後の 3 つはゲームの仕様を変えない範囲の書き方の違いで、AX65 のソースでも同じように書けます。

## 10. 考察

### 10.1 既定の -O2 で、速さは手書きとほぼ同じ

-O2 の 1 フレームは 740 サイクルで、手書き（724 サイクル）との差は 2 % です。-O0 からは 27 % 短くなりました。コードは手書きの 1.23 倍で、4 つの段階の中で最も小さくなっています。

差が最も大きく縮んだのは隕石の更新（360 → 233 サイクル）です。[6章](#r6) のとおり、-O0 では `respawn` が X を壊すためにループの番号をメモリに置くしかなく、1 回あたり 12 サイクル余分にかかっていました。-O2 は `respawn` を展開せずに、番号を X で渡すように渡し方を変えたので、番号を X に置いたまま回せます。

### 10.2 -O1 は -O2 より遅く、大きい

-O1 は `respawn` を 2 か所に展開したため、コードが大きくなり、更新のループが $0400 のページ境界をまたぎました。6502 では、分岐がページ境界をまたぐと 1 サイクル余分にかかるので、ループの 1 回ごとに 2 サイクル、8 個の隕石で 16 サイクル遅くなっています（更新 246 対 233 サイクル）。`respawn` が呼ばれるのは隕石が下まで落ちたときだけ（600 フレームで 72 回）なので、展開しても速くなりません。-O2 を既定にした理由の 1 つです（[仕様書 Q&A I-3](../spec/ax65_spec_1.0.md#qa-i3)）。

### 10.3 -Os は -O2 より 1.5 % 速く、10 % 大きい

-Os は 729 サイクルで、手書きとの差は 0.6 % です。速くなった分の大部分は、表示の `digits()` の展開（498 → 487 サイクル）と起動です。`respawn` も展開しましたが、更新はほとんど変わりません（233 → 231 サイクル）。meteor.AX65 の `respawn` に `#[cold]` を付ければ、-Os でも展開されず、速さはほぼそのままで、コードは 20 バイトほど小さくなる見込みです（[仕様書 7.7](../spec/ax65_spec_1.0.md#s7-7)）。

-Os では、ループの配置のためにサブルーチンを起動処理の前に移しました。その結果、キーがないときの分岐（$03F1 → $0428）がページ境界をまたぐようになり、入力の処理が 1 サイクル遅くなっています。何度も回るループを優先して配置した結果です。

### 10.4 実際のシリアル速度では、差はほとんど見えない

9600bps のシリアルでは、1 フレームの表示の 11 文字だけで約 11000 サイクルの送信待ちが生じます。そのため、1 フレームの時間は -O0 の 11042 サイクルから手書きの 10828 サイクルまで、差は 2 % にとどまりました。どの版も 1 フレーム（16666 サイクル）に収まり、ゲームとしての動作は同じです。CPU の処理の差が効いてくるのは、表示を画面メモリに直接書く v3 のような構成や、処理の多いゲームです。

### 10.5 どの段階でも縮まらない差

手書きとの差のうち、TICKS の大きさ（16 ビットと 8 ビット）、大文字と小文字の判定、文字列の渡し方は、プログラムの書き方の違いで、最適化の段階では縮まりません。どれも AX65 のソースでも同じように書けます。コードの大きさの差（-O2 で 1.23 倍）の多くも、これらと、起動処理のポインタの設定などから来ています。

### 10.6 まとめ

| 段階 | 1 フレーム（理想） | 手書きとの比 | 1 フレーム（シリアル） | コード | 位置づけ |
|---|---|---|---|---|---|
| -O0 | 1016 | 1.40 | 11042 | 581 | 生成されたコードを確かめたいとき |
| -O1 | 808 | 1.12 | 10861 | 433 | 初期の仕様 |
| **-O2（既定）** | **740** | **1.02** | **10847** | **386** | 大きさと速さの両方で最もよい |
| -Os | 729 | 1.006 | 10845 | 426 | あと少し速さが欲しいとき |
| 手書き | 724 | 1 | 10828 | 313 | ― |

### 11.3 差の理由

cc65 の最速の設定が出したアセンブリ（`cc65/meteor_Oirs_Cl_cs.s`）と比べると、差の大部分は次の 4 つから来ています。

**(1) 配列の要素を書き換えるたびに、アドレスを計算する。** `--m_wait[m];` を、cc65 は配列の先頭に番号を足したアドレスをゼロページのポインタに作ってから書き換えます。AX65 は番号を X に置いたまま 1 命令で書き換えます。

```asm
; cc65 -Oirs -Cl --codesize 500：--m_wait[m];
        lda #<(_m_wait)         ; 配列の先頭アドレスの下位
        ldx #>(_m_wait)         ; 上位
        clc                     ; 足し算の準備
        adc L00B8               ; 番号 m を足す
        bcc L00C9               ; 繰り上がりがなければ飛ばす
        inx                     ; 繰り上がりを上位に足す
L00C9:  sta ptr1                ; ポインタの下位に書く
        stx ptr1+1              ; 上位に書く
        ldx #$00                ; X を 0 にする（戻り値の上位の準備。使われない）
        lda (ptr1)              ; 指す先を読む
        sec                     ; 引き算の準備
        sbc #$01                ; 1 を引く
        sta (ptr1)              ; 書き戻す（ここまで約 35 サイクル）

; ax65 -O2：METEORS[m].wait -= 1;
        dec M_WAIT,x            ; X 番目を 1 減らす（6 サイクル）
```

**(2) ループの番号をメモリに置き、毎回比べ直す。** cc65 は `for (m = 0; m < NMET; ++m)` の `m` をメモリ（`L00B8`）に置き、要素を読むたびに `ldy L00B8` で読み直します。AX65 は番号を X に置いたまま回します（[6章](#r6)）。

**(3) 引数を C のソフトウェアスタックで渡す。** cc65 は `putc_acia(c)` の引数を、呼び出し先の入口で C のスタックに積み（`pusha`）、`(sp)` で読み、出口で捨てます（`incsp1`）。表示の 11 文字のそれぞれで、このコストがかかります。AX65 は A で渡します（[仕様書 15.2](../spec/ax65_spec_1.0.md#s15-2)）。

```asm
; cc65 -Oirs -Cl --codesize 500：putc_acia(c)
        jsr pusha               ; 引数（A）を C のスタックに積む（ライブラリのルーチン）
L0135:  lda $8001               ; 送信できるか調べる
        and #$10                ; 送信バッファが空のビット
        beq L0135               ; まだなら待つ
        lda (sp)                ; 引数を C のスタックから読む
        sta $8000               ; 送る
        jmp incsp1              ; C のスタックから引数を捨てて戻る（ライブラリのルーチン）

; ax65 -O2：putc(c)
        sta putc_c              ; 引数（A）をしまう
@wait:  lda ACIA_STATUS         ; 送信できるか調べる
        and #$10                ; 送信バッファが空のビット
        beq @wait               ; まだなら待つ
        lda putc_c              ; 引数を読む
        sta ACIA_DATA           ; 送る
        rts                     ; 戻る
```

**(4) 文字列のポインタを、1 文字ごとに C のスタックから読み直す。** cc65 の `print(s)` は、`s` を C のスタックに置き、1 文字ごとに `(sp),y` で読んでゼロページのポインタに写してから文字を読みます。AX65 は、ポインタをゼロページに 1 回だけ置き、`(pr_s),y` で読みます。

`-Cl`（ローカル変数を static に置く）と `--codesize 500` で、ローカル変数のスタックの操作と、ライブラリの呼び出しの一部はなくなりますが、引数は C のスタックのままなので、(3) と (4) の大部分は残ります。

### 11.4 まとめ

| 版 | 1 フレーム | AX65 `-O2` との比 | コード |
|---|---|---|---|
| cc65 `O0` | 5046 | 6.8 倍 | 1839 |
| cc65 `O` | 2807 | 3.8 倍 | 1066 |
| cc65 `Oirs` | 2507 | 3.4 倍 | 1048 |
| cc65 `Oirs_Cl` | 2263 | 3.1 倍 | 940 |
| cc65 `Oirs_Cl_cs` | 2106 | 2.85 倍 | 931 |
| **AX65 `-O2`** | **740** | **1** | **386** |

同じゲームを、cc65 で速くなる書き方で書き、cc65 の最も速い設定でコンパイルしても、AX65 の既定の `-O2` の 2.85 倍の時間と、2.4 倍のコードになりました。差の大部分は、C の言語の決まり（引数を C のスタックで渡す、配列の要素の書き換えをポインタで行う、ループの番号を毎回比べ直す）と、cc65 の最適化の範囲から来ています。AX65 は、再帰を禁止してローカル変数と引数を固定アドレスやレジスタに置けるようにし、プログラム全体を解析することで、この差を埋めています。

cc65 でも、関数の引数をグローバル変数で渡す、表示の処理をアセンブリで書く、といった手での工夫をすれば差は縮まりますが、この比較には含めていません。
