# meteor.ax65 で使っている仕様の解説

このドキュメントは、サンプル `meteor.ax65` の上から順に、そこで使われている ax65 の仕様をすべて説明するものです。各項目の末尾の（）は、仕様書 第2版 `ax65_spec_v2.md` の該当箇所です。

構文は、仕様書 第2版で統一した Rust 寄りの文法です。サンプルを書いた時点で「仮」だった仕様は、その後すべて決まりました（21節）。

---

## 1. ファイルの先頭：コメントとターゲットの前提

```
// meteor.ax65 — ax65 サンプル：隕石よけゲーム
```

- `//` は行末までのコメントです。複数行のコメントには `/* */` も使えます。アセンブリの中だけは `;` を使います（議題13で提案）。
- このプログラムは v2（画面なし）と v3（画面あり）の両方で動くように書いてあります。どちらで動かすかはソースではなく、コンパイル時に `ax65 build -t v2` のように選びます（2章）。

## 2. モジュールの読み込み

```
use console::{putc, poll};
use screen;
use core::us;
```

| 書き方 | 意味 |
|---|---|
| `use console::{putc, poll};` | `console` インターフェースの `putc` と `poll` を、モジュール名なしで使えるようにする |
| `use screen;` | `screen` インターフェースを読み込む。使うときは `screen::clear()` のように `::` で書く |
| `use core::us;` | 標準ライブラリ `core` の `us()` を読み込む（このサンプルでは読み込みだけで、実際には使っていない） |

- `console` と `screen` は「インターフェース」です。形（関数の名前と型）だけが決まっていて、中身はターゲット定義の `bind` で選ばれた実装になります。v2 では `console` に ACIA の実装が、v3 では画面の実装が bind されている想定です（11.4）。
- `screen` が bind されていない v2 でも、`use screen;` 自体はエラーになりません。`comptime if target.has(screen)` の外で使った場合だけエラーです（11.4）。
- モジュールのパスは `::`、フィールドとメソッドは `.` で区別します（議題13で提案）。
- `use core::us;` のように、読み込んだのに使っていない名前には「使っていない import」の警告が出ます（11.6）。サンプルでは、この警告が出る例として残しています。

## 3. 定数

```
const FIELD_W: u8 = 20;
const FIELD_H: u8 = 16;
const PLAYER_Y: u8 = FIELD_H - 1;
```

- `const 名前: 型 = 値;` で定数を宣言します。名前の後ろに型を書く順序です（議題13で提案）。
- 定数の値は必ずコンパイル時に計算されます。`FIELD_H - 1` のように、別の定数を使った式も書けます（10.1）。
- 定数はメモリを使いません。使った場所に値が直接埋め込まれます（`cmp #16` など）。
- 名前を `UPPER_CASE` で書くのは、Rust と同じ名前の慣習です。守らなくてもエラーにはならず、警告だけです（議題13で提案）。

```
comptime assert(target.clock / 60 <= 65535, "…");
const T1_PERIOD: u16 = (target.clock / 60 - 2) as u16;
```

- `target.clock` は、ターゲット定義に書いたクロック周波数です（10.6）。v2 は 1MHz なので、`T1_PERIOD` は 16664（$4118）になります。
- `target.clock / 60` の計算は、コンパイル時専用の大きさに制限のない整数（`int`）で行われます。
- `comptime assert` は、条件が成り立たなければコンパイルエラーにします（10.6、議題13で `static_assert` から改名を提案）。クロックを 4MHz 以上にしたターゲットでは、周期が 16 ビットに収まらないことを、ここで知らせます。
- `as u16` は明示的な型の変換です。コンパイル時の値を実行時の型に変換するとき、範囲を超えたらエラーになります（一周させない）（10.3）。

```
const TITLE: str = p"METEOR DODGE";
```

- `p"..."` は長さ付きの文字列で、型は `str` です。メモリ上では先頭に長さ（12）、続けて文字が並びます（3.7）。
- 接頭辞を付けない `"..."` は、長さも終端もない `[char; N]` になるので、`str` の変数には入れられません（3.7）。
- `@変換表` を付けていないので、文字コードは ASCII です（3.6）。

## 4. 型の宣言

```
range Mid = 0..8;
```

- `range` は範囲型の宣言です。`Mid` は 0〜7 の値だけを取る新しい型で、中身は `u8` です（3.3、議題13でキーワードを `type` から `range` に変更を提案）。
- `..` は Rust と同じく、終わりの値（8）を含みません。終わりを含めたいときは `0..=7` と書きます（議題13で統一を提案）。
- 同じ範囲で別の `range` を宣言しても、別の型になります（名前による区別）（3.3）。

```
enum Key { Left, Right, Quit }
```

- 列挙型です。値は先頭から 0、1、2 と割り当てられ、中身は `u8` です（3.4）。
- `match` で使うと、すべての値を書いたかどうかが検査されます（6.4）。
- 型の名前と値の名前は `CamelCase` です（議題13で提案した名前の慣習）。

```
flags Ifr { Ca2, Ca1, Shift, Cb2, Cb1, T2, T1, Any }
```

- ビットフラグ型です。先頭からビット 0、1、2…に名前が付きます。`T1` はビット 6 です（3.5）。
- VIA の割り込みフラグのレジスタは、各ビットが別々の意味を持つので、この型で読むと `IFR.contains(Ifr::T1)` のように名前で調べられます。

```
struct Meteor { x: u8, y: u8, wait: u8 }
```

- 構造体です。フィールドは `名前: 型` をカンマで区切って並べます（議題13で Rust に合わせることを提案）。
- 構造体の配列は、メモリ上ではフィールドごとの配列になります（3.9、次の6節）。

## 5. コンパイル時の表の生成

```
comptime fn spawn_x(i: int) -> u8 {
    ((i * 7 + 3) % 20) as u8
}

const SPAWN_X: u8[Mid] = [for i in 0..8 => spawn_x(i)];
```

- `comptime fn` は、コンパイル時にしか呼べない関数です。実行時のコードから呼ぶとエラーです（10.3）。
- 中では、コンパイル時専用の型 `int` が使えます。実行時なら `%` は 2 のべき乗の定数にしか使えませんが、コンパイル時の `int` の計算では自由に使えます（3.12、10.3）。
- 関数の最後の式（`;` のない式）が戻り値になります。`return` を省略できます（議題13で Rust に合わせることを提案）。
- `[for i in 0..8 => 式]` は、添字から各要素を計算して配列を作る書き方です（10.4）。結果は 3、10、17、4、11、18、5、12 で、プログラムにはこの8バイトの表が置かれます。実行時の計算はありません。
- `u8[Mid]` は「`Mid` を添字にする `u8` の配列」です。Rust の書き方 `[u8; Mid]` と同じ意味で、どちらでも書けます（議題13でご要望により両方を許可）。

## 6. 変数

```
static mut METEORS: Meteor[Mid] = [Meteor { x: 0, y: 0, wait: 0 }; Mid];
static mut PLAYER_X: u8 = FIELD_W / 2;
static mut SCORE: bcd16 = 0;
static mut SEED: u8 = $5A;
```

- `static mut` は、書き換えられるグローバル変数です（議題13で Rust に合わせることを提案）。`mut` を付けない `static` は書き換えられません。
- グローバル変数には初期値が必須です。初期値は起動時に毎回設定し直されるので、RAM に読み込んだプログラムを2回実行しても、前回の値は残りません（4.4）。
- `[値; Mid]` は、同じ値を `Mid` の個数（8個）並べた配列の初期値です。
- `METEORS` はフィールドごとの配列になり、メモリ上では x が8個、y が8個、wait が8個と並びます。`METEORS[m].y` は「y の配列の m 番目」で、番号をそのまま X レジスタに入れて1命令で読めます（3.9）。
- `bcd16` は 10進4桁の BCD 型です。`$0072` が「72点」を表します（3.12）。
- `$5A` は16進数です。`0x5A` と書くこともできます（議題13でご要望により両方を許可）。
- 変数は、最適化オプションを付けなければ、ゼロページではなく通常の RAM に置かれます（4.2）。

```
shared(irq) TICKS: u16 = 0;
```

- `shared` は、割り込み処理とメインで共有する変数です。`(irq)` は「書き込むのは割り込み処理だけ」という指定で、メインから書き込むとコンパイルエラーになります（8.4、議題13で `shared<irq>` から書き方の変更を提案）。
- `shared` 変数を2命令以上で読み書きするときは、`atomic` の中でなければなりません。`u16` の読み込みは2命令なので、メインからは `atomic` の中でしか読めません（8.4）。

## 7. I/O

```
io        T1C_L: u8  @ $6004;
io(out)   T1C_H: u8  @ $6005;
io(out)   ACR:   u8  @ $600B;
io(in)    IFR:   Ifr @ $600D;
io(out)   IER:   u8  @ $600E;
```

- `io` は、決まったアドレスにある I/O レジスタの宣言です。`@ $6004` がアドレスです（7章）。
- `(in)` は読み込み専用、`(out)` は書き込み専用で、逆の使い方はコンパイルエラーです。何も付けなければ読み書き両方です（7章、議題13で `io in` から書き方の変更を提案）。
- I/O 変数の型は1バイトに限られます。ビットフラグ型（`Ifr`）も使えます（3.5、7章）。
- I/O の読み書きは、ソースに書いた回数と順序のとおりに行われます。省略も並べ替えもされません（7章）。
- I/O 変数には `pub` を付けられません。このモジュールの外からは、VIA のレジスタに触れません（11.5）。
- 同じアドレスを別のモジュールが宣言していたら、コンパイルエラーになります（11.5）。
- `rmw` を付けていないので、`inc` などの読み・変更・書き込み命令は、これらのレジスタには使われません（7章）。
- アドレスは `io` 区画（ターゲット定義の `region io`）の中でなければなりません（2章）。

## 8. init ブロック

```
init {
    ACR   = 0b0100_0000;
    T1C_L = (T1_PERIOD & $FF) as u8;
    T1C_H = (T1_PERIOD >> 8) as u8;
    IER   = 0b1100_0000;
}
```

- `init` は、起動時に `main` の前に1回だけ実行されるブロックです。コンパイラは呼び出しではなく、起動処理の中に中身を直接並べます（11.6）。
- `init` の実行中は、割り込みは止まったままです（11.6）。
- `0b0100_0000` は2進数です。`_` で桁を区切れます（議題13で提案）。
- VIA のタイマーは上位バイトを書いた瞬間に動き出すので、下位を先に書く必要があります。I/O の読み書きの順序はソースのとおりに守られるので、書いた順に実行されます（7章）。
- `(T1_PERIOD & $FF) as u8` は定数の式なので、コンパイル時に $18 に計算されます。`>>` の右側は定数でなければなりません（3.12）。

## 9. 割り込み処理

```
#[interrupt(irq)]
fn on_irq() {
    if IFR.contains(Ifr::T1) {
        let _ = T1C_L;
        TICKS += 1;
    }
}
```

- `#[interrupt(irq)]` は、この関数を IRQ の割り込み処理にする属性です。レジスタの退避と復帰、`rti`、割り込みベクタへの登録は、コンパイラが作ります（8.1、議題13で属性の形に変更を提案）。
- 退避するのは、割り込み処理の中で実際に使うレジスタだけです（8.1）。
- 割り込みベクタの置き方は、ターゲット定義の `irq = indirect($0280)` などで決まります（2章）。
- `IFR.contains(Ifr::T1)` は、ビットフラグ型のビットを調べる書き方です（Rust の bitflags と同じ名前）。ビット 6 なので、コンパイラは `bit` 命令を使い、結果を V フラグで判定できます（3.5）。
- `let _ = T1C_L;` は、値を使わずに読むだけの書き方です。VIA のタイマー1 は、下位バイトを読むと割り込みフラグが消えます。I/O の読み込みは省略されないので、この1行は必ず読み込み命令になります（7章）。
- 割り込み処理の中は、もともと割り込みが止まっているので、`TICKS += 1`（u16、2命令以上）を `atomic` なしで書いています（8.5）。
- 割り込み処理から呼べるのは、メインから呼ばれない関数だけです。割り込み処理の中で割り込みを許可することはできません（8.3）。
- 割り込み処理の中のループには回数の上限が必要です。このサンプルの割り込み処理にはループがありません（6.2）。

## 10. atomic と、割り込み待ち

```
fn ticks() -> u16 {
    atomic { TICKS }
}
```

- `atomic` は、中身を実行する間だけ割り込みを止めるブロックです。`php` と `sei` で始まり、`plp` で終わります（8.5）。
- `atomic { TICKS }` のように、ブロックの最後の式を値として返せる形にしています（8.6、Rust のブロック式と同じ考え方）。
- 戻り値の `u16` は、A（下位）と X（上位）で返されます（5.3）。

```
fn wait_frame(last: u16) -> u16 {
    loop {
        let now = ticks();
        if now != last { return now; }
        comptime if target.cpu == Cpu::W65C02S {
            wait_interrupt();
        }
    }
}
```

- 引数は `名前: 型` で書きます。`u16` の引数は A（下位）と X（上位）で渡されます（5.2）。
- `let` は、書き換えないローカル変数の宣言です。型は右辺から決まります（議題13で提案）。ローカル変数は、他の関数と重ねて固定アドレスに置かれます（4.3）。
- `loop` は無限ループで、`return` で関数ごと抜けます（6.2）。メインの側のループなので、回数の上限は不要です。
- `if` の条件 `now != last` は `bool` です。数値をそのまま条件には書けません（6.1）。
- `comptime if target.cpu == Cpu::W65C02S` は条件コンパイルです。v2 の CPU は W65C02S なので、中身がプログラムに含まれます（10.7）。
- `wait_interrupt()` は W65C02S の `wai` 命令で、割り込みが来るまで CPU を止めます。他の CPU のターゲットではコンパイルエラーになるので、`comptime if` で囲んでいます（9章）。

## 11. インラインアセンブリの関数

```
asm fn rand_step(r: u8) -> u8 {
    asl a                   ; …
    bcc done                ; …
    eor #$1D                ; …
done:                       ; …
    rts                     ; …
}
```

- `asm fn` は、関数全体をアセンブリで書く書き方です。引数と戻り値は標準の規則に従い、`r` は A で届き、戻り値は A で返します（12.2）。
- コンパイラはこのアセンブリを解析し、壊すのは A とフラグだけで、スタックの使用量は戻り番地の2バイトだけ、と自分で求めます。プログラマが宣言する必要はありません（12.1）。
- ラベル `done` は、このブロックの中だけで有効です（12.2）。
- アセンブリの中のコメントは `;` です。

```
fn rand() -> u8 {
    SEED = rand_step(SEED);
    SEED
}
```

- 最後の行の `SEED` は、`return SEED;` の省略形です。

## 12. Option と ? 演算子

```
fn read_key() -> Option<Key> {
    let c = poll()?;
    match c {
        'A' | 'a' => Some(Key::Left),
        'D' | 'd' => Some(Key::Right),
        'Q' | 'q' => Some(Key::Quit),
        _         => None,
    }
}
```

- `Option<Key>` は、「Key の値があるか、ないか」を表す型です。値があるときは `Some(値)`、ないときは `None` です（3.11、議題13で Rust の書き方に変更を提案）。
- 戻り値としては、有無をキャリーで、値を A で返します。`Option` を使っても、値を包む処理は発生しません（3.11、5.3）。
- `poll()?` の `?` は、`poll()` が `None` を返したら、`read_key` 自身も `None` を返して抜ける、という演算子です。6502 では「キャリーが 0 なら抜ける」分岐1つになります（議題13で提案）。
- `match` は場合分けです。`|` で複数の値をまとめられます。`char` は値の数が多いので、`_`（それ以外）が必須です（6.4）。
- 比べる値が飛び飛び（'A'、'a'、'D'…）なので、コンパイラは比較を並べる方式を選びます。どちらの方式を選んだかはレポートに出ます（6.4）。
- `Key::Left` は、列挙型の値を `型名::値` で書く書き方です（議題13で提案）。

## 13. match の網羅性と saturating_sub

```
fn move_player(k: Key) {
    match k {
        Key::Left  => { PLAYER_X = PLAYER_X.saturating_sub(1); }
        Key::Right => { if PLAYER_X < FIELD_W - 1 { PLAYER_X += 1; } }
        Key::Quit  => {}
    }
}
```

- `Key` のすべての値を書いているので、`_` は不要です。後で `Key` に値を追加すると、この `match` がエラーになり、対応漏れに気づけます（6.4）。
- `saturating_sub(1)` は、0 より小さくならずに 0 で止まる引き算です（3.12、議題13で Rust と同じ名前に変更を提案）。
- `PLAYER_X += 1` は、普通の足し算なので、255 を超えると一周して 0 に戻ります。ここでは直前の `if` で 19 未満であることを確かめているので、一周は起きません（3.1）。
- `Key::Quit => {}` は、何もしない場合の書き方です。

## 14. 範囲型の添字とレジスタの指定

```
fn clear_meteors() {
    #[reg(x)]
    for m in Mid {
        METEORS[m].y = 0;
        METEORS[m].wait = m as u8;
    }
}
```

- `for m in Mid` は、範囲型のすべての値（0〜7）を順に回すループです。`m` の型は `Mid` です（6.2）。
- `m` は `Mid` 型なので、`METEORS[m]` の範囲の検査は不要です。範囲外になりえないことが、型で保証されているからです（3.3）。
- `#[reg(x)]` は、ループの変数を X レジスタに置く指定です。ループの中で X を壊す関数を呼んでいないので、指定どおりに置けます。置けない場合はコンパイルエラーです（6.3、議題13で属性の形に変更を提案）。
- `m as u8` は、範囲型から `u8` への変換です。範囲型の値に演算をしたり、別の型の変数に入れたりするときは、`as` で明示します（3.3）。

```
fn respawn(m: Mid) {
    let r = rand();
    METEORS[m].x = SPAWN_X[Mid::wrap(r)];
    METEORS[m].y = 0;
    METEORS[m].wait = r & 3;
}
```

- 引数の型が `Mid` なので、呼び出し元は範囲内の値しか渡せません。関数の中では検査が不要です（3.3）。
- `Mid::wrap(r)` は、`u8` の下位ビットだけを取って `Mid` に変換する関数です。`Mid` の範囲が 2 のべき乗（8個）なので使えます。命令は `and #7` の1つです（3.3、議題13で `eid.wrap` から `Mid::wrap` に変更を提案）。
- `r & 3` はビットの AND です（3.12）。

## 15. continue、BCD の足し算、bool の戻り値

```
fn update_meteors() -> bool {
    let mut hit = false;
    for m in Mid {
        if METEORS[m].wait > 0 {
            METEORS[m].wait -= 1;
            continue;
        }
        …
        if METEORS[m].y == FIELD_H {
            respawn(m);
            SCORE += 1;
        } else if METEORS[m].y == PLAYER_Y && METEORS[m].x == PLAYER_X {
            hit = true;
        }
    }
    hit
}
```

- `let mut` は、書き換えるローカル変数の宣言です。`mut` のない `let` に再代入するとエラーです（議題13で提案）。
- `continue` は、ループの次の回へ進みます（6.2）。
- `SCORE += 1` は BCD の足し算です。コンパイラが前後に `sed` と `cld` を入れます。`1` は BCD の型に合わせて $01 として扱われます（3.12）。
- `&&` は短絡評価で、左側が偽なら右側は評価されません（6.1）。
- 戻り値の `bool` は、キャリーで返されます（5.3）。
- ループの中で `respawn`（X と Y を壊す）を呼ぶので、コンパイラは `m` をレジスタではなくメモリに置きます。`#[reg(x)]` を付けると、ここではコンパイルエラーになります（6.3）。

## 16. 文字列の出力と digits()

```
fn print(s: str) {
    for c in s { putc(c); }
}
```

- `str` の引数は、文字列を指すポインタとして渡されます。ポインタはゼロページに置かれます（3.10、5.2）。
- `for c in s` は、長さ付きの文字列の各文字を回すループです。長さは先頭の1バイトから読みます（3.7）。

```
fn print_score() {
    for d in SCORE.digits() {
        putc(('0' as u8 + d) as char);
    }
}
```

- `SCORE.digits()` は、BCD の値を上の桁から1桁ずつ（0〜9）取り出します（3.12）。
- `'0' as u8 + d` は、文字 '0' のコード（$30）に桁の値を足して、数字の文字コードにする計算です。`char` と `u8` は別の型なので、`as` で変換します（3.6）。

## 17. 条件コンパイルと、画面用の文字

```
fn draw() {
    comptime if target.has(screen) {
        screen::clear();
        for x in (0..FIELD_W).rev() {
            screen::put(x, FIELD_H, '-'@screen);
        }
        …
    } else {
        putc('\r');
        print(p"SCORE ");
        print_score();
    }
}
```

- `target.has(screen)` は、`screen` インターフェースが bind されているかどうかです。v3 では真、v2 では偽になります（10.7、11.4）。
- 選ばれなかった側のコードはプログラムに含まれず、構文だけが検査されます。両方の側を型まで検査するには、`ax65 check --all-targets` を使います（10.7）。
- `(0..FIELD_W).rev()` は逆順のループです。19 から 0 へ回ります。`dex` と `bpl` で回せるので、少し速くなります（6.2、議題13で `rev` の書き方の変更を提案）。
- `'-'@screen` は、画面の変換表で変換した文字です。型は `char@screen` で、ASCII の `char` とは別の型です（3.6）。
- `'\r'` は復帰（$0D）の文字です。
- `p"SCORE "` のように、文字列の定数をその場で書くこともできます。

## 18. main

```
fn main() {
    print(TITLE);
    putc('\r');

    clear_meteors();
    for m in Mid { respawn(m); }

    irq_enable();

    let mut last = ticks();
    'game: loop {
        last = wait_frame(last);
        if let Some(k) = read_key() {
            if k == Key::Quit { break 'game; }
            move_player(k);
        }
        if update_meteors() { break 'game; }
        draw();
    }

    print(p"\rGAME OVER  SCORE ");
    print_score();
    putc('\r');
}
```

- `irq_enable()` は、割り込みを許可する組み込みの関数で、`cli` 1命令になります。`init` が終わった時点では割り込みはまだ止まっていて、`main` が明示的に許可するまで入りません（8.4、11.6）。
- `'game: loop` は、名前を付けたループです。`break 'game;` で、内側の `if` の中から直接このループを抜けられます（6.2、議題13で Rust と同じ書き方を提案）。
- `if let Some(k) = read_key()` は、値があれば `k` として受け取り、中身を実行します（3.11）。
- `main` が最後まで実行されると、ターゲット定義の `exit` に従って、モニタへ戻ります（2章）。

## 19. 起動から終了までの流れ

コンパイラが作る起動処理は、次の順序で実行されます（11.6）。

1. 割り込みを止め、10進モードを解除し、スタックポインタを設定する
2. グローバル変数に初期値を設定する（METEORS、PLAYER_X、SCORE、SEED、TICKS）
3. 割り込みベクタ（RAM 上の $0280）に `on_irq` のアドレスを書く
4. `init` ブロックの中身を実行する（VIA のタイマーの設定）
5. `main` を呼ぶ
6. `main` が終わったら、`exit` に従ってモニタへ戻る

## 20. コンパイラが検査すること（このサンプルの場合）

このサンプルでは、次のことがコンパイル時に確かめられます。

| 検査 | このサンプルでの例 |
|---|---|
| 再帰がない | すべての関数の呼び出し関係に輪がない |
| スタックの予算 | 最も深い経路は main → update_meteors → respawn → rand → rand_step（戻り番地 2 バイト×5 段）に、割り込みの分を足したもの |
| 範囲外の添字がない | METEORS と SPAWN_X の添字は、すべて `Mid` 型 |
| 代入前の読み込みがない | すべてのローカル変数は、宣言と同時に値が入っている |
| 割り込みとの共有 | TICKS は割り込み処理だけが書き、メインは `atomic` の中で読む |
| I/O の向き | `io(in)` の IFR には書き込んでいない。`io(out)` のレジスタは読んでいない |
| match の網羅性 | `move_player` の `match` は Key のすべての値を書いている |
| Option の確認 | `read_key()` と `poll()` の結果は、`if let` と `?` で有無を確かめてから使っている |
| ターゲットにない機能 | `wait_interrupt()` は `comptime if target.cpu == Cpu::W65C02S` の中でだけ使っている |
| bind の確認 | `screen` は `comptime if target.has(screen)` の中でだけ使っている |
| コンパイル時の検査 | `comptime assert` で、タイマーの周期が 16 ビットに収まることを確かめている |

## 21. サンプルを書いた時点で仮だった仕様

サンプルを書いた時点では次の5点が決まっていませんでしたが、その後、仕様書 第1.1版ですべて決まりました。サンプルの書き方は、決まった仕様と同じです。

| 項目 | 決まった仕様 |
|---|---|
| 割り込みの許可 | 組み込み関数 `irq_enable()`・`irq_disable()`（8.4） |
| 値を返す atomic | `atomic { TICKS }` で、ブロックの最後の式を値として返せる（8.6） |
| 読むだけの I/O | `let _ = T1C_L;`。`bit` 命令で読む（7章） |
| BCD の定数 | 10進の定数をそのまま BCD に変換する。16進の定数はエラー（3.12） |
| 割り込み処理の中の shared | 割り込み処理の中では `atomic` を省略できる（NMI と共有する変数を除く）（8.5） |
