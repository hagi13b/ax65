## 1. はじめに

<a id="s1-1"></a>
### 1.1 目的

自作の 6502 マシン専用のプログラミング言語です。KIM-1 級（RAM 1KB 前後）から Apple I 級、Apple II 級（RAM 48KB 程度）へと拡張していくマシンを対象とします。現在の実機は、6502-CPLD ボードと HEXPAD（モニタ HEXMON）による構成です（ターゲット v2。[16.7節](#s16-7)）。既存のマシンとの互換性は求めません。汎用性は目標とせず、6502 で効率よく、安全に動くプログラムを書けることだけを目標とします。

<a id="s1-2"></a>
### 1.2 設計方針

1. **ハードウェアの制約を、言語の制約で抑える。** 6502 で高くつく操作は、書けないようにするか、高くつくことが見える形でしか書けないようにします。
2. **検査はすべてコンパイル時に行う。** 実行時の検査のコストは、プログラマが明示した場所でしか払いません（Rust の方針と同じ）。
3. **コンパイラはプログラム全体を一度に解析する。** プログラムは 64KB 以内、ヒープなし、スレッドなし（並行して動くのは割り込みだけ）という前提により、呼び出しグラフ、スタック使用量、レジスタの使用状況などをすべて静的に求めます。
4. **最適化はプログラムの意味を変えない。** 最適化の段階によって大きさと速さは変わりますが、意味は変わりません。資源とタイミングの検査は、選んだ段階で生成したコードに対して行います。既定は `-O2` です（[19章](#s19)）。
5. **コンパイラが行った判断は、レポートで見えるようにする。** 変数の配置、レジスタの割り当て、`match` の実装方法、スタック使用量などを出力します（[18.4節](#s18-4)）。
6. **検査できない部分は、1か所に閉じ込める。** `extern fn`、`unchecked()`、`unsafe asm` など、プログラマが正しさに責任を持つ部分は、名前で検索できる形にし、レポートの unsafe の項目に一覧で出します（[18.4節](#s18-4)。Rust の `unsafe` に相当）。

コンパイルが通ったプログラムは、スタックがあふれず、範囲外のアクセスをせず、割り込みとのデータ競合を起こしません。

次の部分は、この保証の対象外です。正しさはプログラマの責任で、すべてレポートの unsafe の項目に一覧で出ます（[18.4節](#s18-4)）。

| 保証の対象外 | 節 |
|---|---|
| ポインタの指す先の読み書き（`p[i]`、`p.hp`、`p.add(n)` で作ったポインタ） | [3.10](#s3-10) |
| `unchecked()` | [3.4](#s3-4) |
| `extern fn` の宣言 | [7.6](#s7-6) |
| `unsafe asm` の宣言 | [14.4](#s14-4) |
| `smc`（自己書き換えコード） | [14.5](#s14-5) |

```
range Eid = 0..16;
static ENEMIES: [Enemy; Eid] = [ENEMY0; Eid];

fn hit(n: u8) {
    ENEMIES[n].hp = 0;                  // エラー：n は u8 で、0〜15 に収まる保証がない
    if let Some(e) = Eid::check(n) {    // 範囲を確かめれば使える
        ENEMIES[e].hp = 0;
    }
}

fn fact(n: u8) -> u8 { n * fact(n - 1) }   // エラー：再帰呼び出し（スタックの予算が計算できない）
```

関連 Q&A：[A-1](#qa-a1)、[A-2](#qa-a2)、[M-1](#qa-m1)、[M-7](#qa-m7)

<a id="s1-3"></a>
### 1.3 対象 CPU

| CPU | 扱い |
|---|---|
| 65C02（W65C02S を含む） | 基本の対象。65C02 の追加命令を前提にしたコードを生成する |
| NMOS 6502 | ターゲット定義で選択できる。コンパイラが命令を選び直し、NMOS 固有の落とし穴を避ける（[15.6節](#s15-6)） |

言語の意味は CPU によって変わりません。CPU によって変わるのは、生成されるコードの速さと大きさだけです。

<a id="s1-4"></a>
### 1.4 処理系の形態

コンパイラ `ax65` は、PC 上で動くクロスコンパイラです。プロジェクトのソースを全部読み込み、6502 の機械語と、リスティング、レポートなどを出力します（[17章](#s17)）。構文は、1〜2 文字先を見るだけで解析できる形に限ります。

<a id="s1-5"></a>
### 1.5 本書の表記

- コード例は AX65 のソースです。`//` の後ろはコメントです。
- アセンブリの例は、行の `;` の後ろに、その命令の説明を書きます。
- 「エラー」はコンパイルエラー、「警告」は警告を指します。番号付きの一覧は [18章](#s18) にあります。
- 各節の末尾の「関連 Q&A」は、その仕様を決めたときの議論（[付録B](#appB)）へのリンクです。

<a id="s1-6"></a>
### 1.6 Rust との違い

文法は Rust に寄せていますが、次の点が違います。

| 項目 | AX65 | 関連 Q&A |
|---|---|---|
| `char` | 1 バイト（Rust は 4 バイトの Unicode） | ― |
| 整数のあふれ | 常に一周して戻る（Rust はデバッグ時にパニック） | [B-2](#qa-b2) |
| ジェネリクス、トレイト、クロージャ、マクロ | なし | [K-3](#qa-k3) |
| 参照とライフタイム | なし。ポインタ `ptr<T>` と、アドレスの規則（[4.9節](#s4-9)）で代える | [A-2](#qa-a2) |
| `static` | 常に書き換えられるグローバル変数。`mut` も `unsafe` も書かない | [K-14](#qa-k14)、[K-16](#qa-k16) |
| 読み取り専用のデータ | すべて `const`（書き換えない `static` はない） | [K-16](#qa-k16) |
| `let`、引数 | 常に書き換えられる。`mut` は書かない | [K-15](#qa-k15) |
| モジュール | `use` がファイルの読み込みを兼ねる（`mod` の宣言はない） | [H-2](#qa-h2) |
| 独自の機能 | `range`、`flags`、`io`、`shared`、`atomic`、`cycles`、`comptime`、`interface` など | ― |

## 2. 字句構造

<a id="s2-1"></a>
### 2.1 ソースファイル

```
// src/meteor.ax65（UTF-8）
use console::{putc, poll};              // ; で文を区切る
const TITLE: str = p"METEOR DODGE";     // ASCII 以外の文字は、コメントと、変換表を付けた文字・文字列の中だけ
const KANA: str@kana = p"ﾒﾃｵ"@kana;     // 変換表 kana がターゲット定義にあれば、文字列にも書ける
```

- ソースファイルの拡張子は `.ax65`、文字コードは UTF-8 です。
- ASCII 以外の文字は、コメントと、変換表を付けた文字・文字列（[3.3節](#s3-3)）と、`comptime assert` の説明の文字列（[13.5節](#s13-5)）の中にだけ書けます。
- 文の区切りの `;` は必須です。改行に意味はありません。

関連 Q&A：[N-8](#qa-n8)

### 2.2 コメント

```
// 行末までのコメント
/* 複数行の
   コメント */

    lda #0                      ; インラインアセンブリの中のコメントは ;

```

<a id="s2-3"></a>
### 2.3 識別子と名前の慣習

```
struct Enemy { x: u8, hp: u8 }          // 型は CamelCase
const MAX_ENEMIES: u8 = 16;             // 定数は UPPER_CASE
static SCORE: bcd16 = 0;            // static も UPPER_CASE
fn update_enemies() {                   // 関数は snake_case
    let enemy_count = 0;                // ローカル変数も snake_case
}
fn UpdateAll() { }                      // 警告（naming）：関数は snake_case
```

- 識別子は、ASCII の英字か `_` で始まり、英数字と `_` が続きます。大文字と小文字は区別します。
- `_` だけの名前は、値を捨てる場所に使います（`let _ = T2C_L;`）。
- 名前の慣習は Rust と同じです。守らない場合は警告で（`naming`）、プロジェクトファイルで止められます（[17.2節](#s17-2)）。

| 対象 | 慣習 | 例 |
|---|---|---|
| 型、列挙型の値、ビットフラグの名前 | `CamelCase` | `Enemy`、`Dir::Up`、`Joy::Fire` |
| 関数、ローカル変数、モジュール、インターフェース | `snake_case` | `update_meteors`、`console` |
| 定数、`static`、`shared`、I/O 変数 | `UPPER_CASE` | `FIELD_W`、`SCORE`、`T2C_L` |

- 言語に組み込みの型（`u8`、`bool`、`char`、`str`、`bcd16`、`ptr<T>`、`strbuf<N>`）は小文字、ライブラリの型（`Option<T>`）は大文字で始まります。

関連 Q&A：[K-5](#qa-k5)、[K-7](#qa-k7)

<a id="s2-4"></a>
### 2.4 キーワード

| 分類 | キーワード |
|---|---|
| Rust と同じもの | `as` `break` `const` `continue` `else` `enum` `extern` `false` `fn` `for` `if` `impl` `in` `let` `loop` `match` `pub` `return` `static` `struct` `true` `type` `unsafe` `use` `while` |
| AX65 の宣言 | `range` `flags` `fnset` `interface` `io` `shared` `init` `comptime` |
| AX65 のブロック | `asm` `atomic` `cycles` `io_span` `max_cycles` |
| ターゲット定義の中だけ | `target` `extends` `region` `reserve` `place` `encoding` `bind` |
| 予約（使えない） | `mut` |

```
let range = 3;                          // エラー：range はキーワード
let delay = 3;                          // 組み込みの名前は、ローカル変数で隠せる（警告なし）
```

- `const` は、コンパイル時に値が決まる・コンパイル時に計算できることを表します（`const X: T = …`、`const fn`。[4.2節](#s4-2)、[7.2節](#s7-2)）。`comptime` は、コンパイル時だけに行うことを表します（`comptime fn`、`comptime if`・`comptime match`・`comptime assert`。[13章](#s13)）。
- `None`、`Some`、`Option`、`delay`、`irq_enable` などは、キーワードではなく組み込みの名前です（[20.1節](#s20-1)）。

関連 Q&A：[K-17](#qa-k17)、[M-10](#qa-m10)

<a id="s2-5"></a>
### 2.5 整数リテラル

```
let a = 255;                            // 10進（型を書かなければ u8）
let b: u32 = 1_000_000;                 // _ で桁を区切れる
let c = $FF;                            // 16進（6502 の慣習）
let d = 0xFF;                           // 16進（C、Rust の慣習）
let e = 0b1010_0101;                    // 2進
let f = 1_000;                          // エラー：型を書かないので u8 になり、1000 は収まらない
```

- 16進は `$FF` と `0xFF` のどちらでも書けます。`ax65 fmt` で、プロジェクトごとに一方へそろえられます（[17.2節](#s17-2)）。コンパイラの出力（リスティング、レポート、メッセージ）は `$` で表示します。
- 2進は `0b` だけです。`%1010` の形は使えません。
- リテラルの型は、使われた場所の型で決まります。値がその型の範囲に収まらなければエラーです。
- 型を書かない `let` の初期値が整数リテラルだけの場合、型は `u8` です。`u8` に収まらなければエラーで、型を書く必要があります（[4.4節](#s4-4)）。
- BCD の型のところに書いた 10進のリテラルは、10進の値として BCD に変換されます（[5.5節](#s5-5)）。

関連 Q&A：[K-2](#qa-k2)、[M-13](#qa-m13)

<a id="s2-6"></a>
### 2.6 文字リテラル

```
let a = 'A';                            // ASCII の 'A'（$41）
let cr = '\r';                          // 復帰（$0D）
let x = '\x7F';                         // 16進で指定
let s = 'A'@screen;                     // 画面の変換表で変換した 'A'（型は char@screen）
```

| エスケープ | 値 |
|---|---|
| `\n` | $0A |
| `\r` | $0D |
| `\t` | $09 |
| `\0` | $00 |
| `\\` | `\` |
| `\'`、`\"` | `'`、`"` |
| `\xNN` | 16進の NN |

<a id="s2-7"></a>
### 2.7 文字列リテラル

```
let raw = "HI";                         // [char; 2]：長さも終端もない
const TITLE: str = p"HELLO";            // 長さ付き（先頭に長さ）
const MSG: zstr = z"READY";             // 0 終端
const ROMSTR: histr = hi"OK";           // 最上位ビット終端
const S: str@screen = p"SCORE"@screen;  // 変換表を付ける
```

| 書き方 | 中身（"HI" の場合） | 型 |
|---|---|---|
| `"HI"` | `48 49` | `[char; 2]` |
| `p"HI"` | `02 48 49` | `str` |
| `z"HI"` | `48 49 00` | `zstr` |
| `hi"HI"` | `48 C9` | `histr` |

接頭辞の考え方は Rust の `b"..."` と同じです。型の詳細は [3.9節](#s3-9) にあります。

<a id="s2-8"></a>
### 2.8 演算子と区切り記号

| 記号 | 意味 |
|---|---|
| `+ - * / %` | 算術（`*` `/` `%` には制限がある。[5.6節](#s5-6)） |
| `& \| ^ ! << >>` | ビット演算とシフト |
| `== != < > <= >=` | 比較 |
| `&& \|\| !` | 論理演算 |
| `= += -= &= \|= ^= <<= >>=` | 代入 |
| `..` `..=` | 範囲（終わりを含まない／含む） |
| `::` | パス（モジュール、型に付いた関数、列挙型の値） |
| `.` | フィールド、メソッド |
| `->` | 戻り値の型 |
| `=>` | match の腕 |
| `@` | 置き場所の指定（`@ $D010`）、変換表の指定（`'A'@screen`） |
| `#[ ]` | 属性 |
| `'name` | ループのラベル |
| `?` | Option の早期の戻り |
| `&` （前置） | アドレスを取る |
