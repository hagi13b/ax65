<a id="s10"></a>
## 10. 割り込みと共有データ

<a id="s10-1"></a>
### 10.1 割り込み処理の宣言

```
#[interrupt(irq)]
fn on_irq() {
    if IFR.contains(Ifr::T1) {
        let _ = T1C_L;
        TICKS += 1;
    }
}

#[interrupt(nmi)]
fn on_nmi() { ... }

#[interrupt(brk)]
fn on_brk() { ... }                     // brk 命令によるもの
```

```asm
on_irq:                         ; コンパイラが作る入口（この処理は A を使わないので退避しない）
        bit IFR                 ; IFR.contains(Ifr::T1)：ビット 6 を V フラグで調べる
        bvc done                ; 立っていなければ終わる
        bit T1C_L               ; let _ = T1C_L：bit で読む（A は変わらない）
        inc TICKS               ; TICKS += 1：下位
        bne done                ; 0 に戻らなければ終わり
        inc TICKS+1             ; 上位に繰り上げる
done:   rti                     ; 戻る
```

- レジスタの退避と復帰、`rti` はコンパイラが作ります。退避するのは、割り込み処理の中で実際に使うレジスタだけです。
- 割り込み処理の関数は、引数と戻り値を持てません。
- `brk` 命令は IRQ と同じベクタを使います。`#[interrupt(brk)]` があれば、コンパイラがスタック上のフラグの B ビットを調べて振り分けるコードを作ります。
- ベクタの置き方は、ターゲット定義の `irq`・`nmi` で指定します（[16.4節](#s16-4)）。
- `irq = none` のターゲットでは `#[interrupt(irq)]` と `#[interrupt(brk)]` が、`nmi = none` のターゲットでは `#[interrupt(nmi)]` がエラーです（[16.4節](#s16-4)）。

<a id="s10-2"></a>
### 10.2 割り込み処理の制約

```
fn common() { ... }
fn read_port() { ... }

#[interrupt(irq)]
fn on_irq() {
    common();                           // エラー：common はメインからも呼ばれている
    read_port();
    irq_enable();                       // エラー：割り込み処理の中で割り込みを許可している
    while busy() { }                    // エラー：上限のないループ（#[max(n)] が必要）
}

#[interrupt(nmi)]
fn on_nmi() {
    read_port();                        // エラー：read_port は IRQ 処理からも呼ばれている
}

fn main() { common(); }
```

- 関数を呼ぶ場所は、メイン、IRQ 処理（`#[interrupt(irq)]` と `#[interrupt(brk)]`）、NMI 処理の 3 つの文脈に分かれます。1 つの関数は、1 つの文脈からだけ呼べます。2 つ以上の文脈から呼ばれる関数はエラーです（コンパイル時に計算される呼び出しは数えない）。
- ローカル変数は、文脈ごとに別の領域に置きます（[4.8節](#s4-8)）。
- 割り込み処理の中での割り込みの許可（`irq_enable()`）は禁止です。割り込み処理から呼ばれる関数の中も同じです。
- 割り込み処理の中のループには上限が必要です（[6.3節](#s6-3)）。
- 割り込み処理の最長経路のサイクル数をレポートに出します。ターゲット定義に `irq_interval` があれば、次の割り込みまでに終わらない場合をエラーにします。

関連 Q&A：[F-1](#qa-f1)、[L-2](#qa-l2)、[M-3](#qa-m3)

<a id="s10-3"></a>
### 10.3 割り込みの許可と禁止

```
fn main() {
    setup();                            // 起動時から割り込みは止まっている
    irq_enable();                       // 割り込みを許可する（cli）
    loop { ... }
}
```

- 起動時は、すべての `init` が終わり、`main` が始まった時点でも割り込みは止まったままです（[15.1節](#s15-1)）。割り込みを使うプログラムは、`main` の中で `irq_enable()` を呼びます。
- 組み込み関数 `irq_enable()`（`cli`）と `irq_disable()`（`sei`）を使えます。
- `irq_enable()` を、割り込み処理、`atomic`、`cycles()`、`io_span()` の中で呼ぶとエラーです。そこから直接・間接に呼ばれる関数の中で呼ぶ場合も、エラーです。

```
fn start_timer() { irq_enable(); }
fn f() {
    atomic { start_timer(); }           // エラー：atomic の中から呼ぶ関数で irq_enable() を呼んでいる
}
```

- `irq_disable()` で割り込みを止めている間でも、`shared` 変数の操作には [10.4節](#s10-4) の規則がそのまま適用されます。
- 割り込み処理を宣言していないプログラムで `irq_enable()` を呼ぶと警告です。`irq = none` のターゲットでは、`irq_enable()` はエラーです（[16.4節](#s16-4)）。

関連 Q&A：[F-4](#qa-f4)、[M-17](#qa-m17)

<a id="s10-4"></a>
### 10.4 shared

```
range Kpos = 0..16;
shared(irq)  KEYBUF: [u8; Kpos] = [0; Kpos];    // 書き込むのは割り込み処理だけ
shared(irq)  HEAD: Kpos = 0;                    // 書き込むのは割り込み処理だけ
shared(main) TAIL: Kpos = 0;                    // 書き込むのはメインだけ
shared(irq)  TICKS: u16 = 0;
shared       COUNT: u8 = 0;                     // どちらも書き込む

#[interrupt(irq)]
fn on_irq() {
    let next = Kpos::wrap(HEAD as u8 + 1);
    if next != TAIL {                   // TAIL はメインが書くが、1 バイトなので atomic 不要
        KEYBUF[HEAD] = KBD;             // データを書いてから
        HEAD = next;                    // 位置を進める（shared の読み書きの順序はソースどおり）
    }
    TICKS += 1;                         // 割り込み処理の中なので atomic は不要
}

fn get_key() -> Option<u8> {
    if TAIL == HEAD { return None; }    // HEAD は 1 バイトなので、そのまま読める
    let c = KEYBUF[TAIL];
    TAIL = Kpos::wrap(TAIL as u8 + 1);  // 書き込むのはメインだけ、1 バイト → atomic 不要
    Some(c)
}

fn ticks() -> u16 {
    atomic { TICKS }                    // メインの側で 16 ビットを読むので必要
}

fn count_up() {
    COUNT += 1;                         // 1 命令の操作なので atomic 不要
    COUNT += 2;                         // エラー：両方が書く変数への 2 命令以上の操作（atomic が必要）
    atomic { COUNT += 2; }              // OK
}

shared(nmi) NMI_HIT: u8 = 0;            // NMI と共有する変数（1 バイト、書き込む側の指定が必須）

#[interrupt(nmi)]
fn on_nmi() { NMI_HIT = NMI_HIT | 1; }  // NMI 処理の中では、どの操作も使える

fn poll_nmi() -> bool {
    NMI_HIT != 0                        // メインの側は 1 命令の操作（読み込み）だけ
}
```

- `shared` は、割り込み処理とメインで共有する変数です。`static` と同じく常に書き換えられる変数です。
- 書き込む側を `shared(irq)`、`shared(main)`、`shared(nmi)` で指定できます（Rust の `pub(crate)` と同じ形）。指定した側以外が書き込むとエラーです。指定を省略した場合は両方が書き込めます。

#### 1 命令の操作

1 バイトの型の `shared` 変数（配列の場合は 1 バイトの要素）に対する、次の形の操作を「1 命令の操作」と呼びます。ソースの形だけで決まり、CPU によって変わりません。

| 操作 | 例 |
|---|---|
| 読み込み（値を読むだけ） | `let h = HEAD;`、`if TAIL == HEAD { }` |
| 書き込み（`X = 式;` で、右辺に X を含まない） | `HEAD = next;` |
| `X += 1;`、`X -= 1;` | `COUNT += 1;` |

それ以外の操作（`COUNT = COUNT * 2;`、`COUNT += 2;`、ビットフラグの `insert`・`remove`、2 バイト以上の読み書きなど）は、すべて「2 命令以上の操作」です。

#### 規則

- 1 命令の操作は、どこでもそのまま書けます。
- 2 命令以上の操作は、次の表に従います。

| 操作する場所 | 共有の相手 | 2 命令以上の操作 |
|---|---|---|
| メイン | IRQ 処理 | `atomic` が必要（下の例外を除く） |
| IRQ 処理の中 | メイン | `atomic` は不要 |
| NMI 処理の中 | メイン、IRQ 処理 | 使える（`atomic` は不要） |
| メイン、IRQ 処理 | NMI 処理 | エラー（1 命令の操作だけを使える） |

**書き込む側が 1 つの場合の例外**：IRQ 処理とメインで共有し、書き込む側を指定した変数では、次の操作に `atomic` は要りません。

| 操作 | atomic |
|---|---|
| 書き込む側が、自分が書く変数を読む | 不要 |
| 書き込む側が、1 バイトの変数に書く（読んで計算して書き戻す場合も含む） | 不要 |
| 書き込む側が、2 バイト以上の変数に書く | 必要 |
| 読む側が、2 バイト以上の変数を読む | 必要 |
| 書き込む側を指定していない変数への 2 命令以上の操作 | 必要 |

**NMI と共有する変数**：

- 1 バイトの型に限ります。
- 書き込む側の指定（`shared(nmi)`、`shared(main)`、`shared(irq)`）が必須です。
- NMI 処理の中では、どの操作も使えます。
- NMI 以外の側（メイン・IRQ 処理）では、1 命令の操作だけを使えます。

**共通**：

- `shared` 変数の読み書きは省略しません。回数と順序はソースどおりです。
- 割り込み処理と通常の `static` を共有するとエラーです（共有する変数は `shared` で宣言する）。

- 割り込みのないターゲットでの `shared` の扱いは [16.4節](#s16-4) にあります。

関連 Q&A：[F-3](#qa-f3)、[F-7](#qa-f7)、[A-2](#qa-a2)、[M-2](#qa-m2)

<a id="s10-5"></a>
### 10.5 atomic

```
shared(main) SPEED: u16 = 0;            // 書き込むのはメインだけ

fn set_speed(v: u16) {
    atomic {
        SPEED = v;                      // 2 バイトの書き込みなので atomic が必要
    }
}

let t = atomic { TICKS };               // 値を返す atomic
```

```asm
; let t = atomic { TICKS };
        php                     ; 割り込みの許可状態を退避する
        sei                     ; 割り込みを止める
        lda TICKS               ; 下位を読む
        ldx TICKS+1             ; 上位を読む
        plp                     ; 許可状態を元に戻す（読み終えてから戻す）
```

- `php` と `sei` で始まり、`plp` で終わります。入れ子にできます。
- ブロックの最後の式を、ブロックの値として返せます（Rust のブロック式と同じ）。
- 割り込み処理の中では何も生成しません（書かなくてもよく、書いても警告は出ません）。
- `irq = none` かつ `nmi = none` のターゲットでも何も生成しません。
- 最も長い `atomic` のサイクル数（割り込みが待たされる最大の時間）をレポートに出します。`cycles()`・`io_span()` の中の時間も、`atomic` として含めます（[12.1節](#s12-1)）。
- `atomic` の中（そこから呼ぶ関数を含む）で `irq_enable()` を呼ぶとエラーです（[10.3節](#s10-3)）。
- `atomic` は NMI を止めません。NMI と共有する変数を `atomic` の中で使うと警告です。

関連 Q&A：[F-5](#qa-f5)

## 11. I/O

<a id="s11-1"></a>
### 11.1 I/O 変数の宣言

```
flags Bits { B0, B1, B2, B3, B4, B5, B6, B7 }

io(in)  KBD:     u8   @ $8800;          // 読み込み専用（HEXPAD のキー）
io(out) DSP:     u8   @ $8804;          // 書き込み専用（HEXPAD の右 2 桁）
io      PORTB:   u8   @ $8000;          // 読み書き両方
io(rmw) DDRA:    Bits @ $8003;          // RMW 命令の使用を許可（ビットフラグ型）
io(in)  JOYPORT: Joy  @ $8001;          // ビットフラグ型として宣言
io      VRAM:    [[u8; Col]; Row] @ $9000;   // I/O の配列（v3 の画面メモリなど）
```

- I/O 変数の要素の型は、`u8`、`i8`、`char`、8 ビット以下のビットフラグ型です。16 ビットのレジスタは、下位と上位を別々に宣言します。
- I/O の配列は、1 バイトの要素の並びです。添字の規則は通常の配列と同じです。
- アドレスは、ターゲット定義の `io` の区画の中でなければなりません（[16.3節](#s16-3)）。

<a id="s11-2"></a>
### 11.2 アクセスの規則

```
T2C_L = $F2;                            // 下位を先に書く
T2C_H = $77;                            // 上位を書くとタイマーが動き出す（順序はソースどおりに守られる）
DSP = KBD;                              // KBD を 1 回読み、DSP に 1 回書く
let k = KBD;                            // エラーにはならないが、もう 1 回読む（読み込みは省略されない）
DDRA.insert(Bits::B0);                  // io(rmw) なので tsb を使える
PORTB += 1;                             // io(rmw) でないので lda / clc / adc / sta になる
```

- `io(in)` は読み込み専用、`io(out)` は書き込み専用です。逆の使い方はエラーです。
- ソースに書いた読み書きは、それぞれ必ず 1 回のアクセスになり、省略も追加もしません。I/O 変数同士の読み書きの順序は、ソースの順のままです。
- RMW 命令（`inc`、`asl`、`tsb` など）は、標準では I/O 変数に使いません。`io(rmw)` と宣言したレジスタにだけ使います。インデックス付きのアクセスで余分な読み込みが起きる場合も同じ扱いです。

関連 Q&A：[L-1](#qa-l1)

<a id="s11-3"></a>
### 11.3 読み捨て

```
let _ = T2C_L;                          // 読むだけで T2 のフラグが消える
```

```asm
        bit T2C_L               ; bit 命令で読む（A、X、Y は変わらない。N、V、Z だけが変わる）
```

- 値を使わない読み込みは `let _ = I/O変数;` と書きます（Rust と同じ書き方）。
- この読み込みは `bit` 命令で行います。読み込みは必ず 1 回行われ、A・X・Y は変わりません（N・V・Z のフラグだけが変わる）。

関連 Q&A：[F-6](#qa-f6)

<a id="s11-4"></a>
### 11.4 I/O の所有者

```
// hw/via.ax65
io(out) DDRB: u8 @ $8002;
pub fn set_output() { DDRB = $FF; }     // 他のモジュールには関数を公開する
pub io(out) PORTB: u8 @ $8000;          // エラー：I/O 変数に pub は付けられない

// hw/other.ax65
io DDRB2: u8 @ $8002;                   // エラー：同じアドレスを hw::via も宣言している
```

- I/O 変数は、宣言したモジュールだけが操作できます（`pub` を付けられない）。他のモジュールは、所有モジュールの関数を通して使います。
- プログラム全体の I/O 変数のアドレスを集め、2 つのモジュールが同じアドレスを宣言していたらエラーです。チップ全体で共有するレジスタがある場合は、1 つのモジュールにまとめます。

<a id="s12"></a>
## 12. タイミング

<a id="s12-1"></a>
### 12.1 サイクル数のブロック

```
cycles(40) {                            // 中の命令が、ちょうど 40 サイクル
    shift_out();
}
io_span(8) {                            // 最初の I/O の書き込みから最後の書き込みまで、ちょうど 8 サイクル
    PORTB = 1;
    PORTB = 0;
}
max_cycles(500) { update(); }           // 500 サイクル以内（超えたらエラー）
delay(core::us(40));                    // 最低 40 マイクロ秒待つ
```

```asm
; io_span(8) { PORTB = 1; PORTB = 0; }
        lda #1                  ; 1 を用意する
        sta PORTB               ; 4 サイクル目にピンが 1 になる（ここから数える）
        nop                     ; 2 サイクル（コンパイラが埋めた）
        nop                     ; 2 サイクル（コンパイラが埋めた）
        stz PORTB               ; 4 サイクル目にピンが 0 になる（ここまで 2+2+4 = 8 サイクル）
```

| 形 | 意味 | 主な用途 |
|---|---|---|
| `cycles(n) { }` | ブロックの中の命令がちょうど n サイクル（足りない分は `nop` で埋める） | ビデオ表示のタイミングなど、処理全体の長さ |
| `io_span(n) { }` | ブロックの中の、最初の I/O の読み書きから最後の I/O の読み書きまでが、ちょうど n サイクル | パルスの幅など、I/O の間隔 |
| `max_cycles(n) { }` | n サイクル以内（超えたらエラー） | 時間内に終わらせたい処理 |
| `delay(n);` | 最低 n サイクル待つ（コンパイラが待ちループを作る） | 周辺チップの待ち時間 |

- `cycles(n)` が数えるのは、ブロックの中の命令だけです（最初の命令の始まりから、ブロックの次の命令の始まりまで）。
- `io_span(n)` は、各命令が実際にバスへ読み書きするサイクル（書き込みは命令の最後のサイクル）で数えます。パルスの幅は、ブロックの中の命令の合計とは一致しません。`io_span()` の中には I/O の読み書きが 2 つ以上必要です。
- 足りないサイクルは、`nop`（2 サイクル）と、奇数の場合は次の命令への `jmp`（3 サイクル）1 つで埋めます。足りない分が 1 サイクルだけの場合はエラーです。
- `cycles()` と `io_span()` では、分岐の両方の経路のサイクル数を同じ方法でそろえます。そろえられない場合はエラーです。ページ境界をまたぐことによるサイクルの増加は、コンパイラが配置で調整します。
- `cycles()` と `io_span()` は自動で `atomic` を兼ねます。ただし NMI は止められません。中の時間は、レポートの「最も長い `atomic`」に含めます（[10.5節](#s10-5)）。
- `cycles()`・`io_span()` の中（そこから呼ぶ関数を含む）で `irq_enable()` を呼ぶとエラーです（[10.3節](#s10-3)）。
- `cycles()`・`io_span()` で埋めた命令（`nop`、`jmp`）の数と場所は、レポートに出ます（[18.4節](#s18-4)）。
- 中のループには上限が必要です（[6.3節](#s6-3)）。

関連 Q&A：[F-8](#qa-f8)、[M-17](#qa-m17)

<a id="s12-2"></a>
### 12.2 時間の指定

```
use core::us;
delay(us(40));                          // ターゲット定義のクロックからサイクル数を求める
io_span(us(10)) { PORTB = 1; PORTB = 0; }
```

- `core::us()` は、マイクロ秒をサイクル数に変換する `comptime fn` です。ちょうどにならない場合は、警告を出して切り上げます。
- 名前だけで `us(40)` と書くには `use core::us;` で取り込みます。取り込まない場合は `core::us(40)` と書きます（[20.2節](#s20-2)）。
- クロックを変えても、ターゲット定義の `clock` を書き換えるだけで、待ち時間が正しく保たれます。

関連 Q&A：[F-2](#qa-f2)、[M-19](#qa-m19)

<a id="s12-3"></a>
### 12.3 割り込み待ち

```
comptime if target.cpu == Cpu::W65C02S && target.has_irq {
    wait_interrupt();                   // wai 命令：割り込みが来るまで CPU を止める
}
```

- `wait_interrupt()` は、CPU が W65C02S で、`irq` が `none` でないターゲットだけで使えます。それ以外のターゲットではエラーなので、他のターゲットでも使うプログラムでは `comptime if` で囲みます。
- `target.has_irq` は、ターゲットの `irq` が `none` でなければ `true` です（[13.5節](#s13-5)）。

## 13. コンパイル時の計算と条件コンパイル

<a id="s13-1"></a>
### 13.1 コンパイル時に計算される場所

`const` と `static` の初期値、配列の長さ、範囲型の上限・下限、`cycles()`・`io_span()`・`max_cycles()`・`delay()` の引数、`@` のアドレス、`match` の場合の値は、必ずコンパイル時に計算されます。計算できない式はエラーです。

```
const N: u8 = 10;
static BUF: [u8; N * 2] = [0; N * 2];   // 長さもコンパイル時に計算
let a: [u8; n];                             // エラー：n は実行時の値
```

<a id="s13-2"></a>
### 13.2 const fn と comptime fn

```
const fn clamp(v: u8, lo: u8, hi: u8) -> u8 { ... }     // 実行時にもコンパイル時にも呼べる

comptime fn sine_at(i: int) -> i8 {                     // コンパイル時にしか呼べない
    let r: real = sin(i as real * 2.0 * PI / 256.0);
    round(r * 127.0) as i8
}
```

| | `const fn` | `comptime fn` |
|---|---|---|
| 呼べる時点 | 実行時とコンパイル時 | コンパイル時だけ |
| 使える型 | 実行時の型だけ | 実行時の型に加えて `int`（大きさの制限なし）、`real`（倍精度の小数） |
| 使える関数 | `const fn` | `const fn`、`comptime fn`、組み込みの数学関数（`sin` `cos` `sqrt` `round` `floor` `abs` と `PI`。[20.1節](#s20-1)） |
| `as` の変換 | 実行時と同じ（整数型同士は下位のバイトを取る） | `int`・`real` から実行時の型への変換で範囲を超えたらエラー（一周させない） |

- `as` の規則は [3.14節](#s3-14) にあります。

- 1 つの定数の計算に使える手順数に上限があり、超えたらエラーです（上限は `--step-limit` で変更できる。[17.5節](#s17-5)）。

関連 Q&A：[K-17](#qa-k17)

<a id="s13-3"></a>
### 13.3 表の生成

```
const SINE: [i8; 256] = [for i in 0..256 => sine_at(i)];
const ROW_ADDR: [u16; 24] = [for r in 0..24 => $0400 + r * 40];   // r は int。最大 $0798 で u16 に収まる
```

- 配列の各要素を、添字から計算する式で書けます。2 次元配列の行の表の自動生成（[3.8節](#s3-8)）も、この仕組みを使います。
- `[for i in a..b => 式]` の添字 `i` は、コンパイル時の型 `int` です。`式` は `int`・`real` で計算し、最後に配列の要素の型に変換します。要素の型に収まらなければエラーです（[3.14節](#s3-14)）。
- 範囲の個数は、配列の長さと同じでなければなりません。

```
const BIG: [u8; 4] = [for i in 0..4 => i * 100];                  // エラー：300 は u8 に収まらない
```

関連 Q&A：[M-20](#qa-m20)

<a id="s13-4"></a>
### 13.4 外部データ

```
const FONT: [[u8; 256]; 3] = include_bin("data/font.bin");
const TILES: [u8; 256] = include_bin("data/tiles.bin", offset = 16);
```

- ファイルの中身をそのまま配列の初期値にします。大きさが配列と合わなければエラーです。パスは、そのソースファイルのある場所からの相対パスです。

<a id="s13-5"></a>
### 13.5 検査と情報

```
comptime assert(size_of(Packet) == 4, "Packet は 4 バイトでなければならない");
comptime assert(target.clock / 60 <= 65535, "タイマーの周期が 16 ビットに収まらない");
const LEN: u8 = TABLE.len();
comptime if build.debug { dump(); }
```

| 書き方 | 意味 |
|---|---|
| `comptime assert(条件, "説明")` | 条件が成り立たなければ、説明を付けてエラーにする |
| `size_of(型)` | 型の大きさ（バイト） |
| `a.len()` | 配列・文字列の長さ |
| `target.cpu`、`target.clock` | ターゲット定義の CPU とクロック |
| `target.has_irq`、`target.has_nmi` | ターゲット定義の `irq`・`nmi` が `none` でないか（[16.4節](#s16-4)） |
| `target.has(インターフェース)` | そのインターフェースが bind されているか |
| `target.名前` | ターゲット定義の定数 |
| `build.名前` | コマンドラインの `-D` で渡した値（[17.5節](#s17-5)） |

<a id="s13-6"></a>
### 13.6 条件コンパイル

```
fn idle() {
    comptime if target.cpu == Cpu::W65C02S && target.has_irq {
        wait_interrupt();
    }
}

comptime if target.has(screen) {
    fn draw_all() { screen::clear(); ... }
} else {
    fn draw_all() { console::putc('\r'); ... }
}

comptime match target.cpu {
    Cpu::W65C02S => console::putc('W'),
    _            => console::putc('-'),
}

comptime if build.debug { console::putc('*'); }
```

- `comptime if` と `comptime match` は、関数の中（文）にも外（宣言）にも書けます。文字列を置き換えるプリプロセッサやマクロはありません。
- 条件に使えるのは、[13.5節](#s13-5) の `target.*` と `build.*` です。機種名による分岐はできません。
- `target.has()` に書けるのは既知のインターフェースの名前だけ、`target.名前` に書けるのはターゲット定義の定数の名前だけです。書き間違いはエラーです。
- 選ばれなかった側のコードはプログラムに含まれず、スタック・メモリ・呼び出しグラフの検査も、選ばれた側だけで行います。
- 選ばれなかった側は、構文だけを検査します。登録したすべてのターゲットで型まで検査するには `ax65 check --all-targets` を使います（[17.4節](#s17-4)）。

<a id="s14"></a>
## 14. インラインアセンブリ

<a id="s14-1"></a>
### 14.1 基本方針

```
asm {
    ldx #0                      ; コンパイラは「X を壊す」と分かる
    lda {BUF},x                 ; 「A を壊す」「BUF を読む」と分かる
    pha                         ; スタックを 1 バイト使う
    pla                         ; 戻すので、出口での深さは入口と同じ
}
// 宣言は不要。レポートには「A、X、フラグを壊す。スタック 1 バイト。13 サイクル」と出る
```

コンパイラはインラインアセンブリを 1 命令ずつ解析し、壊すレジスタとフラグ、スタックの使用量、サイクル数、呼び出しグラフを自動で求めます。プログラマがこれらを宣言する必要はなく、これまでの検査はインラインアセンブリの中でも続きます。

<a id="s14-2"></a>
### 14.2 書き方

```
fn add_score(n: u8) {
    asm {
        sed                     ; 10進モードにする
        clc                     ; 足し算の準備
        lda {SCORE.lo}          ; 言語の変数は {名前} で参照する。2バイト以上は .lo / .hi
        adc {n}                 ; 引数 n を足す
        sta {SCORE.lo}          ; 下位を書く
        lda {SCORE.hi}          ; 上位を読む
        adc #0                  ; 繰り上がりを足す
        sta {SCORE.hi}          ; 上位を書く
        cld                     ; 10進モードを解除する
    }
}

fn reverse_bits(v: u8) -> u8 {
    let r: u8;
    asm (in A = v, out A -> r) {        // 値をレジスタで受け渡す
        ldx #8                  ; 8 ビット分くり返す
    loop:                       ; ブロックの中だけで有効なラベル
        lsr a                   ; 最下位ビットをキャリーへ
        rol {TMP}               ; キャリーを TMP に入れる
        dex                     ; 残りを 1 減らす
        bne loop                ; 残っていればくり返す
        lda {TMP}               ; 結果を A に（出口で r に入る）
    }
    r
}
```

- `asm { }`、レジスタで値を受け渡す `asm (in A = 式, out A -> 変数) { }`、関数全体の `asm fn`（[7.4節](#s7-4)）の 3 つの形があります。
- 言語の名前は `{名前}` で参照します。2 バイト以上の変数は `{W.lo}`、`{W.hi}` のように、どのバイトかを明示します。
- 参照した変数について、アドレッシングモード（間接参照はゼロページの変数だけ）、値を入れる前の読み込み、I/O の所有者・向き・RMW の可否、`shared` の規則を検査します。
- 数値は言語と同じく `$FF`、`0xFF`、`0b...` で書きます。

関連 Q&A：[L-3](#qa-l3)

<a id="s14-3"></a>
### 14.3 ブロックの決まり

```
asm {
    pha                         ; エラー：pla がなく、出口でスタックの深さが違う
    jmp {game_over}             ; エラー：ブロックの外への jmp（jsr {関数} を使う）
    jsr $FF09                   ; エラー：数値のアドレスへの jsr（extern fn で宣言する）
    sei                         ; エラー：通常の asm では書けない命令（unsafe asm が必要）
}
```

- ブロックの入口と出口で、スタックの深さが同じでなければなりません。
- 分岐と `jmp` の飛び先は、ブロックの中のラベルかブロックの終わりだけです。
- `jsr {関数名}` で AX65 の関数を呼べます（呼び出しグラフに組み込まれる）。ROM ルーチンは `extern fn` で宣言したものだけを呼べ、数値のアドレスへの `jsr` はエラーです。
- ターゲットの CPU にない命令と、未定義命令はエラーです。
- ブロックの出口では、10進モードが解除されていなければなりません。`sed` の後に `cld` がないブロックはエラーです。
- 割り込み処理の中と `cycles()` などの中では、ループの回数の上限をコンパイラが求められる形でなければなりません。

<a id="s14-4"></a>
### 14.4 unsafe asm

```
unsafe asm (clobbers(A), stack(1), cycles(12..=20), irq(disables)) {
    php                         ; フラグを退避する
    sei                         ; 割り込みを止める
    ...                         ; 割り込みを止めた状態での処理
    plp                         ; フラグを戻す
}
```

- `txs`、`sei`、`cli`、`plp`、`rti`、`brk`、間接ジャンプ、数値のアドレスへの書き込みなど、検査の前提を崩す命令は、通常の `asm` では書けません。必要な場合は `unsafe asm` を使い、コンパイラが求められない性質を宣言します。
- 宣言の正しさはプログラマの責任です。`unsafe asm` の中でも、他のモジュールの I/O 変数や変数、他の関数の変数のアドレスへの書き込みはエラーです。
- `unsafe asm` の宣言と、そこで使った数値のアドレスは、レポートの unsafe の項目に一覧で出します。
- 割り込みを止めるだけなら、`atomic { }` の中に通常の `asm` を書きます。

<a id="s14-5"></a>
### 14.5 自己書き換えコード

```
asm {
        lda {PAGE}              ; 読みたいページの番号
        sta load+2              ; 下の命令のアドレスの上位バイトを書き換える
        ldx #0                  ; X = 0 から
    smc load: lda $1200,x       ; オペランドを書き換えてよい命令（smc を付ける）
}
```

- 書き換える命令には `smc` を付けます。宣言なしに命令の位置へ書き込むとエラーです。
- 書き換えられるのはオペランドだけで、オペコードは書き換えられません。
- `run = rom` のターゲットでは、`smc` はエラーです。
- `smc` を付けた命令は、レポートの unsafe の項目に一覧で出ます。
