## 18. 診断とレポート

<a id="s18-1"></a>
### 18.1 エラー

```
エラー[E0601]：再帰呼び出しがあります
  --> src/main.ax65:12:5
   |
12 |     a();
   |     ^ b → a の呼び出しで、a → b → a の輪ができています
補足：ax65 では再帰を使えません（7.5節）
```

番号の範囲は、エラーの種類ごとに分けます。各番号の詳しい説明と例は `ax65 explain <番号>` で表示します。

| 番号 | 種類 | 主な内容 |
|---|---|---|
| E01xx | 字句・構文 | 書式の誤り、未知のキーワード、予約語（`mut`）の使用、文の区切りの抜け、比較の連鎖（`a < b < c`） |
| E02xx | 名前・モジュール | 未定義の名前、`use` の名前の重なり、非公開の名前の使用、モジュールが見つからない、`init` の順序が決まらない循環 |
| E03xx | 資源の上限 | スタックの予算の超過（E0301）、RAM・ゼロページの容量の超過、区画の外や `reserve` の中のアドレス |
| E04xx | 型 | 型の不一致（`u8` と `u16`、符号、範囲型・列挙型・変換表の違い、`[char; N]` と `str` など）、範囲外になりうる添字（E0412）、値を返す `if`・`match` の型の違い、`else` の抜け、`Option` の確認の抜け、戻り値が `Option` でない関数の中の `?`、2 のべき乗の定数でない `/`・`%`、右側が定数でない `<<`・`>>`、`u8` から範囲型・列挙型への `as`、BCD と整数の間の `as`、個数が 2 のべき乗でない範囲型の `wrap()`、割る数に `Nz8`・`Nz16` でない値を渡す、配列を返す関数 |
| E05xx | 値と変数 | 値を入れる前の読み込み、`const` への代入、`const` を指すポインタを通した書き込み、数値の `const` のアドレス、型のない `const`、ローカル変数のアドレスの持ち出し（呼び出し先を通したものを含む）、構造体の値のフィールドの抜け、配列の値の個数の違い、BCD への 16進・範囲外のリテラル、変換できないリテラル、型を書かない `let` の整数リテラルが `u8` に収まらない |
| E06xx | 関数 | 再帰呼び出し、`fnset` にない関数の代入、`const fn` の条件違反、`comptime fn` の実行時の呼び出し、`#[inline(always)]` で展開できない関数、`extern fn` 以外での `in` によるレジスタの指定 |
| E07xx | 制御構文 | `match` の場合の抜け、上限のないループ（割り込み処理・サイクル数のブロックの中）、`#[reg]` で指定したレジスタが使えない |
| E08xx | 割り込みと共有 | 2 つ以上の文脈（メイン、IRQ 処理、NMI 処理）から呼ばれる関数、割り込み処理・`atomic`・`cycles()`・`io_span()` の中（そこから呼ぶ関数を含む）の `irq_enable()`、`shared` の規則（[10.4節](#s10-4)）に反する操作、指定外の側からの書き込み、NMI と共有する 2 バイト以上の変数・書き込む側の指定のない変数、割り込み処理と通常の `static` の共有、割り込み処理の時間が `irq_interval` を超える |
| E09xx | I/O とタイミング | `io(in)`・`io(out)` に反する使用、`io(rmw)` でないレジスタへの RMW、同じ I/O アドレスの宣言、I/O 変数への `pub`、I/O 変数に使えない型、`cycles()`・`io_span()`・`max_cycles()` のサイクル数の超過、そろえられない分岐、I/O が 2 つ未満の `io_span()` |
| E10xx | コンパイル時 | 計算できない式、`int`・`real` から実行時の型への変換の範囲超過、手順数の上限超過、`include_bin` の大きさの不一致、`comptime assert` の失敗、`target.has()`・`target.名前` の知らない名前 |
| E11xx | ターゲットと bind | 実装の過不足・型の違い、`impl` の中の `pub`、bind の誤り、bind されていないインターフェースの使用、ターゲットの CPU にない機能（`wait_interrupt()` など）、`irq = none`・`nmi = none` のターゲットでの割り込みの機能（[16.4節](#s16-4)）、`reserve` の中の I/O 変数、変換表にない文字・重複・範囲の個数の違い、`exit = never` で `main` が終わりうる |
| E12xx | インラインアセンブリ | スタックの不釣り合い、ブロック外への分岐、未宣言のアドレスへの `jsr`、CPU にない命令・未定義命令、通常の `asm` での検査できない命令、変数のバイトの未指定、宣言のない命令の書き換え、ROM のターゲットでの `smc`、`unsafe asm` での他のモジュールの I/O 変数・変数への書き込み |

- 資源とタイミングの検査（E03xx、E07xx の `#[reg]`、E08xx の `irq_interval`、E09xx の `max_cycles()`）は、選んだ最適化の段階で生成したコードに対して行います（[19.1節](#s19-1)）。

### 18.2 警告

| 名前 | 内容 |
|---|---|
| `unused_imports` | 使っていない `use`。取り込んだ名前ごとに出す（`init` がある場合は、起動時に実行されることも示す） |
| `unused_variables` | 使っていない変数 |
| `unused_results` | 使っていない `bool`・`Option` の値 |
| `naming` | 名前の慣習（[2.3節](#s2-3)）に合わない名前 |
| `inexact_time` | `us()` の時間がちょうどのサイクル数にならない（切り上げた） |
| `nmi_in_atomic` | NMI と共有する変数を `atomic` の中で使っている（NMI は止められない） |
| `irq_without_handler` | 割り込み処理を宣言していないプログラムでの `irq_enable()` |
| `reversible_loop` | 逆順にすると速くなるループ（助言） |

```
#[allow(unused_imports)]
use hw::debug;                          // この場所だけ警告を止める
```

- 警告ごとの扱いは、ソースの `#[allow(名前)]`・`#[warn(名前)]`・`#[deny(名前)]`、プロジェクトファイルの `lints`、コマンドラインの `-A`・`-W`・`--deny` で変えられます。優先順位は、ソースの属性、コマンドライン、プロジェクトファイルの順です。
- `--deny-warnings` で、すべての警告をエラーとして扱います（[17.5節](#s17-5)）。

<a id="s19"></a>
## 19. 最適化

<a id="s19-1"></a>
### 19.1 最適化の段階

```
ax65 build -O0        # 最適化をしない
ax65 build -O1
ax65 build            # 既定（-O2）
ax65 build -Os        # 速さ優先
```

| 段階 | 方針 | 位置づけ |
|---|---|---|
| `-O0` | 最適化をしない。配置と命令が最も予測しやすい | 生成されたコードを確かめたいとき |
| `-O1` | 速さと大きさの釣り合いを取る（初期の仕様の最適化） | ― |
| `-O2` | 大きさを優先する | **既定** |
| `-Os` | `-O2` に加えて、コードが大きくなっても速さを優先する | 速さが足りないとき |

- どの段階でも、プログラムの意味は変わりません。`cycles()`・`io_span()` とインラインアセンブリが参照する変数の配置は、段階で変わりません。
- 資源とタイミングの検査（スタックの予算、RAM・ゼロページの容量、`max_cycles()`、`irq_interval`、`#[reg]`）は、選んだ段階で生成したコードに対して行います。検査が通るかどうかは、段階によって変わることがあります。すべての段階で検査するには `ax65 check --all-levels` を使います（[17.5節](#s17-5)）。
- GCC などでは `-Os` は大きさ優先の意味ですが、ax65 では速さ優先（speed）の意味です。
- 段階ごとの測定の例は『サンプルと効果測定 1.1』にあります（要約は [付録D](#appD)）。

```
ax65 check --all-levels                 # -O0・-O1・-O2・-Os のすべてで検査する
```

関連 Q&A：[I-3](#qa-i3)、[I-4](#qa-i4)、[I-1](#qa-i1)、[M-7](#qa-m7)

次の例で、段階による違いを示します（`respawn` は 2 か所から呼ばれる）。

```
fn respawn(m: Mid) { ... }              // 2 か所から呼ばれる小さな関数
fn update() {
    for m in Mid {
        if METEORS[m].y == FIELD_H { respawn(m); }   // めったに通らない枝
    }
}
fn main() { for m in Mid { respawn(m); } loop { update(); } }
```

| 段階 | `respawn` の扱い |
|---|---|
| `-O0` | 展開しない。m は呼び出しをまたぐのでメモリに置く |
| `-O1` | 小さいので 2 か所に展開する（ループが大きくなる） |
| `-O2` | 2 か所から呼ばれるので展開しない。m を X で渡すように渡し方を変え、ループの番号を X に置く |
| `-Os` | ループの中で呼ばれるので展開する。`#[cold]` を付ければ展開しない |

<a id="s19-2"></a>
### 19.2 -O1

- ゼロページへの自動配置（[4.7節](#s4-7)）
- 関数の展開（1 か所からしか呼ばれない関数と、小さな関数）
- 関数ごとの引数の渡し方の変更（[15.2節](#s15-2)）
- 構造体の戻り値の最初のフィールドを、レジスタでも返す
- 順番に依存しないループの自動の逆順化（[6.4節](#s6-4)）

<a id="s19-3"></a>
### 19.3 -O2（既定）

- ゼロページへの自動配置
- **展開**：1 か所からしか呼ばれない関数と、`#[inline]` を付けた関数だけを展開する。2 か所以上から呼ばれる関数は展開しない
- 関数ごとの引数の渡し方の変更
- **不要な書き込みの削除**：後で読まれずに上書きされるだけの書き込みを消す。ループをまたぐ場合も対象とする。`shared` 変数、`io` 変数、アドレスを取った変数、アセンブリから参照される変数への書き込みは対象外
- **共通部分のくくり出し**：同じ形の命令の並びを、小さなサブルーチンにまとめる。何度も回るループの本体に直接ある命令の並びは対象外（ループから呼ぶ関数の中は対象）
- `for` で直接回す `digits()` の展開（[5.5節](#s5-5)）
- 構造体の戻り値の最初のフィールドを、レジスタでも返す
- 順番に依存しないループの自動の逆順化
- **ループの配置**：何度も回るループの中の分岐がページ境界をまたがないように、関数やコードの並び順を入れ替える（6502 では、分岐がページ境界をまたぐと 1 サイクル余分にかかる）。空きのバイトは入れない

関連 Q&A：[M-9](#qa-m9)、[N-9](#qa-n9)

<a id="s19-4"></a>
### 19.4 -Os

- `-O2` のすべて。ただし共通部分のくくり出しは行わない
- **展開の拡大**：2 か所以上から呼ばれる小さな関数も、ループの中で呼ばれていれば展開する。`#[cold]` の関数は展開しない
- **ループの配置**：並び順の入れ替えでそろえられない場合は、空きのバイトを入れてでもページ境界をそろえる

関連 Q&A：[L-5](#qa-l5)

<a id="s19-5"></a>
### 19.5 段階にかかわらず行うこと

```asm
; draw() の最後が print_score() の呼び出しの場合（どの段階でも）
        jmp print_score         ; jsr print_score と rts の代わり（1 バイト・9 サイクル減る）
```

- 末尾呼び出しの `jmp` への置き換え（[7.7節](#s7-7)）
- 値を使わない I/O の読み込みに `bit` を使う（[11.3節](#s11-3)）
- 初期値が 0 の変数を `stz` で初期化する（[4.6節](#s4-6)）
- `cycles()`・`io_span()` の中のページ境界の調整（[12.1節](#s12-1)）

## 20. 標準ライブラリと組み込み関数

<a id="s20-1"></a>
### 20.1 組み込み関数

```
fn main() {
    let t: Option<u8> = None;           // use なしで使える
    delay(100);
    comptime if target.has_irq {
        irq_enable();
        comptime if target.cpu == Cpu::W65C02S { wait_interrupt(); }
    }
}

comptime fn half_sine(i: int) -> i8 {   // 数学関数も use なしで使える
    round(sin(i as real * PI / 128.0) * 63.0) as i8
}
```

`use` なしで使える名前です。

| 名前 | 意味 | 節 |
|---|---|---|
| `Option`、`Some`、`None` | 値があるか、ないか | [3.11](#s3-11) |
| `irq_enable()`、`irq_disable()` | 割り込みの許可（`cli`）と禁止（`sei`）。`irq_enable()` は `irq` が `none` のターゲットでは使えない | [10.3](#s10-3)、[16.4](#s16-4) |
| `wait_interrupt()` | 割り込み待ち（`wai`。W65C02S で、`irq` が `none` でないターゲットのみ） | [12.3](#s12-3) |
| `delay(n)` | 最低 n サイクル待つ | [12.1](#s12-1) |
| `size_of(T)` | 型の大きさ | [13.5](#s13-5) |
| `include_bin(パス, offset = n)` | ファイルの中身 | [13.4](#s13-4) |
| `target`、`build` | ターゲット定義とビルドの設定 | [13.5](#s13-5) |
| `Cpu` | CPU の品種の列挙型（`Cpu::W65C02S` など） | [16.2](#s16-2) |
| `strbuf::new()` | 空の文字列バッファ | [3.9](#s3-9) |
| `sin` `cos` `sqrt` `round` `floor` `abs`、`PI` | コンパイル時の数学関数と円周率（`comptime fn` の中と、コンパイル時に計算される式だけで使える） | [13.2](#s13-2) |

関連 Q&A：[M-19](#qa-m19)

<a id="s20-2"></a>
### 20.2 core

```
use core::{us, mul8, divmod8, Nz8};

delay(us(40));
let p: u16 = mul8(a, b);
let qr = divmod8(n, 10);                // 定数の 10 はそのまま Nz8 として渡せる
show(qr.q, qr.r);
if let Some(d) = Nz8::check(k) { let r = divmod8(n, d).r; show(0, r); }
let w = core::mul16(x, y);              // use しなくても core::名前 で書ける
```

| 名前 | 型 | 意味 |
|---|---|---|
| `us(t)` | `comptime fn(int) -> int` | マイクロ秒をサイクル数に変換する（[12.2節](#s12-2)） |
| `mul8(a, b)` | `fn(u8, u8) -> u16` | 掛け算。bind した `mul` の実装の関数（[20.4節](#s20-4)） |
| `mul16(a, b)` | `fn(u16, u16) -> u32` | 同上 |
| `Nz8`、`Nz16` | 範囲型 | 0 でない値（`range Nz8 = 1..256;`、`range Nz16 = 1..65536;`） |
| `QR8`、`QR16` | 構造体 | 商と余り（`QR8 { q: u8, r: u8 }`、`QR16 { q: u16, r: u16 }`） |
| `divmod8(a, b)` | `fn(u8, Nz8) -> QR8` | 商と余り |
| `divmod16(a, b)` | `fn(u16, Nz16) -> QR16` | 同上 |

- `core` の名前は、`use` しなくても `core::mul8(x, y)` のように書けます。名前だけで書くには `use core::名前;` で取り込みます。
- 割る数が定数なら、そのまま渡せます（0 ならエラー）。変数は `Nz8::check(n)`・`Nz16::check(n)` で確かめてから渡します（[5.6節](#s5-6)）。
- コンパイル時の数学関数（`sin`、`PI` など）は組み込みの名前で、`core` には含みません（[20.1節](#s20-1)）。

関連 Q&A：[M-5](#qa-m5)、[M-19](#qa-m19)

### 20.3 bcd と text

```
use bcd;
use text::u8_to_dec;
let s: strbuf<3> = u8_to_dec(n);        // 数値を 10進の文字列にする（結果は呼び出し先の結果領域。15.3節）
print(s.as_str());
let v: u16 = bcd::to_u16(SCORE);        // bcd16 → u16
let b: bcd32 = bcd::from_u16(v);        // u16 → bcd32（5 桁まで入る）
```

| モジュール | 主な内容 |
|---|---|
| `bcd` | BCD と整数の変換（下の表）、`digits()` の実装 |
| `text` | 数値を 10進・16進の文字列にする関数、`strbuf` の操作 |

| `bcd` の関数 | 型 | 意味 |
|---|---|---|
| `to_u8(x)` | `fn(bcd8) -> u8` | BCD を整数にする |
| `to_u16(x)` | `fn(bcd16) -> u16` | 同上 |
| `to_u32(x)` | `fn(bcd32) -> u32` | 同上 |
| `from_u8(n)` | `fn(u8) -> bcd16` | 整数を BCD にする（3 桁） |
| `from_u16(n)` | `fn(u16) -> bcd32` | 同上（5 桁） |

- BCD と整数の変換は、`as` ではなく、これらの関数で行います（[3.14節](#s3-14)）。

### 20.4 標準のインターフェース

```
interface console {                     // <ax65>/std/console.ax65
    fn putc(c: char);
    fn getc() -> char;
    fn poll() -> Option<char>;
}

interface screen {                      // <ax65>/std/screen.ax65
    const WIDTH: u8;
    const HEIGHT: u8;
    fn clear();
    fn put(x: u8, y: u8, c: char@screen);
}

interface keyboard {                    // <ax65>/std/keyboard.ax65
    fn poll() -> Option<char>;          // char の値は実装ごとに決める（v2 の hexmon_keyboard では HEXPAD のキーコード）
}

interface sound {                       // <ax65>/std/sound.ax65
    fn tone(period: u16);               // 周期 period の方形波を鳴らし続ける（周波数 = クロック ÷ (2 × (period + 2))）
    fn off();                           // 音を止める
}

interface timer {                       // <ax65>/std/timer.ax65
    fn ticks() -> u16;                  // 起動からの時間（実装ごとの単位）
    const TICKS_PER_SECOND: u16;
}

interface mul {                         // <ax65>/std/mul.ax65
    fn mul8(a: u8, b: u8) -> u16;
    fn mul16(a: u16, b: u16) -> u32;
}
```

```
// targets/v3.target（メモリに余裕があるので、表を使う掛け算にする）
bind mul = mul_table;
```

- 実装は、自分のマシン用に `hw/` などに書くか、標準ライブラリにある実装（`ps2_keyboard` など）を bind します。
- `mul` の標準の実装は次の 2 つです。ターゲット定義で `mul` を bind しなければ `mul_shift` を使います。

| 実装 | 方式 | 速さの目安 |
|---|---|---|
| `mul_shift`（既定） | シフトと足し算 | `mul8` 約 100〜150 サイクル、`mul16` 約 500〜700 サイクル |
| `mul_table` | 表を使う。速いが、表の分のメモリを使う | `mul_shift` より速い |

- `core::mul8`・`core::mul16` は、bind した `mul` の実装の関数そのものです（呼び出しは直接の `jsr`）。

<a id="s21"></a>
## 21. 将来の拡張

仕様に余地だけを残しておくものです。

- Apple II 級のメモリを超える拡張（バンク切り替え）
- セルフホスト（Apple II 級のマシンの上で ax65 を動かす）
- ROM ルーチンの宣言を、エミュレータで実測して照合するツール
- 速さの要らない関数を、1 命令 1〜2 バイトの小さな中間コードにして、解釈ルーチンで実行する仕組み（Apple II の SWEET16 と同じ考え方）。関数ごとに属性で指定する形を想定する。コードは 2〜3 倍小さくなるが、5〜10 倍遅くなる

定数の文字列を表にまとめる、0 終端の文字列の後ろを共有する、データを圧縮する、といった大きさの工夫は、プログラマが必要に応じて行うものとし、言語の仕様には入れません。

<a id="appA"></a>
## 付録A 文法の要約

構文のおおまかな形です（`?` は省略可、`*` は 0 回以上のくり返し、`|` はどちらか）。`リスト(X)` は、`X` をカンマで区切って 0 個以上並べたもので、最後のカンマは省略できます（`X ("," X)* ","?` か空）。

```
リスト(X)      = ( X ( "," X )* ","? )?

プログラム     = 項目*
項目           = 属性* pub? ( use宣言 | const宣言 | static宣言 | shared宣言 | io宣言
                 | fn宣言 | struct宣言 | enum宣言 | range宣言 | flags宣言 | fnset宣言
                 | type宣言 | interface宣言 | impl宣言 | init | comptime_if | comptime_assert )

use宣言        = "use" パス ( "::" "{" リスト(名前) "}" )? ( "as" (名前 | "_") )? ";"
const宣言      = "const" 名前 ":" 型 "=" 式 ";"
static宣言     = "static" 名前 ":" 型 ( "=" 式 )? ";"
shared宣言     = "shared" ( "(" ("irq"|"main"|"nmi") ")" )? 名前 ":" 型 "=" 式 ";"
io宣言         = "io" ( "(" ("in"|"out"|"rmw") ")" )? 名前 ":" 型 "@" 式 ";"
fn宣言         = ("const"|"comptime")? "fn" 名前 "(" リスト(引数) ")" ("->" 型)? ブロック
                 | "asm" "fn" 名前 "(" リスト(引数) ")" ("->" 型)? "{" アセンブリ "}"
                 | "extern" "fn" 名前 "(" リスト(extern引数) ")" ("->" 型 "in" レジスタ)? "@" 式
                   "clobbers" "(" リスト(レジスタ) ")" "stack" "(" 式 ")" ";"
引数           = 名前 ":" 型
extern引数     = 名前 ":" 型 "in" レジスタ
レジスタ       = "A" | "X" | "Y" | "AX" | "C" | "flags"
struct宣言     = "struct" 名前 "{" リスト(名前 ":" 型) "}"
enum宣言       = "enum" 名前 "{" リスト(名前 ("=" 式)?) "}"
range宣言      = "range" 名前 "=" 式 (".."|"..=") 式 ";"
flags宣言      = "flags" 名前 "{" リスト(名前) "}"
fnset宣言      = "fnset" 名前 "=" "{" リスト(名前) "}" ";"
type宣言       = "type" 名前 "=" 型 ";"
interface宣言  = "interface" 名前 "{" ( "fn" 名前 "(" リスト(引数) ")" ("->" 型)? ";"
                 | "const" 名前 ":" 型 ";" )* "}"
impl宣言       = "impl" 名前 "{" 項目* "}"
init           = "init" ブロック

型             = 名前 | パス | "[" 型 ";" 式 "]" | 型 "[" 式 "]" | "ptr" "<" 型 ">" | "Option" "<" 型 ">"
                 | "strbuf" "<" 式 ">" | 型 "@" 名前
ブロック       = "{" 文* 式? "}"
文             = "let" (名前|"_") (":" 型)? ("=" 式)? ";" | 式 ";" | 項目
式             = リテラル | パス | 式 二項演算子 式 | 単項演算子 式 | 式 "as" 型 | 式 "?"
                 | 式 "." 名前 ( "(" リスト(引数式) ")" )? | 式 "[" 式 "]" | 式 "(" リスト(引数式) ")"
                 | "(" 式 ")" | 範囲式 | 構造体の値 | 配列の値
                 | ブロック | if式 | match式 | loop式 | while式 | for式
                 | "atomic" ブロック | ("cycles"|"io_span"|"max_cycles") "(" 式 ")" ブロック
                 | "asm" ( "(" リスト(受け渡し) ")" )? "{" アセンブリ "}"
                 | "unsafe" "asm" "(" リスト(性質) ")" "{" アセンブリ "}"
                 | "break" ラベル? 式? | "continue" ラベル? | "return" 式?
単項演算子     = "-" | "!" | "&"
引数式         = 式 | 名前 "=" 式
範囲式         = 式 (".."|"..=") 式
構造体の値     = パス "{" 名前 ":" 式 ( "," 名前 ":" 式 )* ( "," ( ".." 式 )? )? "}"
配列の値       = "[" リスト(式) "]" | "[" 式 ";" 式 "]" | "[" "for" 名前 "in" 範囲式 "=>" 式 "]"
受け渡し       = "in" レジスタ "=" 式 | "out" レジスタ "->" 名前
if式           = "if" ( 式 | "let" パターン "=" 式 ) ブロック ( "else" (if式 | ブロック) )?
match式        = 属性* "match" 式 "{" ( パターン ("|" パターン)* "=>" (式 "," | ブロック ","?) )* "}"
for式          = 属性* (ラベル ":")? "for" 名前 "in" 式 ブロック
while式        = 属性* (ラベル ":")? "while" 式 ブロック
loop式         = (ラベル ":")? "loop" ブロック
comptime_if    = "comptime" "if" 式 ブロック ( "else" ブロック )? | "comptime" "match" 式 "{" ... "}"
comptime_assert= "comptime" "assert" "(" 式 "," 文字列 ")" ";"
属性           = "#[" 名前 ( "(" 属性の引数 ")" )? "]"
```

- `in` によるレジスタの指定（`extern引数`、戻り値の `in`）は、`extern fn` の宣言にだけ書けます。`C` は戻り値（`bool`）だけに、`flags` は `clobbers` だけに使います（[7.6節](#s7-6)）。
- `asm fn` の本体は、ブロックではなくアセンブリです（[7.4節](#s7-4)）。
- 従来の配列の型 `T[N1][N2]` は `[[T; N2]; N1]` です（左の添字が外側。[3.8節](#s3-8)）。
- 名前付きの引数（`名前 = 式`）は、`include_bin` の `offset` だけに使います（[13.4節](#s13-4)）。
- 構造体の値は、`if` の条件の中には書けません（[6.2節](#s6-2)）。
- `impl` の中の、インターフェースの関数と定数には `pub` を書けません（[8.4節](#s8-4)）。
