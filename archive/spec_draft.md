## 1. 目的と設計方針

### 1.1 目的

自作の 6502 マシン専用のプログラミング言語です。KIM-1 級（RAM 1KB 前後）から Apple I 級、Apple II 級（RAM 48KB 程度）へと拡張していくマシンを対象とします。既存のマシンとの互換性は求めません。汎用性は目標とせず、6502 で効率よく、安全に動くプログラムを書けることだけを目標とします。

### 1.2 設計方針

この言語の基本方針は次のとおりです。

1. **ハードウェアの制約を、言語の制約で抑える。** 6502 で高くつく操作は、書けないようにするか、高くつくことが見える形でしか書けないようにします。
2. **検査はすべてコンパイル時に行う。** 実行時の検査のコストは、プログラマが明示した場所でしか払いません（Rust の方針と同じ）。
3. **コンパイラはプログラム全体を一度に解析する。** プログラムは 64KB 以内、ヒープなし、スレッドなし（並行して動くのは割り込みだけ）という前提により、呼び出しグラフ、スタック使用量、レジスタの使用状況などをすべて静的に求めます。
4. **最適化はプログラムの意味を変えない。** 最適化の段階（`-O0`〜`-O2`、`-Os`）によって、生成されるコードの大きさと速さは変わりますが、プログラムの意味は変わりません。既定は `-O2` です。配置と命令を最も予測しやすくしたい場合は `-O0` を使います（12章）。サイクル数を保証するブロック（`cycles()` など）とインラインアセンブリが参照する変数は、どの段階でも配置が変わりません。
5. **コンパイラが行った判断は、レポートで見えるようにする。** 変数の配置、レジスタの割り当て、`match` の実装方法、スタック使用量などをレポートに出力します。
6. **検査できない部分は、1か所に閉じ込める。** ROM ルーチンの宣言（`extern`）、範囲検査の省略（`unchecked()`）など、プログラマが正しさに責任を持つ部分は、名前で検索できる形にします（Rust の `unsafe` に相当）。

"コンパイルが通ったプログラムは、スタックがあふれず、範囲外のアクセスをせず、割り込みとのデータ競合を起こさない" ことを目指します。

### 1.3 対象 CPU

| CPU | 扱い |
|---|---|
| 65C02（W65C02S を含む） | 基本の対象。65C02 の追加命令を前提にしたコードを生成する |
| NMOS 6502 | ターゲット定義で選択できる。コンパイラが命令を選び直し、NMOS 固有の落とし穴を避ける（10章） |

言語の意味は CPU によって変わりません。CPU によって変わるのは、生成されるコードの速さと大きさだけです。

### 1.4 コンパイラの形態

コンパイラは、まず PC 上で動くクロスコンパイラとして作ります。将来、Apple II 級のマシンでのセルフホストを検討できるよう、文法は小さく保ちます。

## 2. ターゲット定義（概要）

マシンごとの違いは、ターゲット定義ファイルに閉じ込めます。同じソースでも、ターゲット定義を替えればコンパイル結果が変わります（例：Apple II 級では通り、KIM-1 級では「RAM が 300 バイト足りない」というエラーになる）。

ターゲット定義には、次の項目を書きます。詳しい書式は議題12で決定します。

| 項目 | 内容 |
|---|---|
| CPU | `6502`、`65c02`、`w65c02s` など（品種まで区別する） |
| クロック周波数 | `us()` による時間指定に使う |
| メモリ配置 | RAM と ROM のアドレス範囲 |
| ゼロページ | プログラムが使ってよい範囲（モニタが使う範囲を除く） |
| スタック予算 | ページ $01 のうち、プログラムが使ってよいバイト数 |
| 実行の形 | RAM に読み込んで実行するか、ROM から実行するか |
| 割り込みベクタ | ハードウェアのベクタに直接書くか、モニタが用意する RAM 上のベクタに書くか（その場所） |
| 割り込みの間隔 | 指定すれば、割り込み処理の時間の検査に使う |
| 文字の変換表 | `@変換表` で使う変換表（3.6節） |
| bind | インターフェースの実装の選択（`bind console = hw.acia_console;`）。bind されていることが「その機能がある」ことを意味する（10B.4節） |
| 定数 | コードを伴わない性質（`const screen_width = 40;` など）。`target.名前` で読める |

I/O レジスタのアドレスは、ターゲット定義ではなく、bind される実装モジュールの中で宣言します。

#### ターゲット定義の書き方

ターゲット定義は ax65 と同じ文法で書きます（`const` に式が使え、`bind` のモジュール名を検査できるため）。マシンの成長に合わせ、`extends` で前の構成を引き継いで差分だけを書けます。

```
// targets/kim.target
target kim {
    cpu    = w65c02s;
    clock  = 1_000_000;
    ram    = $0000..$03FF;
    zp     = $00..$EF;
    stack  = 64;
    run    = ram;
    bind console = hw.led_console;
    const led_digits = 6;
}

// targets/v3.target
target v3 extends v2 {
    clock = 2_000_000;
    bind screen   = hw.v3_screen;
    bind keyboard = std.ps2_keyboard;
    const screen_width = 40;
}
```

#### メモリの区画

```
region zp    = $00..$FF;
region stack = $0100..$01FF;
region ram   = $0200..$1FFF;
region io    = $8000..$8FFF;
region rom   = $E000..$FFFF;
reserve $24..$2B;                 // モニタが使う場所（使用禁止）
place const in $F000..$F7FF;      // 必要なら種類ごとの置き場所を指定
```

- `@` で指定したアドレスが区画の外や `reserve` の中ならエラーです。I/O 変数のアドレスは `io` 区画の中でなければなりません。
- コンパイラが作るものは、コード、定数、初期値（起動時にコピーする元データ）、変数の4種類です。

| | コード・定数・初期値 | 変数 |
|---|---|---|
| `run = ram` | `ram` 区画（`load` のアドレスから） | `ram` 区画 |
| `run = rom` | `rom` 区画 | `ram` 区画 |

- 区画ごとの使用量をレポートに出します。

#### 起動と終了

- `run = ram` では `load = $0300;` で読み込み先を指定し、モニタからそのアドレスを実行します。`run = rom` では、リセットベクタ（$FFFC）に起動処理のアドレスを書きます。
- `main` が終わったときの動作を `exit` で指定します。

| 指定 | 動作 |
|---|---|
| `exit = monitor($FF1F);` | モニタの入口へ `jmp` する |
| `exit = halt;` | その場で止まる（無限ループ） |
| `exit = never;` | `main` は終わってはならない。終わりうる場合はコンパイルエラー |

#### 割り込みベクタ

| 指定 | 意味 |
|---|---|
| `irq = hw;` | ROM のベクタに直接書く（`run = rom` のとき） |
| `irq = indirect($0300);` | ROM が `jmp ($0300)` で飛ぶ形。$0300 に処理のアドレスを書く |
| `irq = jump($0300);` | ROM が `jmp $0300` で飛ぶ形。$0300 に `jmp` 命令ごと書く |

- `nmi` も同じ形で指定します。`indirect` と `jump` は起動処理の中で、割り込みを止めた状態で書き込みます。

#### 出力形式の既定

```
output = [woz, sym, lst];
```

#### プロジェクトファイル

```
// ax65.proj
project mygame {
    main    = src/main.ax65;
    paths   = [src, hw];
    targets = [kim, v2, v3];      // --all-targets の検査対象
    default = v3;
}
```

#### コマンドライン

```
ax65 build                                  # 既定のターゲットでコンパイル
ax65 build -t v2                            # ターゲットを指定
ax65 build -t v3                            # 最適化は既定の -O2
ax65 build -t v3 -O0                        # 最適化をしない（-O1、-Os も指定できる）
ax65 build -t v3 -D debug                   # build.debug を true にする
ax65 build -t v3 --bind console=sim.console # bind を一時的に差し替える（エミュレータでの試験など）
ax65 check --all-targets                    # プロジェクトの全ターゲットで型まで検査
```

## 3. 型

### 3.1 整数型

| 型 | 大きさ | 範囲 |
|---|---|---|
| `u8` | 1バイト | 0〜255 |
| `i8` | 1バイト | -128〜127 |
| `u16` | 2バイト | 0〜65535 |
| `i16` | 2バイト | -32768〜32767 |
| `u24` / `i24` | 3バイト | 0〜16777215 / -8388608〜8388607 |
| `u32` / `i32` | 4バイト | 0〜4294967295 / -2147483648〜2147483647 |
| `bcd8` / `bcd16` / `bcd32` | 1 / 2 / 4バイト | 10進 2 / 4 / 8 桁（3.12節） |

規則は次のとおりです。

- **暗黙の変換をしない。** C のように 8 ビットの値を自動で 16 ビットに広げることはしません。`u8` と `u16` を混ぜた式は、明示的な変換（`as`）がなければエラーです。16 ビットの計算は、必ずソース上で見えます。
- **符号の混在をしない。** 符号付きと符号なしを混ぜた比較や代入は、明示的な変換がなければエラーです。
- **例外：`u8 + i8 → u8`。** 位置（`u8`）に変化量（`i8`）を足す操作だけは、明示的な変換なしで許可します。命令は `ADC` 1つで済みます。
- **あふれは一周して戻る。** 符号付き・符号なしのどちらも、あふれた場合は一周して戻ると定義します（C と異なり、符号付きのあふれも未定義動作ではありません）。

符号付きで追加のコストがかかるのは、大小比較、8 ビットから 16 ビットへの拡張、右シフト、割り算と表示だけです。足し算と引き算は、符号の有無にかかわらず同じ命令です。

### 3.2 bool

`bool` は真偽値の型です。if や while の条件には `bool` だけを書けます（数値をそのまま条件にはできません）。比較の結果はフラグに入り、分岐命令に直接つながるため、値として0や1をしまうことは通常ありません。関数の戻り値としてはキャリーフラグで返します。

### 3.3 範囲型

決まった範囲の値だけを取る型です。中身は `u8` です。

```
type eid = 0..15;               // 0〜15 の値だけを取る型
```

- **名前による型の区別**：同じ範囲でも、宣言ごとに別の型です。`type eid = 0..15;` と `type iid = 0..15;` は混ぜて使えません。
- **別名**：`type eid = table.idx;` のように、既存の型に別名を付けた場合は同じ型です。共有したいときは別名で明示します。
- **値の作り方**：範囲型の値は、範囲を必ず守れる方法でしか作れません。

| 作り方 | 例 | 実行時のコスト |
|---|---|---|
| for で回す | `for e in eid { }` | なし |
| 定数 | `enemies[3]`（範囲外ならコンパイルエラー） | なし |
| 範囲を確かめる変換 | `eid.check(n)`（結果は `eid?`） | 比較と分岐 |
| 下位ビットだけを取る変換 | `eid.wrap(n)`（範囲が2のべき乗のとき） | `and` 1命令 |
| 検査の省略 | `eid.unchecked(n)` | なし（プログラマの責任） |

- **演算**：範囲型の値に演算すると、結果は `u8` に戻ります。
- **検査の要否**：範囲の検査が必要かどうかはコンパイラが型で判断します。プログラマが決めるのは、検査をどこで行うか（引数を範囲型にして呼び出し元で行うか、関数の中で行うか）だけです。

### 3.4 列挙型

```
enum dir { up, down, left, right }                  // up=0、down=1、left=2、right=3
enum cmd { reset = $FF, read = $10, write = $11 }   // 値の明示もできる
```

- 中身は `u8` です。
- 範囲型と同じく、宣言ごとに別の型で、for で回せ、`match` で網羅性が検査され、`dir.check(n)` で `u8` から変換できます（結果は `dir?`）。列挙型から `u8` へは `d as u8` で変換します。
- 0 から連続した値の列挙型だけが、配列の添字に使えます。
- 値ごとに別のデータを持つ列挙型（Rust の enum のようなもの）は採用しません。必要な場合は、列挙型と構造体を組み合わせます。

### 3.5 ビットフラグ型

```
flags joy { up, down, left, right, fire }   // up=ビット0 … fire=ビット4
```

- 各ビットに名前を付けた型です。8 ビットまでは `u8`、16 ビットまでは `u16` が中身になります。
- 操作は 6502 の命令にそのまま対応します。

| 操作 | 書き方 | 対応する命令 |
|---|---|---|
| 調べる | `j.fire`、`j.has(up \| left)` | `and`（または `bit`） |
| 立てる | `j.set(fire)` | `ora` |
| 消す | `j.clear(fire)` | `and` |
| 反転する | `j.flip(fire)` | `eor` |

- I/O 変数の型にも使えます（`io in joy JOYPORT @ $6001;`）。`io rmw` のレジスタでは `tsb` と `trb` を使います。

### 3.6 文字型と文字の変換表

- `char` は文字の型で、`u8` とは別の型です。数値として扱うときは `c as u8` と書きます。
- 何も指定しない文字・文字列は ASCII です。ソースの意味がターゲットによって変わることはありません。ASCII 以外の文字を変換表なしで書くとエラーです。
- `@変換表` を付けると、ターゲット定義の変換表で、コンパイル時に機種の文字コードに変換します。実行時の変換処理はありません。

```
// ターゲット定義の中の変換表の例（Apple II 級の画面）
encoding screen {
    ' '..'?' => $A0..$BF;
    '@'..'_' => $C0..$DF;
}
```

- 変換表にない文字を使うとコンパイルエラーです。
- 変換表は文字以外のバイトにも使えます（7セグメント LED の点灯パターンなど）。
- 変換表ごとに別の型になります（`char@screen`、`str@screen`）。ASCII の文字列を受け取る関数に画面用の文字列を渡すとエラーです。

### 3.7 文字列

| 書き方 | 中身（"HI" の場合） | 型 |
|---|---|---|
| `"HI"` | `48 49` | `char[2]`（長さは型が持つ。長さも終端もない） |
| `p"HI"` | `02 48 49` | `str`（長さ付き、最大255文字） |
| `z"HI"` | `48 49 00` | 0終端の文字列 |
| `hi"HI"` | `48 C9` | 最上位ビット終端の文字列 |

- 変換表の指定と組み合わせられます（`p"SCORE"@screen`、`z"OK"@serial`）。
- 標準の文字列型 `str` は長さ付きです。長さ付きは 0終端と同じ速さで出力でき、長さがすぐわかり、終端の書き忘れによる読みすぎが起きません。
- `z` と `hi` は、モニタの ROM ルーチンなど、その形式を要求する相手とのやり取りに使います。
- 書き換える文字列には、容量を決めた文字列バッファ `strbuf<N>`（N は 255 以下）を使います。`push` は満杯のとき `false` を返し、あふれは起きません。
- ヒープがないため、文字列をつなげて新しい文字列を作る操作はありません。

### 3.8 構造体

```
struct enemy { u8 x; u8 y; u8 dir; u8 hp; }
```

- 構造体の配列の並べ方は 3.9 節のとおりです。
- 関数の戻り値として、構造体を値で返せます（5.3節）。

### 3.9 配列

#### 要素数と添字

- 配列の要素数は 256 以下です。
- 添字の型は次のとおりです。

| 配列の宣言 | 添字に使える型 |
|---|---|
| `u8 table[256];` | `u8`（どの値でも範囲内なので検査不要） |
| `u8 table[16];` | `table.idx`（自動で作られる範囲型） |
| `enemy enemies[eid];` | `eid`（範囲型または列挙型） |

- 範囲外になりうる値（ただの `u8` など）を、長さ 256 未満の配列の添字に使うとコンパイルエラーです。

#### メモリ上の並べ方

- **構造体の配列は、フィールドごとの配列にするのが標準**です。`enemies[i].y` と書けば、`y` だけを並べた配列の i 番目を読みます。番号をそのまま X に入れて1命令で読め、要素数も 256 まで扱えます。
- **u16 とポインタの配列は、下位バイトの配列と上位バイトの配列に分けるのが標準**です。
- 1要素を連続したバイト列として並べる必要がある場合（ディスクや通信のデータ形式、ハードウェアが決めた表など）は、`packed` を付けます。`packed` の配列は、全体で 256 バイト以下です。
- フィールドごとの配列では、1要素を指すポインタは作れません。代わりに添字を渡します。

#### 256バイトを超えるデータ

- 256 バイトを超えるデータは、`u8 buf[4][256]` のようなページ単位の配列として宣言します。コンパイラはページの先頭（アドレスの下位バイトが $00）に配置します。
- 行の長さが 2 のべき乗でない 2 次元配列（`u8 map[24][40]` など）には、各行の先頭アドレスの表をコンパイラが自動で作り（下位・上位に分けて配置）、掛け算を使わずにアクセスします。表のメモリ使用量はレポートに出ます。

### 3.10 ポインタ

- ポインタ型は `ptr<T>` と書きます。ポインタ型の変数は自動でゼロページに置かれます。ゼロページの空きを超えたらコンパイルエラーです。
- ポインタでできる操作は、6502 で安く実行できるものに限ります。

| 操作 | 書き方 | 対応する命令 |
|---|---|---|
| 指す先を読み書き | `p[i]`（i は u8） | `lda (p),y`。i が 0 なら 65C02 の `lda (p)` |
| packed 構造体のフィールド | `p->hp` | `ldy #位置` と `lda (p),y` |
| 次のページへ進める | `p.page += 1` | `inc p+1` |
| アドレスを代入 | `p = &table` | 下位・上位の2回の書き込み |
| 一致の比較 | `p == q` | 2バイトの比較 |
| 任意の数を足す | `p.add(n)` | 16ビットの足し算（明示が必要） |

- ヌルポインタはありません。標準のポインタは必ず有効な場所を指します。「指していないかもしれない」場合は `ptr<T>?` を使います（3.11節）。
- ローカル変数のアドレスの扱いは 4.5 節のとおりです。

### 3.11 Optional 型（`?` 付きの型）

- どの型にも `?` を付けて、「値があるか、ないか」を表せます（Swift や Java の Optional、Rust の Option と同じ）。「なし」は `none` と書きます。
- 中身を使うには、`if let` などで有無を確かめる必要があります。確かめずに使うとコンパイルエラーです。

```
fn poll_key() -> u8? {          // キーが押されていれば文字を、なければ「なし」を返す
    if KBD_READY { return KBD_DATA; }
    return none;
}

fn main_loop() {
    if let c = poll_key() {     // 値があれば c として受け取る
        putc(c);
    }
}
```

- `?` を付けなければ、追加のコストはかかりません。
- 「ある・なし」の表し方はコンパイラが型ごとに選び、使える値の範囲は狭まりません。

| 場面 | 「ある・なし」の表し方 |
|---|---|
| 戻り値 | キャリーフラグ（値は通常どおり A などで返す） |
| 使われない値がある型（範囲型など）の変数 | 使われない値（$FF など）を「なし」に流用。追加のメモリなし |
| すべての値が有効な型（u8 など）の変数 | 「ある・なし」用にもう1バイト使う |

- 範囲型との役割の違い：範囲型は「値が決まった範囲に収まっているか」、`?` は「値があるか、ないか」を表します。

### 3.12 演算

#### ビット演算とシフト

| 演算 | 書き方 | 対応する命令 |
|---|---|---|
| AND / OR / XOR | `a & b`、`a \| b`、`a ^ b` | `and`、`ora`、`eor` |
| ビット反転 | `~a` | `eor #$FF` |
| 定数回のシフト | `a << 3`、`a >> 3` | `asl` / `lsr` の繰り返し（符号付きの右シフトは符号を保つ） |
| 変数回のシフト | `a.shl(n)`、`a.shr(n)` | ループ（明示が必要） |
| キャリーを通したローテート | `a.rol()`、`a.ror()` | `rol`、`ror` |

- `<<` と `>>` の右側には定数だけを書けます。回数が変数の場合は `shl()` / `shr()` で明示します。
- 多バイトのシフトは、コンパイラが `asl` と `rol` などを組み合わせて作ります。

#### あふれの扱い

| 書き方 | 意味 |
|---|---|
| `a + b`、`a - b` | 一周して戻る（既定） |
| `a.checked_add(b)`、`a.checked_sub(b)` | あふれたら「なし」（結果は `?` 付き。追加コストは分岐1つ） |
| `a.sat_add(b)`、`a.sat_sub(b)` | あふれたら最大値・最小値で止まる |

#### 多バイトの整数

- `u24`・`i24`・`u32`・`i32` は、明示的に書いたときだけ使える型です。キャリーのつなぎはコンパイラが作ります。
- 暗黙の変換をしない規則は、u16 と同じく適用します。

#### 10進演算（BCD）

- `bcd8`・`bcd16`・`bcd32` は、1バイトに10進2桁を入れる型です（$25 が「25」）。
- 使える演算は足し算・引き算と大小比較だけです。`sed` と `cld` はコンパイラが前後に入れます。
- 他の整数型と混ぜた計算はエラーです。変換は `as` で明示します（割り算に近いコストがかかる）。
- 1桁ずつ取り出す `digits()` で、表示を簡単にできます。
- `digits()` は、標準では全桁を結果領域に作ってから返します。速さ優先の最適化（`-Os`、12章）では、`for d in x.digits()` のように直接回す場合に限り、結果領域を作らずに、1桁ずつ取り出す処理をループの中に展開します（コードは少し大きくなる）。
- 65C02 は割り込み時に自動で10進モードを解除します。NMOS では、割り込み処理の入口に `cld` を入れます（10章）。

#### 掛け算と割り算

- 定数の掛け算は、どんな定数でも `*` で書けます。コンパイラがシフトと足し算に展開し、命令数をレポートに出します。
- 割り算の演算子 `/` と `%` は、2のべき乗の定数だけに使えます（シフトと `and` になる）。
- それ以外の掛け算・割り算は、ライブラリの関数（`mul8`、`mul16`、`divmod8`、`divmod16` など）で明示します。
- 割り算の関数の結果は `?` 付きの型で、0で割った場合は「なし」になります。
- メモリに余裕のあるターゲットでは、表を使った高速な掛け算のライブラリに切り替えられます（関数名と使い方は同じ）。

## 4. 変数と記憶域

### 4.1 記憶域の種類

| キーワード | 置き場所 | 用途 |
|---|---|---|
| なし（関数の外） | RAM の固定アドレス | グローバル変数 |
| なし（関数の中） | RAM の固定アドレス（他の関数と重ねて使う） | ローカル変数 |
| `static`（関数の中） | RAM の固定アドレス（重ねない） | 呼び出しをまたいで値を保つ変数 |
| `zp` | ゼロページ | ポインタや、よく使う変数 |
| `const` | ROM（またはプログラム本体） | 表や文字列などの読み取り専用データ |
| `io` | 指定したアドレス | I/O レジスタ（7章） |
| `shared` | RAM（重ねない） | 割り込み処理とメインで共有する変数（8.4節） |
| `noinit` | RAM（重ねない） | 起動時に初期化しない変数 |

### 4.2 ゼロページ

- ポインタ型の変数は、自動でゼロページに置きます。
- それ以外の変数は、既定では `zp` と明示したものだけをゼロページに置きます。
- `-O1` 以上（既定の `-O2` を含む）では、よく使う変数をコンパイラが自動でゼロページに移します。`-O0` では移しません。その際の規則は次のとおりです。
  - `zp` の変数とポインタを置いた後の、残りの空きだけを使う（オプションによってゼロページ不足のエラーが出ることはない）
  - `cycles()` ブロックの中で使う変数は対象外
  - `io` 変数は対象外。`shared` 変数は `fixed` を付ければ対象外にできる
  - インラインアセンブリから参照される変数は対象外（命令の長さとサイクル数がオプションで変わらないようにするため）
  - 移した変数と、節約できる見込みのサイクル数・バイト数をレポートに出す

### 4.3 ローカル変数の重ね合わせ

- 再帰がないため、ローカル変数はスタックではなく固定アドレスに置きます。
- コンパイラは呼び出しグラフを解析し、同時に使われることのない関数同士のローカル変数を、同じアドレスに重ねて配置します。関数のローカル変数は、すべての呼び出し元のローカル変数の後ろに置かれます。
- 割り込み処理から呼ばれる関数のローカル変数は、メインの関数とは別の領域に置きます。
- 各関数のローカル変数の配置と合計の使用量をレポートに出します。メモリの合計がターゲット定義の RAM を超えたらコンパイルエラーです。

### 4.4 初期値

- グローバル変数には、初期値の記述が必須です（`noinit` を除く）。初期値は起動時に毎回設定し直します。これにより、RAM に読み込んだプログラムを2回実行しても、前回の値が残りません。
- ローカル変数は、代入する前に読むとコンパイルエラーです（重ね合わせにより、他の関数が使っていた値が残っているため）。
- RAM に読み込んで実行する形と、ROM から実行する形の両方に対応し、ターゲット定義で切り替えます。ROM から実行する場合は、初期値を ROM に置き、起動時に RAM へコピーします。
- 初期値が 0 の変数は、元データを持たず、起動時に `stz` で 0 を書きます（連続した領域はループでまとめて書く）。元データを持つのは、初期値が 0 でない変数だけです。0 でない変数を元データからコピーするか、即値で書くかは、コンパイラが小さいほうを選びます。どちらの方法でも、起動時に毎回初期化されることは変わりません。
- 起動時の初期化にかかるサイクル数とバイト数は、レポートに出します。

### 4.5 ローカル変数のアドレス

ローカル変数のアドレスは「下には貸せるが、外には出せない」とします。

- 呼び出し先の関数に渡すのは安全です（呼び出し先のローカル変数は、呼び出し元の領域と重ならないため）。
- 関数の戻り値として返す、グローバル変数に保存する、といった、関数を抜けた後もアドレスが残る使い方はコンパイルエラーです。

## 5. 関数

### 5.1 関数の定義

- 関数とサブルーチンを区別せず、「入口と出口のデータを宣言したサブルーチン」として1つの仕組みにまとめます。引数も戻り値もない関数は、そのままサブルーチンとして使えます。
- 状態を書き換えない関数には `pure` を付けられます。`pure` な関数は、コンパイル時の計算に使えます（10章）。
- 再帰呼び出し（直接・間接とも）はコンパイルエラーです。

### 5.2 引数の渡し方

- 引数は、呼び出し先が持つ固定アドレスの変数として扱います。
- 先頭から3バイト分は、A、X、Y の順に入れて渡します。u16 とポインタは A（下位）と X（上位）の2本を使います。呼び出し先は、後で使う値だけを自分の固定領域にしまいます。
- レジスタで受け取ったポインタは、呼び出し先が入口で自分のゼロページ領域に書きます（`(zp),Y` で使うため）。書き込みは呼び出し先に1か所あるだけなので、呼び出し元ごとにゼロページへ書く方式より、呼び出しのたびに4バイト小さくなります（版0.2 で変更。meteor の比較で確認）。
- 4 バイトめ以降の引数（レジスタに入りきらないポインタを含む）は、呼び出し元が、呼び出し先専用の引数領域に直接書き込みます。ポインタの場合、その引数領域は呼び出し先のゼロページ領域です。

### 5.3 戻り値

戻り値は1つで、大きさによって返し方が決まります。

| 戻り値 | 返し方 |
|---|---|
| なし | 何も返さない |
| `bool` | キャリー |
| 1バイトの型（u8、i8、範囲型、列挙型、fnset の値など） | A |
| 2バイトの型（u16、i16、ポインタ） | A（下位）と X（上位） |
| 構造体 | すべてのフィールドを、呼び出し先の結果領域に置く |
| `?` 付きの型 | 有無をキャリーで返し、値は上の規則に従う |

- 構造体の結果領域は固定アドレスで、呼び出し元はコピーせずに直接読みます。同じ関数をもう一度呼ぶまで値は変わりません。古い結果を使い終わる前に同じ関数を呼ぶ場合だけ、コンパイラが自動でコピーを入れます。フィールドの数に制限はありません。
- 配列は直接は返せません。返したい場合は構造体に入れます。
- 結果を指すポインタを返す方式は採用しません。

### 5.4 レジスタの扱い

関数を呼ぶと A、X、Y は壊れる可能性がある、という前提にします。ただし、コンパイラはプログラム全体を解析し、呼び出し先が実際に壊すレジスタだけを、呼び出し元で退避します。

### 5.5 スタックの予算

- スタックに積まれるのは、`jsr` の戻り番地（2バイト）、割り込み時に CPU が積む戻り番地とフラグ（3バイト）、割り込み処理の入口でのレジスタ退避、コンパイラが入れる一時的な退避と `atomic` の `php` だけです。ローカル変数は積みません。
- コンパイラは、メイン・IRQ 処理・NMI 処理それぞれのすべての呼び出し経路について最大の使用量を求め、その合計がターゲット定義の予算を超えたら、原因の経路を示してコンパイルエラーにします。

```
エラー：スタック予算超過（必要 140 バイト / 予算 128 バイト）
  メイン最深経路：main → update → draw_sprite → plot（112 バイト）
  IRQ：irq → read_kbd（16 バイト）
  NMI：nmi（12 バイト）
```

### 5.6 関数ポインタ（候補一覧）

```
fnset state_fn = { idle, walk, jump };  // 呼ぶ可能性のある関数の一覧（すべて同じ型）
state_fn current = idle;                // 一覧の中のどれかを指す変数（中身は番号）

fn update() {
    current();                          // current が指す関数を呼ぶ
    current = walk;                     // 一覧にある関数なら代入できる
}
```

- 候補一覧にない関数は代入できません。
- コンパイラは、呼び出しを「一覧のどれかを呼ぶもの」として呼び出しグラフに組み込みます。深さの計算と変数の重ね合わせはそのまま行えます。
- 65C02 では `jmp (表,x)` によるジャンプテーブルになります。NMOS では別の方法に切り替えます。

### 5.7 ROM ルーチンの宣言

```
extern fn rom_print(u8 c in A)  // 引数 c を A で渡す
    @ $FFEF                     // ルーチンのアドレス
    clobbers(A, X, flags)       // 壊すもの
    stack(4);                   // 使うスタック（戻り番地を含む）
```

- コンパイラが中身を解析できないルーチンについて、引数のレジスタ、アドレス、壊すもの、スタック使用量を宣言します。
- 宣言の正しさはプログラマの責任です。

### 5.8 最適化

- 末尾呼び出し（`jsr` の直後が `rts`）は、常に `jmp` に置き換えます。
- `-O1` 以上では、関数ごとに引数の渡し方を変えてもかまいません。ただし、`extern` の関数と、アセンブリから呼ばれる関数は、常に標準の規則に従います。

#### インライン化の指定

| 属性 | 意味 |
|---|---|
| `#[inline]` | 展開してよい。`-O0` でも展開する |
| `#[inline(always)]` | 必ず展開する。展開できない場合はコンパイルエラー |
| `#[inline(never)]` | 決して展開しない |
| `#[cold]` | めったに呼ばれない関数であることを示す。`-Os` でも展開せず、何度も回るループの外に置く |

- 属性がない関数を展開するかどうかは、最適化の段階で決まります（12章）。
- `#[inline(always)]` と `#[inline(never)]` は、最適化の段階による判断より優先されます。
- 展開できない関数（`#[inline(always)]` を付けるとエラーになるもの）は、途中に `rts` がある `asm fn`、`unsafe asm` を含む関数、`extern` の関数、割り込み処理の関数です。
- `#[cold]` を用意するのは、ループの中でもめったに通らない枝で呼ばれる関数（meteor の `respawn` など）を、コンパイラが自分で見分けるのが難しいためです。こうした関数を展開すると、ループが大きくなってページ境界をまたぎ、かえって遅くなることがあります（meteor の比較で確認）。
- どの関数を展開したか、しなかったか、その理由をレポートに出します。

## 6. 制御構文

### 6.1 条件分岐

- `if` の条件は `bool` だけです。
- `&&` と `||` は短絡評価です。
- 分岐命令が届かない遠くへの分岐は、コンパイラが自動で書き換えます。

### 6.2 ループ

```
loop { ... }                    // 無限ループ
while cond { ... }              // 条件が成り立つ間くり返す
while cond max 100 { ... }      // 最大100回まで（上限に達したら抜ける）
for i in 0..10 { ... }          // 0〜9（終わりを含まない）
for i in 0..=255 { ... }        // 0〜255（終わりを含む）
for e in eid { ... }            // 範囲型・列挙型のすべての値
for i in rev 0..16 { ... }      // 15 から 0 へ逆順
for c in "HELLO" { ... }        // 文字の配列の各要素
```

- `break`、`continue`、名前を付けた外側のループを抜ける `break`（ラベル付き）を使えます。
- `goto` はありません。
- 逆順のループは `rev` で明示します。逆順にできそうなループには、コンパイラがレポートで助言を出します。`-O1` 以上では、順番に依存しないと証明できたループを、コンパイラが自動で逆順にします。証明の条件は、ループの中で I/O 変数・`shared` 変数に触れない、呼ぶ関数は `pure` だけ、各回で読み書きする配列要素がループ変数の位置だけ、ループ変数を外に保存・出力しない、の全部です。`cycles()` ブロックの中のループは対象外です。逆順にしたループはレポートに出します。
- 割り込み処理の中と、`cycles()`・`max_cycles()` の中では、回数の上限がわかるループ（`for`、または `max` を付けた `while`）だけを使えます。

### 6.3 レジスタの割り当て

- ループカウンタなどを X や Y に置くかどうかは、コンパイラが自動で選び、レポートに出します。
- `for i @x in ...` のように、プログラマがレジスタを指定することもできます。指定したレジスタが使えない場合（ループの中で呼ぶ関数がそのレジスタを壊すなど）はコンパイルエラーです。

### 6.4 match

```
match s {
    0     => idle(),
    1 | 2 => walk(),
    3     => jump(),
}
```

- 範囲型と列挙型では、すべての値を書いたかどうかを検査し、抜けがあればエラーにします。`u8` のように値の数が多い型では `_ =>`（それ以外）が必須です。
- 実装方法（比較を並べるか、ジャンプテーブルにするか）はコンパイラが選び、レポートに出します。`match table s { ... }` のように指定もできます。
- 各場合の結果が定数だけの `match` は、表引きに変換します。

## 7. I/O

```
io in   u8  KBD    @ $D010;     // 読み込み専用
io out  u8  DSP    @ $D012;     // 書き込み専用
io      u8  PORTB  @ $6000;     // 読み書き両方
io rmw  u8  DDRB   @ $6002;     // RMW 命令の使用を許可
io in   joy JOYPORT @ $6001;    // ビットフラグ型として宣言
```

- `in` は読み込み専用、`out` は書き込み専用です。逆の使い方はコンパイルエラーです。
- ソースに書いた読み書きは、それぞれ必ず1回のアクセスになり、省略も追加もしません。I/O 変数同士の読み書きの順序は、ソースの順のままです。
- I/O 変数の大きさは 1 バイトだけです。16 ビットのレジスタは、下位と上位を別々に宣言し、読み書きの順序をソースで明示します。
- RMW 命令（`inc`、`asl`、`tsb` など）は、内部でアクセスが2回以上起きるため、標準では I/O 変数に使いません。`io rmw` と宣言したレジスタにだけ使います。インデックス付きのアクセスで余分な読み込みが起きる場合も同じ扱いです。
- I/O 変数には `pub` を付けられません。I/O を操作できるのは宣言したモジュールだけです（10B.5節）。
- 値を使わない読み込み（読むだけで状態が変わるレジスタを読む場合。例：`let _ = T1C_L;`）は、`bit` 命令で行います。読み込みは必ず1回行われ、A、X、Y は変わりません（フラグの N、V、Z だけが変わる）。これにより、割り込み処理などで、読み捨てのためだけにレジスタを退避する必要がなくなります。

## 8. 割り込み

### 8.1 割り込み処理の宣言

```
interrupt(irq) fn on_irq() { ... }
interrupt(nmi) fn on_nmi() { ... }
interrupt(brk) fn on_brk() { ... }
```

- レジスタの退避と復帰、`rti` はコンパイラが作ります。退避するのは、割り込み処理の中で実際に使うレジスタだけです。
- `brk` 命令は IRQ と同じベクタを使うため、コンパイラが、スタック上のフラグの B ビットを調べて振り分けるコードを作ります。

### 8.2 割り込みベクタ

- ベクタの置き方は、ターゲット定義の `irq`・`nmi`（`hw`、`indirect(addr)`、`jump(addr)`）で指定します（2章）。

### 8.3 割り込み処理の制約

- 割り込み処理から呼べるのは、メインから呼ばれない関数だけです。両方から呼ばれる関数はコンパイルエラーです（ローカル変数が固定アドレスにあるため）。
- 割り込み処理の中での `cli` は禁止です（スタック予算が計算できなくなる、入れ子の実行でローカル変数が壊れる、割り込みの原因を消す前に許可すると無限に入れ子になる、の3つの理由による）。
- 割り込み処理の最長経路のサイクル数をレポートに出します。ターゲット定義に割り込みの間隔があれば、次の割り込みまでに終わらない場合をエラーにします。
- 割り込み処理の中のループには上限が必要です（6.2節）。

### 8.4 shared 変数

```
shared<irq>  u8   keybuf[kpos];     // 書き込むのは割り込み処理だけ
shared<irq>  kpos head = 0;         // 書き込むのは割り込み処理だけ
shared<main> kpos tail = 0;         // 書き込むのはメインだけ
shared       u8   count = 0;        // どちらも書き込む
```

- 1命令で済む操作（8 ビットの読み込み・書き込み、`inc`、`dec` など）は、そのまま書けます。2命令以上になる操作（読んで計算して書き戻す、16 ビットの読み書きなど）は、`atomic` の中でしか書けません。
- 書き込む側を `shared<irq>`、`shared<main>`、`shared<nmi>` で指定できます。指定した側以外が書き込むとコンパイルエラーです。指定を省略した場合は両方が書き込めます。
- `shared` 変数同士の読み書きの順序は、ソースの順のままです。
- NMI 処理と共有する変数は、書き込む側の指定が必須で、1命令で済む操作しか使えません。

### 8.5 atomic

```
atomic {
    u16 t = timer;              // 割り込みを止めた状態で 16 ビットを読む
}
```

- `php` と `sei` で始まり、`plp` で終わります。
- 入れ子にできます。割り込み処理の中では何もしません。
- 最も長い `atomic` ブロックのサイクル数（割り込みが待たされる最大の時間）をレポートに出します。
- NMI は `sei` で止められないため、NMI と共有する変数を `atomic` の中で使うと警告を出します。

## 9. タイミング

| 形 | 意味 | 主な用途 |
|---|---|---|
| `cycles(n) { }` | ちょうど n サイクル（足りない分は `nop` で埋める） | パルスの幅、ビデオ表示のタイミング |
| `max_cycles(n) { }` | n サイクル以内（超えたらエラー） | 時間内に終わらせたい処理 |
| `delay(n);` | 最低 n サイクル待つ（コンパイラが待ちループを作る） | 周辺チップの待ち時間 |

- 時間は、コンパイル時の関数 `us()` で指定できます（`delay(us(40));`）。ターゲット定義のクロックからサイクル数を求め、ちょうどにならない場合は警告を出して切り上げます。
- `cycles()` では、分岐の両方の経路のサイクル数を `nop` でそろえます。そろえられない場合はエラーです。ページ境界をまたぐことによるサイクルの増加は、コンパイラが配置で調整します。
- `cycles()` ブロックは自動で `atomic` を兼ねます。ただし NMI は止められません。
- 中のループには上限が必要です（6.2節）。
- W65C02S のターゲットでは、割り込みが来るまで CPU を止める `wait_interrupt()`（`wai` 命令）を使えます。それ以外の CPU ではコンパイルエラーです。

## 10. コンパイル時の計算と条件コンパイル

### 10.1 コンパイル時に計算される場所

`const` の初期値、配列の長さ、範囲型の上限・下限、`cycles()`・`max_cycles()`・`delay()` の引数、`@` のアドレス、`match` の場合の値は、必ずコンパイル時に計算されます。計算できない式はコンパイルエラーです。

### 10.2 pure 関数

- `pure` 関数は、実行時にもコンパイル時にも呼べます（Rust の `const fn` に相当）。
- コンパイル時に計算しても、実行時と同じ型の規則（あふれは一周して戻るなど）で計算し、結果は実行時と一致します。

### 10.3 comptime 関数

```
comptime fn sine_at(int i) -> i8 {
    real r = sin(i * 2.0 * PI / 256.0);
    return round(r * 127.0) as i8;          // 範囲外ならコンパイルエラー
}
```

- `comptime` 関数はコンパイル時にしか呼べません。実行時のコードから呼ぶとエラーです。
- 中では、コンパイル時専用の型 `int`（大きさの制限なし）と `real`（倍精度の小数）、数学関数（`sin`、`cos`、`sqrt`、`round` など）を使えます。
- 結果を実行時の型に変換するとき、範囲を超えたらエラーにします（一周させない）。
- `us()` は、標準ライブラリの `comptime` 関数として提供します。
- 1つの定数の計算に使える手順数に上限を設け、超えたらエラーにします（上限はオプションで変更可）。

### 10.4 表の生成

```
const i8  sine[256]    = [for i in 0..256 => sine_at(i)];
const u16 row_addr[24] = [for r in 0..24 => $0400 + r * 40];
```

- 配列の各要素を、添字から計算する式で書けます。
- 2次元配列の行の表の自動生成（3.9節）も、この仕組みを使います。

### 10.5 外部データの取り込み

```
const u8 tiles[256] = include_bin("tiles.bin", offset=16);
```

- ファイルの中身をそのまま配列の初期値にします。大きさが配列の長さと合わなければコンパイルエラーです。

### 10.6 コンパイル時の検査と情報

```
static_assert(sizeof(packet) == 4, "packet は4バイトでなければならない");
```

- `static_assert` で、プログラマが書いた条件をコンパイル時に検査します。
- `sizeof(型)`、`len(配列)`、`target.xxx`（ターゲット定義の値）、`build.xxx`（コンパイラのオプションで渡した値）を読めます。

### 10.7 条件コンパイル

```
fn idle() {
    const if target.cpu == w65c02s {
        wait_interrupt();
    }
}

const if target.has(screen) {
    io u8 SCREEN[40] @ $0400;
}

const match target.cpu {
    w65c02s => wait_interrupt(),
    _       => {},
}
```

- `const if` と `const match` は、関数の中（文）にも外（宣言）にも書けます。文字列を置き換えるプリプロセッサはありません。
- 条件に使えるのは、インターフェースが bind されているか（`target.has(screen)`）、CPU とクロック（`target.cpu`、`target.clock`）、ターゲット定義の定数（`target.screen_width` など）、ビルドの設定（`ax65 -D debug` で渡す `build.debug` など）です。機種名による分岐はできません（マシンが育っても、ターゲット定義に bind を書き足すだけで済むようにするため）。
- `target.has()` に書けるのは既知のインターフェースの名前だけ、`target.名前` に書けるのはターゲット定義の定数の名前だけです。書き間違いはエラーです。
- 選ばれなかった側のコードはプログラムに含まれず、スタック・メモリ・呼び出しグラフの検査も、選ばれた側だけで行います。
- 選ばれなかった側は、構文だけを検査します。登録したすべてのターゲット定義で型まで検査するコマンド（`ax65 check --all-targets`）を別に用意します。

## 10B. モジュールとライブラリ

### 10B.1 モジュールと import

- 1つのファイルが1つのモジュールです。`import math;`、`import hw.via;`（`hw/via.ax65`）で読み込みます。
- 分割コンパイルとリンクは行いません。コンパイラは import をたどってすべてのファイルを読み込み、プログラム全体を1つとして解析します。
- モジュールの循環は許しますが、init の順序が決まらない場合はエラーです。

### 10B.2 名前と公開範囲

- 他のモジュールの名前は `モジュール名.名前` で参照します。
- `use screen.{print, clear};` で短く書けます。`import hw.via as v;` で別名を付けられます。取り込んだ名前が重なったらエラーです。
- 宣言は既定で非公開です。`pub` を付けたものだけを他のモジュールから使えます。

### 10B.3 使われないコードの除去

- `main` と割り込み処理から呼び出しグラフをたどり、使われない関数・変数・表はプログラムに含めません。
- モジュールごとのメモリ使用量（コード、変数、ゼロページ）をレポートに出します。

### 10B.4 インターフェースと実装

```
// std/console.ax65
interface console {
    fn putc(char c);
    fn getc() -> char;
    fn poll() -> char?;
}

// hw/acia_console.ax65
impl console {
    io in  u8 STATUS @ $8001;
    io out u8 DATA   @ $8000;
    pub fn putc(char c) { ... }
    ...
}

// hw/wozmon_console.ax65（ROM ルーチンを実装にする例）
impl console {
    pub extern fn putc(char c in A) @ $FFEF clobbers(flags) stack(2);
    ...
}
```

- インターフェースは関数と定数の形だけを宣言します。実装は `impl` で書き、どの実装を使うかはターゲット定義の `bind` で選びます。使う側はインターフェースの名前で `import` し、実装の名前は書きません。
- 実装の過不足や型の違いはコンパイルエラーです。
- 実装はコンパイル時に決まるため、呼び出しは直接の `jsr` になり、実行時のコストはありません。
- bind されていないインターフェースも `import` はできますが、`const if target.has(...)` の外で使うとエラーです。
- 使い分け：どの機種にもあり中身が違う機能はインターフェース、機種によって有無が違う機能や小さな違いは `const if` を使います。

### 10B.5 I/O の所有者

- I/O 変数は公開できません。他のモジュールは、所有モジュールの関数を通して使います。
- プログラム全体の I/O 変数のアドレスを集め、2つのモジュールが同じアドレスを宣言していたらエラーにします。チップ全体で共有するレジスタがある場合は、1つのモジュールにまとめます。

### 10B.6 init と起動の順序

```
init {
    DDRB = $FF;
}
```

- モジュールごとに `init` ブロックを書けます。起動時の順序は、スタックポインタの設定、グローバル変数の初期値の設定、各モジュールの `init`（読み込まれる側が先）、`main` です。
- `init` は起動の手順の中に直接展開されます。`init` がなければコストは0です。
- `init` の実行中は割り込みが止まっています。`main` が明示的に許可するまで割り込みは入りません。
- `import` されたモジュールの `init` は、そのモジュールを使っていなくても必ず実行します。`init` を実行させない方法はありません。
- 使っていないモジュールの import には警告を出します。`init` があるモジュールでは、起動時に実行されることも知らせます。`init` だけが目的の場合は `import hw.via for init;` と書くと警告が出ません。`for init` を付けたモジュールの関数を使うと警告が出ます。
- すべての `init` の実行順、サイクル数、バイト数をレポートに出します。

### 10B.7 標準ライブラリ（予定）

| モジュール | 内容 |
|---|---|
| `core` | `us()` などのコンパイル時の関数、`mul8`・`divmod8` などの算術 |
| `bcd` | BCD の桁の取り出し、表示用の変換 |
| `text` | 数値の文字列化、`strbuf` の操作 |
| `console` | 1文字の入出力のインターフェース |
| `timer` | 時間を測るインターフェース |

## 10C. インラインアセンブリ

### 10C.1 基本方針

コンパイラはインラインアセンブリを1命令ずつ解析し、壊すレジスタとフラグ、スタック使用量、サイクル数、呼び出しグラフを自動で求めます。プログラマがこれらを宣言する必要はなく、これまでの検査はインラインアセンブリの中でも続きます。

### 10C.2 書き方

```
asm {
    lda {score.lo}              ; 言語の変数は {名前} で参照する
    ...
}

asm (in A = v, out A -> r) {    ; 値をレジスタで受け渡す
    ...
}

asm fn bit_count(u8 v) -> u8 {  ; 関数全体をアセンブリで書く（標準の呼び出し規約に従う）
    ...
    rts
}
```

- 言語の名前は `{名前}` で参照します（ラベルや数値と区別するため）。
- 2バイト以上の変数は `{w.lo}`、`{w.hi}` のように、どのバイトかを明示します。
- 参照した変数について、アドレッシングモード（間接参照はゼロページの変数だけ）、初期化前の読み込み、I/O の所有者・読み書きの方向・RMW の可否、`shared` 変数の2命令以上の操作を検査します。
- ラベルはブロックの中だけで有効です。

### 10C.3 ブロックの決まり

- ブロックの入口と出口で、スタックの深さが同じでなければなりません。
- 分岐と `jmp` の飛び先は、ブロックの中のラベルかブロックの終わりだけです。
- `jsr {関数名}` で ax65 の関数を呼べます（呼び出しグラフに組み込まれる）。ROM ルーチンは `extern` で宣言したものだけを呼べ、数値のアドレスへの `jsr` はエラーです。
- ターゲットの CPU にない命令と、未定義命令はエラーです。
- 割り込み処理の中と `cycles()` などの中では、ループの回数の上限をコンパイラが求められる形でなければなりません。

### 10C.4 unsafe asm

`txs`、`sei`、`cli`、`plp`、`rti`、`brk`、間接ジャンプ、数値のアドレスへの書き込みなど、検査の前提を崩す命令は、通常の `asm` では書けません。必要な場合は `unsafe asm` を使い、コンパイラが求められない性質を宣言します。

```
unsafe asm (clobbers(A), stack(1), cycles(12..20), irq(disables)) {
    ...
}
```

- 宣言の正しさはプログラマの責任です（`extern` と同じ位置づけ）。
- `unsafe asm` の中でも、他のモジュールの I/O 変数や他の関数の変数のアドレスへの書き込みはエラーです。
- `unsafe asm` で使った数値のアドレスは、レポートに一覧で出します。
- 割り込みを止めるだけなら、`atomic { }` の中に通常の `asm` を書きます。

### 10C.5 自己書き換えコード

```
smc load: lda $1200,x           ; オペランドを書き換えてよい命令
```

- 書き換える命令には `smc` を付けます。宣言なしに命令の位置へ書き込むとエラーです。
- 書き換えられるのはオペランドだけで、オペコードは書き換えられません（サイクル数とスタックの解析を続けるため）。
- `run = rom` のターゲットでは、`smc` はエラーです。

## 10A. CPU による違いの扱い

65C02 では、次の追加命令を活用します。

| 追加命令 | 主な用途 |
|---|---|
| `(zp)` | ポインタの指す先の読み書き（Y を使わない） |
| `phx` `phy` `plx` `ply` | 割り込み処理のレジスタ退避 |
| `inc a` `dec a` | A の ±1 |
| `stz` | 0 の書き込み |
| `bra` | 無条件の短い分岐 |
| `jmp (abs,x)` | ジャンプテーブル（関数ポインタ、match） |
| `tsb` `trb` | ビットの操作 |
| `wai`（W65C02S のみ） | 割り込み待ち |
| `rmb` `smb` `bbr` `bbs`（W65C02S など一部の品種のみ） | ゼロページのビット操作（品種をターゲット定義で区別する） |

NMOS 6502 のターゲットでは、コンパイラが次の点を自動で処理します。

- 割り込み処理の入口に `cld` を入れる（NMOS は割り込み時に 10 進モードを解除しないため）
- 間接ジャンプの格納先を $xxFF に置かない（`jmp (ind)` のページ境界のバグを避けるため）
- 10 進演算の後の N・Z フラグを判定に使わない
- 65C02 の追加命令を、同じ働きの命令の組み合わせに置き換える

未定義命令は、どの CPU でも使いません。

## 11. コンパイラの検査とレポート

### 11.1 主なコンパイルエラー

- 再帰呼び出し
- スタック予算の超過
- RAM・ゼロページの容量の超過
- 型の不一致（`u8` と `u16` の混在、符号の混在、範囲型・列挙型・変換表の違い、`char[N]` と `str` の違いなど）
- 範囲外になりうる添字
- 代入前のローカル変数の読み込み
- ローカル変数のアドレスの持ち出し
- `?` 付きの値の、有無を確かめない使用
- `match` の場合の抜け
- 割り込み処理とメインの両方から呼ばれる関数
- 割り込み処理の中での `cli`
- `shared` 変数への、`atomic` の外での2命令以上の操作、指定外の側からの書き込み
- I/O 変数の、読み込み専用・書き込み専用に反する使用
- 割り込み処理と `cycles()` などの中の、上限のないループ
- `cycles()` のサイクル数の超過、分岐のサイクル数がそろえられない場合
- 変換表にない文字
- 指定したレジスタが使えない場合（`@x` など）
- ターゲットの CPU にない機能の使用（`wait_interrupt()` など）
- コンパイル時に計算できない式を、定数が必要な場所に書いた場合
- `comptime` 関数の実行時の呼び出し、実行時の型への変換での範囲超過、手順数の上限超過
- `include_bin` のファイルの大きさと配列の長さの不一致
- `static_assert` の条件が成り立たない場合
- `target.has()` や `target.名前` の知らない名前
- 実装（`impl`）のインターフェースに対する過不足・型の違い、bind の誤り
- bind されていないインターフェースの、`const if` の外での使用
- `use` で取り込んだ名前の重なり、非公開の名前の使用、I/O 変数への `pub`
- 複数のモジュールによる同じ I/O アドレスの宣言
- init の順序が決まらないモジュールの循環
- インラインアセンブリ：スタックの不釣り合い、ブロック外への分岐、未宣言の数値アドレスへの `jsr`、CPU にない命令・未定義命令、通常の `asm` での検査できない命令、変数のバイトの未指定、宣言のない命令の書き換え、ROM ターゲットでの `smc`

### 11.2 主な警告

- `us()` の時間がちょうどのサイクル数にならない
- NMI と共有する変数を `atomic` の中で使っている
- 使っていない import（init がある場合は、起動時に実行されることも示す）
- `for init` を付けたモジュールの関数の使用

### 11.3 レポートの内容

- 変数の配置（アドレス、ゼロページ、レジスタ）
- 各関数のローカル変数の重ね合わせの結果と、合計のメモリ使用量
- スタックの最大使用量と、その経路
- 割り込み処理の最長サイクル数、最も長い `atomic` ブロックのサイクル数
- `match` の実装方法
- 自動で作った表（2 次元配列の行の表、`match` の表など）のメモリ使用量
- 最適化で行った変更（ゼロページへの移動、インライン化、逆順化など）と、使った最適化の段階
- 逆順にできそうなループの助言
- 区画ごと・モジュールごとのメモリ使用量、`init` の実行順・サイクル数・バイト数、`unsafe asm` で使った数値のアドレス
- 起動時の初期化のサイクル数・バイト数（4.4節）
- ループの配置の結果（ページ境界をそろえるために入れた空きのバイト数、そろえられなかったループ）（12.1節）
- 展開した関数・しなかった関数と、その理由（5.8節）

レポートは1つのファイル（`.report`）にまとめます。

### 11.4 エラーメッセージの書式

```
エラー[E0412]：enemies の添字に u8 は使えません
  --> src/main.ax65:24:13
   |
24 |     enemies[n].hp = 0;
   |             ^ n は u8 型で、0〜255 のどれでもありえます
   |
補足：enemies の添字の型は eid（0..15）です
候補：eid.check(n) で範囲を確かめてください
```

- 場所、番号、内容、補足、直し方の候補の順に示します。
- エラーと警告には番号を付け、`ax65 explain E0412` で詳しい説明と例を表示できます。
- `-W error` で警告をエラーとして扱えます。
- エラーメッセージとレポートは、人が読む形式が標準です。`--json` で同じ内容を JSON で出力できます。

### 11.5 出力形式

| 形式 | 拡張子 | 用途 |
|---|---|---|
| バイナリ | `.bin` | 読み込み先から始まる生のバイト列 |
| Wozmon 形式 | `.woz` | `0300: A9 00 ...` の16進テキスト（1行の長さ、最後の `300R` の有無を選べる） |
| Intel HEX | `.hex` | ROM ライタ向け |
| ROM イメージ | `.rom` | ROM の大きさちょうど。空きは $FF、ベクタを含む |
| KIM-1 紙テープ形式 | `.ptp` | KIM-1 のモニタ向け |
| シンボル | `.sym` | 関数・変数・ラベルのアドレスの一覧 |
| リスティング | `.lst` | ソースの行と、アドレス・バイト列・サイクル数・命令・命令の説明を並べた一覧 |

- 複数の形式を同時に出力できます。既定はターゲット定義の `output`、コマンドラインでは `--emit bin,lst` で指定します。
- リスティングの命令の説明は、`--lst-plain` で省けます。

```
                         ; main.ax65:12   if hp == 0 {
0310  AD 40 02    4      lda hp          ; hp を A に読む
0313  D0 03       2/3    bne $0318       ; 0 でなければ if の中を飛ばす
                         ; main.ax65:13       game_over();
0315  20 80 04    6      jsr game_over   ; game_over を呼ぶ
```

## 12. 最適化の段階

最適化は次の4段階です。どの段階でも、プログラムの意味は変わりません。

| 段階 | 方針 | 位置づけ |
|---|---|---|
| `-O0` | 最適化をしない。配置と命令が最も予測しやすい | デバッグや、生成されたコードを確かめたいとき |
| `-O1` | 速さと大きさの釣り合いを取る、版0.1 の最適化 | 初期の仕様 |
| `-O2` | 大きさを優先する最適化。6502 では命令を小さくすることが速さにもつながるため、多くの場合、速さも最もよくなる | **既定** |
| `-Os` | `-O2` に加えて、コードが大きくなっても速さを優先する | 速さが足りないとき |

何も指定しなければ `-O2` になります。`-O2` を既定にしたのは、meteor の比較で、`-O2` に当たる版が、大きさ（`-O1` 比で 10 % 小さい）でも速さ（最も速い版とほぼ同じ）でも最もよかったためです。

なお、GCC などでは `-Os` は大きさ優先の意味で使われますが、ax65 では速さ優先（speed）の意味です。

### 12.1 `-O1` で行うこと（版0.1 の最適化）

- ゼロページへの自動配置（4.2節）
- 関数のインライン化（1 か所からしか呼ばれない関数と、小さな関数を展開する）（5.8節）
- 関数ごとの引数の渡し方の変更（5.8節）
- 構造体の戻り値の最初のフィールドをレジスタでも返す
- 順番に依存しないループの自動の逆順化（6.2節）

### 12.2 `-O2` で行うこと（既定）

- ゼロページへの自動配置（4.2節）
- **インライン化**：1 か所からしか呼ばれない関数と、`#[inline]` を付けた関数だけを展開する。2 か所以上から呼ばれる関数は展開しない（5.8節）
- 関数ごとの引数の渡し方の変更（5.8節）
- **不要な書き込みの削除**：後で読まれずに上書きされるだけの書き込みを消す。ループをまたぐ場合（すべての要素を書くループの後に、すべての要素を書き直すループがある場合など）も対象とする
- **共通部分のくくり出し**：同じ形の命令の並びが複数あれば、小さなサブルーチンにまとめる。何度も回るループの中の並びは対象外とする
- 構造体の戻り値の最初のフィールドをレジスタでも返す
- 順番に依存しないループの自動の逆順化（6.2節）
- **何度も回るループの配置**：ループの中の分岐が、ページ境界をまたがないように、関数やコードの並び順を入れ替える。6502 では、分岐がページ境界をまたいで飛ぶと 1 サイクル余分にかかるため。空きのバイトは入れない。そろえられなかったループはレポートに出す

### 12.3 `-Os` で行うこと（速さ優先）

- `-O2` のすべて。ただし共通部分のくくり出しは行わない（呼び出しのコストがかかるため）
- **インライン化の拡大**：2 か所以上から呼ばれる小さな関数も、ループの中で呼ばれていれば展開する。`#[cold]` を付けた関数は展開しない
- `for` で直接回す `digits()` の展開（3.12節）
- **ループの配置**：並び順の入れ替えでそろえられない場合は、空きのバイトを入れてでもページ境界をそろえる。入れたバイト数はレポートに出す

`cycles()` ブロックの中のページ境界の調整は、段階にかかわらず常に行います（9章）。

### 12.4 段階にかかわらず常に行うこと

- 末尾呼び出しの置き換え（5.8節）
- 値を使わない I/O の読み込みに `bit` を使う（7章）
- 初期値が 0 の変数を `stz` で初期化する（4.4節）

これらは、コードが大きくならず、配置や命令の予測しやすさも損なわないため、既定の動作とします。

## 13. 今後の議題

| 議題 | 主な内容 |
|---|---|
| 13. 文法の清書 | キーワードや記号の最終決定 |

将来の拡張として、仕様に余地だけを残しておくもの：

- Apple II 級のメモリを超える拡張（バンク切り替え）
- セルフホスト
- ROM ルーチンの宣言を、エミュレータで実測して照合するツール
- 速さの要らない関数（起動時の処理、メニューなど）を、1 命令 1〜2 バイトの小さな中間コードにして、解釈ルーチンで実行する仕組み（Apple II の SWEET16 と同じ考え方）。関数ごとに属性で指定する形を想定する。コードは 2〜3 倍小さくなるが、5〜10 倍遅くなる

なお、定数の文字列を表にまとめる、0 終端の文字列の後ろを共有する、データを圧縮する、といった大きさの工夫は、プログラマが必要に応じて行うものとし、言語の仕様には入れません。
