## 3. 型

<a id="s3-1"></a>
### 3.1 整数型

| 型 | 大きさ | 範囲 |
|---|---|---|
| `u8` | 1バイト | 0〜255 |
| `i8` | 1バイト | -128〜127 |
| `u16` | 2バイト | 0〜65535 |
| `i16` | 2バイト | -32768〜32767 |
| `u24` / `i24` | 3バイト | 0〜16777215 / -8388608〜8388607 |
| `u32` / `i32` | 4バイト | 0〜4294967295 / -2147483648〜2147483647 |
| `bcd8` / `bcd16` / `bcd32` | 1 / 2 / 4バイト | 10進 2 / 4 / 8 桁（[5.5節](#s5-5)） |

```
let x: u8 = 200;
let dx: i8 = -2;
let w: u16 = x as u16 * 40;             // u8 を u16 に広げるには as が必要
let nx = x + dx;                        // 例外：u8 + i8 → u8（位置に変化量を足す。adc 1命令）
let bad = x + w;                        // エラー：u8 と u16 の混在
let bad2 = dx < x;                      // エラー：符号付きと符号なしの比較
```

- **暗黙の変換をしない。** `u8` と `u16` を混ぜた式は、`as` での変換がなければエラーです。16 ビットの計算は、必ずソース上で見えます。
- **符号の混在をしない。** 符号付きと符号なしを混ぜた比較や代入は、`as` での変換がなければエラーです。
- **例外：`u8 + i8 → u8`** と **`u8 - i8 → u8`**。命令は `adc`・`sbc` 1つで済みます。
- `u24`・`i24`・`u32`・`i32` は、明示的に書いたときだけ使える型です。キャリーのつなぎはコンパイラが作ります。
- 符号付きで追加のコストがかかるのは、大小比較、8 ビットから 16 ビットへの拡張、右シフト、割り算と表示だけです。

関連 Q&A：[B-1](#qa-b1)

<a id="s3-2"></a>
### 3.2 bool

```
let ready: bool = KBDCR.contains(Kbd::Ready);
if ready && !paused { step(); }
```

- 値は `true` と `false` です。`if` や `while` の条件には `bool` だけを書けます（数値をそのまま条件にはできません）。
- 比較の結果は、通常はフラグのまま分岐に使われます。変数に入れた場合は 1 バイトです。
- 関数の戻り値としてはキャリーフラグで返します（[15.3節](#s15-3)）。

<a id="s3-3"></a>
### 3.3 char と文字の変換表

```
let c: char = 'A';
let code: u8 = c as u8;                 // $41
let back: char = code as char;          // u8 から char へ（コストなし）
let s: char@screen = 'A'@screen;        // 画面の変換表で変換（v3 の場合 $C1）
putc(s);                                // エラー：char@screen は char ではない
```

- `char` は文字の型で、`u8` とは別の型です。大きさは 1 バイトで、0〜255 のどの値も持てます（0〜127 が ASCII。128 以上の意味は、端末などの相手によって決まる）。
- `c as u8` で数値に、`n as char` で文字に変換できます。変換表付きの文字型への変換（`n as char@screen`）も書けます。どれもコストはかかりません。
- 何も指定しない文字・文字列は ASCII です。ソースの意味がターゲットによって変わることはありません。
- `@変換表` を付けると、ターゲット定義の変換表（[16.5節](#s16-5)）で、コンパイル時に機種の文字コードに変換します。実行時の変換処理はありません。変換表にない文字はエラーです。
- 変換表ごとに別の型になります（`char@screen`、`str@screen`）。ASCII の文字を受け取る関数に、画面用の文字を渡すとエラーです。

<a id="s3-4"></a>
### 3.4 範囲型

決まった範囲の値だけを取る型です。中身は `u8` です（上限が 256 を超える範囲型の中身は `u16` で、配列の添字には使えない）。

```
range Eid = 0..16;                      // 0〜15（0..=15 と書いても同じ）
range Iid = 0..16;                      // 範囲は同じだが、Eid とは別の型

static ENEMIES: [Enemy; Eid] = [ENEMY0; Eid];
static ITEMS: [Item; Iid] = [ITEM0; Iid];

fn damage(e: Eid) {                     // 引数が Eid なので、中では検査不要
    ENEMIES[e].hp = ENEMIES[e].hp.saturating_sub(1);
    ITEMS[e].count = 0;                 // エラー：ITEMS の添字は Iid で、Eid は使えない
}

fn on_key(n: u8) {
    if let Some(e) = Eid::check(n) {    // 外から来た値は、入口で1回だけ確かめる
        damage(e);
    }
    let w = Eid::wrap(n);               // 下位 4 ビットだけを取る（and #15 の1命令）
    damage(w);
}
```

- **名前による型の区別**：同じ範囲でも、`range` の宣言ごとに別の型です。同じ型として共有したいときは `type` で別名を付けます（[3.13節](#s3-13)）。
- **値の作り方**：範囲型の値は、範囲を必ず守れる方法でしか作れません。

| 作り方 | 例 | 実行時のコスト |
|---|---|---|
| for で回す | `for e in Eid { }`、`for e in Eid::range(a, b) { }`（a から b まで。b を含む） | なし |
| 定数 | `ENEMIES[3]`（範囲外ならエラー） | なし |
| 範囲を確かめる変換 | `Eid::check(n)`（結果は `Option<Eid>`） | 比較と分岐 |
| 下位ビットだけを取る変換 | `Eid::wrap(n)`（範囲の個数が 2 のべき乗のとき） | `and` 1命令 |
| 検査の省略 | `Eid::unchecked(n)` | なし（プログラマの責任） |

- **一部を回す**：`Eid::range(a, b)` の引数 `a`・`b` は `Eid` 型で、`a` から `b` まで（`b` を含む）を回します。ループ変数は常に範囲内で、最後の値まで届きます。`a` が `b` より大きければ 0 回です。

```
fn heal_from(first: Eid) {
    for e in Eid::range(first, 15) {    // first から 15 まで（15 を含む）。15 は定数なので Eid として渡せる
        ENEMIES[e].hp = 3;
    }
}
```

- **演算**：範囲型の値に演算すると、結果は `u8` に戻ります。`e as u8` で明示的に `u8` にできます。
- **検査の要否**：範囲の検査が必要かどうかは、コンパイラが型で判断します。プログラマが決めるのは、検査をどこで行うか（引数を範囲型にして呼び出し元で行うか、関数の中で行うか）だけです。
- 範囲型の値を `Option` にしても、使われない値（$FF など）で「なし」を表すので、大きさは 1 バイトのままです（[3.11節](#s3-11)）。

### 3.5 列挙型

```
enum Dir { Up, Down, Left, Right }                  // Up=0、Down=1、Left=2、Right=3
enum Cmd { Reset = $FF, Read = $10, Write = $11 }   // 値の明示もできる

const DX: [i8; Dir] = [0, 0, -1, 1];                // 0 から連続した列挙型は配列の添字になる

fn turn(d: Dir) -> Dir {
    match d {
        Dir::Up    => Dir::Right,
        Dir::Right => Dir::Down,
        Dir::Down  => Dir::Left,
        Dir::Left  => Dir::Up,                      // すべての値を書かないとエラー
    }
}

let n = Dir::Left as u8;                            // 2
let d: Option<Dir> = Dir::check(n);                 // u8 から列挙型へは check
```

- 値は `Dir::Up` のように書きます。中身は `u8` です。
- 範囲型と同じく、宣言ごとに別の型で、`for d in Dir` で回せ、`match` で網羅性が検査されます。
- 0 から連続した値の列挙型だけが、配列の添字に使えます。
- 値ごとに別のデータを持つ列挙型（Rust の enum のようなもの）は採用しません。必要な場合は、列挙型と構造体を組み合わせます。組み込みの `Option<T>` だけは例外です（[3.11節](#s3-11)）。

### 3.6 ビットフラグ型

```
flags Joy { Up, Down, Left, Right, Fire }   // Up=ビット0 … Fire=ビット4

io(in) JOYPORT: Joy @ $6001;

fn check() {
    let j = JOYPORT;
    if j.contains(Joy::Fire) { shoot(); }
    if j.contains(Joy::Up | Joy::Left) { jump_left(); }  // 両方が立っているか
    let m = Joy::Up | Joy::Down;
    m.insert(Joy::Fire);
    m.remove(Joy::Up);
    m.toggle(Joy::Left);
    let raw = j as u8;                  // ビットフラグ → u8
    let all = $FF as Joy;               // u8 → ビットフラグ（名前のないビットもそのまま持つ）
}
```

- 各ビットに名前を付けた型です。8 ビットまでは `u8`、16 ビットまでは `u16` が中身になります。
- ビットの値は `Joy::Fire` のように書き、`|` で組み合わせます。操作の名前は Rust の `bitflags` ライブラリと同じです。

| 操作 | 書き方 | 対応する命令 |
|---|---|---|
| 調べる | `j.contains(Joy::Fire)` | `and`（ビット 6・7 は `bit`） |
| 立てる | `j.insert(Joy::Fire)` | `ora` |
| 消す | `j.remove(Joy::Fire)` | `and` |
| 反転する | `j.toggle(Joy::Fire)` | `eor` |
| 数値にする・数値から作る | `j as u8`、`n as Joy` | なし |

- ビットフラグ型と中身の整数型の間は、`as` でどちらの向きにも変換できます。どのビットの組み合わせも有効な値です（[3.14節](#s3-14)）。
- I/O 変数の型にも使えます。`io(rmw)` のレジスタでは、`insert`・`remove` に `tsb`・`trb` を使います（[11.2節](#s11-2)）。

### 3.7 構造体

```
struct Enemy { x: u8, y: u8, dir: Dir, hp: u8 }

#[packed]
struct Packet { cmd: u8, addr: u16, len: u8 }       // 1要素を連続したバイト列として並べる

const ENEMY0: Enemy = Enemy { x: 0, y: 0, dir: Dir::Up, hp: 3 };
```

- フィールドは `名前: 型` をカンマで区切って並べます。
- 構造体の配列は、標準ではフィールドごとの配列になります。`#[packed]` を付けた構造体は、1要素を連続したバイト列として並べます（[3.8節](#s3-8)）。
- 関数の戻り値として、構造体を値で返せます（[15.3節](#s15-3)）。
- 値の書き方は [4.5節](#s4-5) にあります。

### 3.8 配列

```
static BUF: [u8; 256] = [0; 256];   // 長さ 256：どの u8 でも添字にできる
static ENEMIES: [Enemy; Eid] = [ENEMY0; Eid];   // 範囲型を添字にする
const TABLE: [u8; 16] = [0; 16];        // 長さを数字で書いた配列
static PAGES: [[u8; 256]; 4] = [[0; 256]; 4];   // ページ単位の配列（1KB）
static MAP: u8[24][40] = [[0; 40]; 24];          // 従来の書き方（[[u8; 40]; 24] と同じ）

fn f(n: u8, e: Eid) {
    BUF[n] = 1;                         // OK
    ENEMIES[e].y += 1;                  // OK：y だけを並べた配列の e 番目（inc ENEMIES_y,x）
    let a = TABLE[3];                   // OK：定数の添字
    let b = TABLE[n];                   // エラー：0〜15 に収まる保証がない
    let c: Option<u8> = TABLE.get(n);   // OK：範囲外なら None
    let len = TABLE.len();              // 16（コンパイル時の定数）
}
```

#### 型の書き方と添字

- 配列の型は `[T; N]` と書きます。従来の書き方 `T[N]` も同じ意味で書けます（2次元は `[[u8; 256]; 4]` または `u8[4][256]`）。`ax65 fmt` で一方にそろえられます。
- 従来の書き方の `T[N1][N2]` は `[[T; N2]; N1]` です（C と同じく、左の添字が外側）。上の `MAP: u8[24][40]` は 40 バイトの行が 24 個並ぶ配列で、`MAP[y][x]` の `y` が 0〜23、`x` が 0〜39 です。
- `N` には、長さ（256 以下の定数）か、範囲型・列挙型の名前を書きます。

| 配列の型 | 添字に使える型 |
|---|---|
| `[T; 256]` | `u8`（どの値でも範囲内） |
| `[T; R]`（R は範囲型・列挙型） | `R` |
| `[T; N]`（N は 256 未満の数） | 定数の添字だけ。変数で読むときは `a.get(n)`（結果は `Option<T>`） |

- 長さを数字で書いた配列を変数の添字で何度も使う場合は、範囲型を宣言して `[T; R]` にするのが基本です。

#### メモリ上の並べ方

- **構造体の配列は、フィールドごとの配列にするのが標準**です。番号をそのまま X に入れて 1 命令で読め、要素数も 256 まで扱えます。
- **u16 とポインタの配列は、下位バイトの配列と上位バイトの配列に分けるのが標準**です。
- `#[packed]` の構造体の配列は、1要素を連続したバイト列として並べます（ディスクや通信のデータ形式、ハードウェアが決めた表など）。全体で 256 バイト以下です。
- フィールドごとの配列では、1要素を指すポインタは作れません。代わりに添字を渡します。

```asm
; ENEMIES[e].y += 1（e は X に入っている）
        inc ENEMIES_y,x         ; y だけを並べた配列の X 番目を 1 増やす（7サイクル）
```

#### 256 バイトを超えるデータ

- 256 バイトを超えるデータは、`[[u8; 256]; 4]` のようなページ単位の配列として宣言します。コンパイラはページの先頭（アドレスの下位バイトが $00）に配置します。
- `&PAGES` は配列全体の先頭（＝最初のページの先頭）のアドレス、`&PAGES[k]` は k 番目のページの先頭のアドレスです。型はどちらも `ptr<u8>` です。
- 行の長さが 2 のべき乗でない 2 次元配列（`[[u8; 40]; 24]` など）には、各行の先頭アドレスの表をコンパイラが自動で作り（下位・上位に分けて配置）、掛け算を使わずにアクセスします。表のメモリ使用量はレポートに出ます。

### 3.9 文字列型

```
const TITLE: str = p"METEOR DODGE";
static LINE: strbuf<40> = strbuf::new();

fn print(s: str) {
    for c in s { putc(c); }             // 長さの分だけ回る
}

fn read_line() {
    LINE.clear();
    loop {
        let c = getc();
        if c == '\r' { break; }
        if !LINE.push(c) { beep(); }    // 満杯なら false
    }
}
```

| 型 | 中身 | 用途 |
|---|---|---|
| `[char; N]` | 長さも終端もない N 文字 | `"..."`。長さは型が持つ |
| `str` | 先頭に長さ（最大 255 文字） | 標準の文字列。`p"..."` |
| `zstr` | 最後に $00 | `z"..."`。ROM ルーチンなどとのやり取り |
| `histr` | 最後の文字の最上位ビットが 1 | `hi"..."`。同上 |
| `strbuf<N>` | 長さ（1 バイト）＋ N バイト | 書き換えられる文字列 |

- `str` を受け取る関数に `[char; N]` を渡すとエラーです。
- `strbuf<N>` の操作は `clear()`、`push(c) -> bool`、`len()`、`as_str()` です。`push` は満杯のとき `false` を返し、あふれは起きません。
- 文字列をつなげて新しい文字列を作る操作はありません。
- 変換表を付けた文字列は別の型になります（`str@screen` など）。

### 3.10 ポインタ

```
#[packed]
struct Rec { id: u8, hp: u8 }

fn sum(p: ptr<u8>, n: u8) -> u16 {      // p は自動でゼロページに置かれる
    let t: u16 = 0;
    for i in 0..n { t += p[i] as u16; } // p[i] → lda (p),y
    t
}

fn heal(r: ptr<Rec>) {
    r.hp += 1;                          // packed 構造体のフィールド → ldy #1 / lda (r),y
}

fn next(p: ptr<u8>) -> ptr<u8> { p.add_pages(1) }   // inc p+1
```

| 操作 | 書き方 | 対応する命令 |
|---|---|---|
| 指す先を読み書き | `p[i]`（i は u8） | `lda (p),y`。i が 0 なら 65C02 の `lda (p)` |
| `#[packed]` 構造体のフィールド | `p.hp`（自動で指す先をたどる） | `ldy #位置` と `lda (p),y` |
| 次のページへ進める | `p.add_pages(1)` | `inc p+1` |
| 任意の数を足す | `p.add(n)` | 16ビットの足し算 |
| アドレスを代入 | `p = &TABLE;` | 下位・上位の2回の書き込み |
| 一致の比較 | `p == q` | 2バイトの比較 |

- ポインタ型は `ptr<T>` です。ポインタ型の変数は自動でゼロページに置かれ、空きを超えたらエラーです。
- `.` の後ろの名前は、`()` がなければ指す先のフィールド、`()` があればポインタのメソッドです。
- ヌルポインタはありません。「指していないかもしれない」場合は `Option<ptr<T>>` を使います。
- ポインタの指す先の範囲は検査されません（`p.add(n)` で配列の外を指すことはできる）。ポインタを通した読み書きは、[1.2節](#s1-2) の保証の対象外で、レポートの unsafe の項目に一覧で出ます。範囲の検査が必要なデータは、配列と範囲型で扱います。
- `const` を指すポインタを通した書き込みはエラーです（[4.2節](#s4-2)）。

<a id="s3-11"></a>
### 3.11 Option

```
fn poll_key() -> Option<char> {
    if KBDCR.contains(Kbd::Ready) { Some(KBD as char) } else { None }
}

fn read_cmd() -> Option<Cmd> {
    let c = poll_key()?;                // None ならここで None を返して抜ける
    Cmd::check(c as u8)
}

fn main_loop() {
    if let Some(c) = poll_key() { putc(c); }
    match read_cmd() {
        Some(Cmd::Reset) => reset(),
        Some(_)          => {}
        None             => idle(),
    }
}
```

- `Option<T>` は「値があるか、ないか」を表す型です（Rust と同じ）。値があるときは `Some(v)`、ないときは `None` です。
- 中身を使うには、`if let Some(v) = ...`、`match`、`?` のどれかで有無を確かめる必要があります。確かめずに使うとエラーです。
- `?` は、値が `None` なら、その関数自身も `None` を返して抜けます（戻り値が `Option` の関数の中だけで使える）。
- `Option` を使わなければ、追加のコストはかかりません。使っても、値を包む処理は発生しません。

| 場面 | 「ある・なし」の表し方 | コスト |
|---|---|---|
| 戻り値 | キャリーフラグ（値は通常どおり A などで返す） | 呼び出し先の `sec`/`clc` と、呼び出し元の分岐（4〜5 サイクル） |
| 使われない値がある型（範囲型など）の変数 | 使われない値（$FF など）を「なし」に流用 | 追加のメモリなし |
| すべての値が有効な型（u8 など）の変数 | 「ある・なし」用にもう 1 バイト | 1 バイト |

- 「ある・なし」の表し方はコンパイラが型ごとに選ぶので、`Option<u8>` でも 255 は普通に使えます。
- 範囲型は「値が決まった範囲に収まっているか」、`Option` は「値があるか、ないか」を表します。

```asm
        jsr poll_key            ; キーを調べる（あればキャリー 1、文字は A）
        bcc no_key              ; キャリーが 0（None）なら飛ばす
        jsr putc                ; Some(c)：A の文字をそのまま出す
no_key:                         ; 合流地点
```

<a id="s3-12"></a>
### 3.12 関数集合

```
fnset StateFn = { idle, walk, jump };       // 呼ぶ可能性のある関数の一覧（すべて同じ型）
static CURRENT: StateFn = idle;         // 一覧の中のどれかを指す変数（中身は番号）

fn update() {
    CURRENT();                              // CURRENT が指す関数を呼ぶ
    CURRENT = walk;                         // 一覧にある関数なら代入できる
    CURRENT = draw;                         // エラー：draw は StateFn の一覧にない
}
```

- 関数ポインタの代わりです。一覧に入れる関数は、すべて同じ引数と戻り値の型でなければなりません。
- コンパイラは、呼び出しを「一覧のどれかを呼ぶもの」として呼び出しグラフに組み込みます。再帰の検査、スタックの予算、ローカル変数の重ね合わせは、そのまま行えます。
- 値の中身は番号（1 バイト）で、65C02 では `jmp (表,x)` によるジャンプテーブルで呼びます。NMOS では別の方法に切り替えます。

<a id="s3-13"></a>
### 3.13 型の別名

```
type EnemyId = Eid;                     // Eid の別名（同じ型）
type Score = bcd16;
```

- `type` は別名だけを作ります（Rust と同じ）。新しい範囲型は `range` で作ります。

<a id="s3-14"></a>
### 3.14 型の変換

```
let w = x as u16;                       // u8 → u16（上位に 0）
let s = dx as i16;                      // i8 → i16（符号を広げる）
let b = w as u8;                        // u16 → u8（下位バイト）
let n = Dir::Up as u8;                  // 列挙型・範囲型 → u8
let c = n as char;                      // u8 → char
let j = $11 as Joy;                     // u8 → ビットフラグ
let v = SCORE as u16;                   // エラー：BCD と整数の変換は as ではできない
let v2 = bcd::to_u16(SCORE);            // bcd16 → u16（use bcd; が必要。20.3節）
```

| 変換 | 意味 | コスト |
|---|---|---|
| 狭い整数 → 広い整数 | 符号なしは 0、符号付きは符号を広げる | 1〜4 命令 |
| 広い整数 → 狭い整数 | 下位のバイトを取る | なし |
| 符号付き ↔ 符号なし（同じ大きさ） | ビットの並びはそのまま | なし |
| 範囲型・列挙型 → `u8` | 中身の値 | なし |
| `u8` → 範囲型・列挙型 | `as` ではできない（エラー）。`check()` などを使う | ― |
| ビットフラグ ↔ 中身の整数型（`u8`・`u16`） | 中身の値。どのビットの組み合わせも有効 | なし |
| `u8` ↔ `char`、`char@enc` | 中身の値 | なし |
| 整数 ↔ BCD | `as` ではできない（エラー）。`bcd::to_u16(x)`、`bcd::from_u16(n)` などを使う（[20.3節](#s20-3)） | ― |
| `int`・`real` → 実行時の型 | 値が範囲に収まるかを検査する（収まらなければエラー） | なし（コンパイル時） |

- 実行時の整数型同士の `as` は、範囲を検査せず、下位のバイトを取ります。`const fn` をコンパイル時に計算する場合も同じです。
- コンパイル時の型 `int`・`real`（[13.2節](#s13-2)）から実行時の型への `as` は、範囲を検査します。範囲外ならエラーで、一周させません。

```
const fn low(x: u16) -> u8 { x as u8 }
const A: u8 = low(300);                 // 44（実行時と同じく下位のバイト）
comptime fn twice(i: int) -> u8 { (i * 2) as u8 }
const B: u8 = twice(100);               // 200
const C: u8 = twice(200);               // エラー：400 は u8 に収まらない
```
