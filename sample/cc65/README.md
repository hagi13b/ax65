# meteor の cc65 版（ax65 との性能比較用）

ax65 版の meteor と同じゲームを C で書いたものです。cc65 でビルドして、出力を返していただくと、ax65 版と同じ方法（同じエミュレータ、同じキー操作）で測定します。

## ファイル

| ファイル | 内容 |
|---|---|
| `meteor.c` | ゲームの本体（C） |
| `crt0.s` | 起動処理（アセンブリ。HEXMON から呼ばれ、rts で戻る） |
| `meteor.cfg` | リンカの設定（$0200 から読み込み、ゼロページは $20〜$FF、C のスタックの先頭は $7EF0） |
| `build.sh` / `build.bat` | 5 つの最適化の設定でビルドする |

## ビルド

```
sh build.sh        （Windows なら build.bat）
```

| 設定の名前 | cc65 のオプション |
|---|---|
| `O0` | なし |
| `O` | `-O` |
| `Oirs` | `-Oirs` |
| `Oirs_Cl` | `-Oirs -Cl` |
| `Oirs_Cl_cs` | `-Oirs -Cl --codesize 500` |

`crt0.s` のアセンブルで「`sp` が未定義」と出た場合は、`crt0.s` の `CSTK = sp` を `CSTK = c_sp` に変えてください（cc65 の版によって名前が違います）。

## 返していただきたいもの

各設定について、次の 4 つのファイルです（20 ファイル）。チャットにファイルを添付していただくのが一番簡単です。

- `meteor_<設定>.bin`（バイナリ）
- `meteor_<設定>.map`（リンカのマップ。セグメントの大きさを使う）
- `meteor_<設定>.lbl`（ラベル）
- `meteor_<設定>.s`（コンパイラが出したアセンブリ。差の理由を調べるのに使う）

あわせて、`cc65 --version` の表示もお知らせください。

バイナリを添付できない場合は、16進のテキストにして貼り付けてください。

```
xxd -p meteor_O0.bin                                 （Linux、macOS）
certutil -encodehex -f meteor_O0.bin meteor_O0.hex 4 （Windows。4 は区切りのない16進）
```

## 測定との対応

- 計測の目印は、`$7F00`〜`$7F04` への `stz`（4 サイクル）です。測定の側で、目印 1 つにつき 4 サイクルを差し引きます。
- 実機で遊ぶときは、目印を入れずに作ります（`cl65 -t none --cpu 65c02 -Oirs -Cl -DNO_MARK -C meteor.cfg -o meteor.bin crt0.s meteor.c`）。
- v2 には割り込みがないので、フレームの時間は ax65 版と同じく、GPIO のタイマー T2 を見て待ちます。キーは HEXPAD（4 で左、6 で右、A/D で終了）、表示は UART（19200bps）です。
- C の書き方は、cc65 で速いコードを得るための一般的な書き方（グローバル変数、`unsigned char`、フィールドごとの配列）に従っています。ax65 では、フィールドごとの配列はコンパイラが自動で作ります。
